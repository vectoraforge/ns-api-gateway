The test sets `EXAMPLES_PATH` as an env var via `patch.dict(os.environ, ...)`. Because `BaseConfig` (parent of `MainConfig`) uses `env_nested_delimiter="_"`, pydantic-settings interprets `EXAMPLES_PATH` as both the literal field `examples_path` AND the nested path `examples` -> `path`. Since `AppConfig` (loaded inside the model_validator) has an `examples: dict[str, list[str]]` field, the nested interpretation tries to set `examples.path = "/tmp/..."` which fails validation (`Input should be a valid list`).

Fix `test_main_config_loads_yaml_and_content`: Pass the file paths as constructor kwargs to `MainConfig(config_dir=..., prompt_path=..., examples_path=...)` instead of setting them as env vars. This bypasses pydantic-settings env parsing entirely and goes through normal Pydantic field assignment.

Keep the env var cleanup (`os.unlink`) in `finally` block.

Also fix `test_main_config_missing_file` the same way: pass `config_dir="/nonexistent/path.yaml"` as a constructor kwarg instead of patching `os.environ`.

<task type="auto">
  <name>Task 2: Suppress 422 from OpenAPI schema for all endpoints</name>
  <files>app/api/main.py</files>
  <action>
FastAPI auto-generates 422 (Unprocessable Entity) responses for every route that accepts a request body or has path/query parameters. The app already maps validation errors to 400 via a custom `RequestValidationError` handler, so the 422 in the schema is misleading and violates the error contract (ERR-04).

Suppress 422 from the OpenAPI schema by overriding `app.openapi()` with a custom function that strips all 422 entries from every operation's responses. Add this after the `app = FastAPI(...)` definition in `app/api/main.py`:

```python
def custom_openapi():
    if app.openapi_schema:
        return app.openapi_schema
    schema = get_openapi(
        title=app.title,
        version=app.version,
        description=app.description,
        routes=app.routes,
    )
    for path_data in schema.get("paths", {}).values():
        for operation in path_data.values():
            if isinstance(operation, dict):
                operation.get("responses", {}).pop("422", None)
    app.openapi_schema = schema
    return schema

app.openapi = custom_openapi
```

Import `get_openapi` from `fastapi.openapi.utils`. Place the custom function and assignment after the `app = FastAPI(...)` block but before `app.include_router(...)` calls.

Note: The app-level `responses={400: ..., 401: ..., ...}` dict in the FastAPI constructor must be passed to `get_openapi()` as well. Use the `responses` parameter of `get_openapi()` -- but actually the simpler approach is: just generate the default schema and strip 422. The app-level responses are already merged by FastAPI's internal schema generation. So use `fastapi.openapi.utils.get_openapi` with `title`, `version`, `description`, `routes` -- it will pick up the app-level responses from the route definitions.

IMPORTANT: Do NOT pass the app-level `responses` dict separately -- FastAPI already merges them into each route when routes are included. The `get_openapi(routes=app.routes)` call captures everything.
