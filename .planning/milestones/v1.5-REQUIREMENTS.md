# Requirements: sn-api-gateway

**Defined:** 2026-03-19
**Core Value:** The analysis pipeline must work reliably — correct LLM invocation, proper resilience under load, and safe per-user data isolation.

## v1.5 Requirements

Requirements for User Management & Subscriptions milestone. Each maps to roadmap phases.

### User Management

- [x] **USER-01**: User record is auto-created in local PostgreSQL on first authenticated API request (JIT provisioning)
- [x] **USER-02**: User can retrieve their profile (email, name, plan, usage) via `GET /users/me`
- [x] **USER-03**: Concurrent first requests from same user do not create duplicate records (`ON CONFLICT`)
- [x] **USER-04**: Users cannot access other users' data (existing isolation extended to user records)

### Subscriptions

- [x] **SUBS-01**: App receives Apple Store Server Notifications V2 via `POST /webhooks/apple`
- [x] **SUBS-02**: Apple notifications are verified using JWS signature chain verification (`app-store-server-library`)
- [x] **SUBS-03**: Webhook processes full subscription lifecycle (active, grace period, billing retry, expired, revoked)
- [x] **SUBS-04**: Duplicate Apple notifications are safely ignored (idempotency on `notificationUUID`)
- [x] **SUBS-05**: User's plan tier (free/silver/gold/platinum) is stored in local DB as authoritative source
- [x] **SUBS-06**: Plan changes sync to Firebase custom claims for JWT propagation
- [x] **SUBS-07**: Firebase claim sync does not block the event loop (`asyncio.to_thread()`)

### Envoy Gateway

- [x] **ENVOY-01**: SecurityPolicy extracts JWT `plan` claim to `x-user-plan` request header
- [x] **ENVOY-02**: BackendTrafficPolicy enforces per-user rate limits by plan tier
- [x] **ENVOY-03**: Webhook endpoint bypasses JWT authentication (separate HTTPRoute)
- [x] **ENVOY-04**: Rate limiting uses local per-pod rate limiting (no Redis); backend PostgreSQL quota is authoritative
- [x] **ENVOY-05**: `GET /users/me` returns plan usage data (request counts, limits)

### Logging

- [x] **LOG-01**: Structured logging via structlog with JSON output in production
- [x] **LOG-02**: Console-formatted logs in development mode
- [x] **LOG-03**: Request ID context injected into all log entries via middleware
- [x] **LOG-04**: Info level for request lifecycle, debug for implementation details

### Service Refactoring

- [x] **SVC-01**: `service.py` split into `services/` package with separate modules (LLMService, ChatService)
- [x] **SVC-02**: `database.py` split into `database/` package with separate modules (ChatsDB, UsersDB)
- [x] **SVC-03**: Refactoring introduces zero behavior changes — all existing tests pass unchanged

### Test Infrastructure

- [x] **TEST-01**: Each test runs within a transaction that rolls back on completion
- [x] **TEST-02**: Manual cleanup helpers (e.g. `cleanup_chat`) removed
- [x] **TEST-03**: No database artifacts remain after test suite execution

## Out of Scope

| Feature | Reason |
|---------|--------|
| Application-level rate limiting (slowapi) | Envoy Gateway owns rate limiting — explicit project constraint |
| Per-request Firebase claim reads | Adds 100-300ms latency; JWT already carries the plan claim |
| New HTTP status codes or error codes | Contract locked at 5 codes (400/401/404/503/500) |
| Multi-provider identity support | Firebase only; no requirement for other IdPs |
| Payment refund processing | Apple handles refunds; app reacts to revocation notifications |
| User registration endpoint | JIT provisioning from JWT; Firebase handles account creation |
| Admin user management | Own profile only (`GET /users/me`); no admin listing or management |
