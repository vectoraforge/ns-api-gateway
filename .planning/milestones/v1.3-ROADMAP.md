## Phase Details

### Phase 10: JWT Authentication
**Goal**: Users can authenticate with real RS256-signed JWTs; signature, claims, and algorithm are all verified
**Depends on**: Phase 9 (v1.2 complete)
**Requirements**: AUTH-01, AUTH-02, AUTH-03, AUTH-04, AUTH-05, AUTH-06, AUTH-07, AUTH-09
**Success Criteria** (what must be TRUE):
  1. A valid RS256 token signed with the configured public key is accepted and its `sub` claim is used as the user identity
  2. A token signed with a wrong key, using HS256, or with `alg: none` is rejected with 401 and `WWW-Authenticate: Bearer` header
  3. A token with expired, wrong audience, or wrong issuer claims is rejected with 401
  4. All 19 tests in `test_jwt_security.py` pass without collection errors (2 email_verified tests removed per CONTEXT.md)
  5. JWT config (project_id, jwks_url, leeway, cache_ttl) loads from `config/config.yaml` and is validated by Pydantic
  6. JWKS keys fetched via PyJWKClient at startup with TTL caching (AUTH-09 pulled from v2)
**Plans**: 2 plans
Plans:
- [ ] 10-01-PLAN.md — Exception rename (AuthError -> AuthenticationError) + JWTConfig + error handler opaque 401
- [ ] 10-02-PLAN.md — JWTVerifier implementation with JWKS + app wiring + test migration

### Phase 11: Error Contract Hardening
**Goal**: The API exposes exactly 5 status codes with fixed opaque error codes; no raw exception text reaches callers
**Depends on**: Phase 10
**Requirements**: ERR-01, ERR-02, ERR-03, ERR-04, ERR-05, ERR-06
**Success Criteria** (what must be TRUE):
  1. Any API error response uses exactly one of: 400, 401, 404, 503, 500 — no other status codes are emitted
  2. Error response bodies contain only fixed string codes (invalid_request, unauthorized, not_found, service_unavailable, internal_error) — no exception messages, stack traces, or Pydantic field details
  3. Hitting an undefined route or wrong HTTP method returns a 4xx response within the 5-code set (not a 405 or 422 leaking through)
  4. `ErrorResponse` Pydantic model is visible in the OpenAPI schema at `/docs`
  5. Status code remappings hold: a 409 conflict, 413 payload, and 422 validation error all surface as 400; a 502 bad gateway surfaces as 503
**Plans**: 2 plans
Plans:
- [x] 11-01-PLAN.md — ErrorResponse model + handler body/status fixes + remap table + test updates
- [x] 11-02-PLAN.md — OpenAPI schema customization (custom_openapi, strip 422) + contract enforcement tests

### Phase 12: LLM Dependency Injection
**Goal**: All FastAPI dependencies centralized in `app/dependencies.py`; routes use `Depends()` instead of `request.app.state.*`; AnalysisService annotates llm as BaseChatModel
**Depends on**: Phase 11
**Requirements**: DI-01, DI-02, DI-03
**Success Criteria** (what must be TRUE):
  1. `app/dependencies.py` exports `get_db`, `get_user_id`, `get_service`, `get_config` — single source of truth for all DI functions
  2. No route handler in `app/routers/` imports or uses `Request`; all state access via `Depends()`
  3. `app/services.py` uses `BaseChatModel` type annotation (not `ChatOpenAI`)
  4. `get_db` deleted from `database.py`; `get_user_id` deleted from `auth.py`
  5. Tests use `dependency_overrides` for all injected deps — no `app.state.service`/`app.state.config` in test setup
**Plans**: 2 plans
Plans:
- [ ] 12-01-PLAN.md — Create dependencies.py, update routes to Depends(), update services.py type annotation, delete originals
- [ ] 12-02-PLAN.md — Migrate test infrastructure to DI overrides, fix test_prompts_endpoints.py mocks

### Phase 13: Endpoint Unification
**Goal**: A single POST /chats endpoint handles both new analysis and chat continuation; old routes are removed; response schema uses suggestions
**Depends on**: Phase 12
**Requirements**: EP-01, EP-02, EP-03, EP-04
**Success Criteria** (what must be TRUE):
  1. `POST /chats` with a new phrase and `lang` creates a chat and returns analysis results
  2. `POST /chats` with an existing `chat_id` continues the conversation using prior message history
  3. `POST /chats` without `lang` and without `chat_id` returns 400 (no silent English default)
  4. Response bodies use the `suggestions` field name; `alternatives` does not appear in any response or OpenAPI schema
  5. Old routes `POST /prompts/analyze` and `POST /chats/{chat_id}/messages` are removed and return 404
**Plans**: 2 plans
Plans:
- [ ] 13-01-PLAN.md — Schema/model/service renames, field renames (alternatives->suggestions, assessment->response), merge analyze()+chat(), model_validator for lang, prompt update
- [ ] 13-02-PLAN.md — Router restructure (chats.py, examples.py, delete prompts.py), main.py wiring, full test migration, 404 tests for removed routes
