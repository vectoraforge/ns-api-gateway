# Requirements: sn-api-gateway

**Defined:** 2026-03-03
**Core Value:** The analysis pipeline must work reliably — correct LLM invocation, proper resilience under load, and safe per-user data isolation.

## v1.4 Requirements

Requirements for DB query optimization and chat refactoring. Each maps to roadmap phases.

### Query Optimization

- [x] **QOPT-01**: `list_messages` uses LEFT JOIN from Chat to Message with `user_id` filter — 1 query, 404 for non-existent/wrong-user chats
- [x] **QOPT-02**: `delete_chat` uses single `DELETE WHERE id AND user_id` with rowcount check — 1 query
- [x] **QOPT-03**: `load_history` (continuation) uses JOIN with `user_id` filter — 1 query replaces separate ownership check + history load
- [x] **QOPT-04**: Capacity check derived from loaded history in Python — eliminates `get_message_counts` DB call
- [x] **QOPT-05**: New chat path skips `load_history` — empty history assigned directly

### Dead Code Removal

- [x] **DEAD-01**: Remove `get_chat_owned` method from Chats class
- [x] **DEAD-02**: Remove `get_message_counts` method from Chats class
- [x] **DEAD-03**: Remove `_ensure_history_capacity` method from ChatService
- [x] **DEAD-04**: Remove `ChatOwnershipError` exception class + handler + imports (4-file atomic cleanup)
- [x] **DEAD-05**: Clean up phantom test mocks for removed methods

### Chat Refactoring

- [x] **REFACT-01**: Chat model has `phrase` (required), `comment` (optional), `lang` (optional) columns; Role is StrEnum with `human`/`ai`
- [x] **REFACT-02**: Separate request schemas — ChatRequest (phrase/comment/lang) and FollowupRequest (content); ChatResponse (chat_id/issues/suggestions/response, no text echo); ChatMessagesResponse flat with chat fields + messages + cursor
- [x] **REFACT-03**: ChatsDB with session-in-init pattern — create, save_message (generic), get_history, get_messages (paginated), delete, list_chats
- [x] **REFACT-04**: ChatService takes chain/policy/config/db, creates ChatsDB internally; create_chat (LLM-first, persist-after), followup (load history, check capacity, save 2 messages); AI stored as json.dumps
- [x] **REFACT-05**: Separate endpoints — POST /chats (new), POST /chats/{id} (followup), GET /chats (list), GET /chats/{id} (detail + messages), DELETE /chats/{id}
- [x] **REFACT-06**: Per-request DI — get_chat_service receives chain+policy from app.state, config+db from dependencies; chain built once in lifespan via create_chain()
- [x] **REFACT-07**: File reorganization — app/database/ and app/services/ packages declared in pyproject.toml; old files (app/chats.py, app/database.py, app/models.py, app/services.py) removed
- [x] **REFACT-08**: DB migration adds phrase/comment/lang to chats, updates role CHECK constraint from assistant to ai
- [x] **REFACT-09**: Full test rewrite — new ChatService constructor, AsyncMock(spec=ChatsDB), no phantom mocks, no references to removed methods

## Out of Scope

| Feature | Reason |
|---------|--------|
| PostgreSQL Row-Level Security (RLS) | Disproportionate operational complexity for current scale |
| Counter cache tables | Premature optimization given bounded per-chat message counts |
| Separate 403/404 error codes | OWASP anti-recommendation; unified 404 is correct security practice |
| Service-layer ownership wrappers | Adds indirection without enabling query-level optimization |
