# Requirements: sn-api-gateway

**Defined:** 2026-03-02
**Core Value:** The analysis pipeline must work reliably — correct LLM invocation, proper resilience under load, and safe per-user data isolation.

## v1.3 Requirements

Requirements for v1.3 Feature Integration. Each maps to roadmap phases.

### JWT Authentication

- [x] **AUTH-01**: JWTVerifier verifies RS256 signatures using a configurable public key PEM
- [x] **AUTH-02**: JWTVerifier validates audience, issuer, and expiration claims from config
- [x] **AUTH-03**: JWTVerifier rejects tokens with disallowed algorithms (HS256, none)
- [x] **AUTH-04**: JWTVerifier extracts user identity from `sub` claim (replacing `user_id`)
- [x] **AUTH-05**: AuthenticationError exception type maps to 401 responses
- [x] **AUTH-06**: JWT config (audience, issuer, leeway, public_key_pem) loaded from config.yaml
- [x] **AUTH-07**: All 401 responses include `WWW-Authenticate: Bearer` header (RFC 6750)
- [x] **AUTH-09**: JWKS live key rotation via PyJWKClient with TTL caching

### Error Contract

- [x] **ERR-01**: API returns exactly 5 status codes: 400, 401, 404, 503, 500
- [x] **ERR-02**: Error responses use fixed string codes (invalid_request, unauthorized, not_found, service_unavailable, internal_error)
- [x] **ERR-03**: No raw exception text appears in error response bodies
- [x] **ERR-04**: ErrorResponse Pydantic model documented in OpenAPI schema
- [x] **ERR-05**: StarletteHTTPException catch-all maps non-contract codes to the 5-code set
- [x] **ERR-06**: Remappings applied: 409→400, 413→400, 422→400, 502→503, 500(DB)→503

### LLM Dependency Injection

- [x] **DI-01**: `get_llm()` dependency provides ChatOpenAI via `Depends()` (consistent with `get_db`/`get_user_id`)
- [x] **DI-02**: `AnalysisService.analyze()` accepts `llm` as a parameter (service stays framework-agnostic)
- [x] **DI-03**: LangChain chain built per-call inside `analyze()` (not stored as `self.chain`)

### Endpoint Unification

- [x] **EP-01**: Unified `POST /chats` endpoint handles both new analysis and chat continuation
- [x] **EP-02**: Old routes (`POST /prompts/analyze`, `POST /chats/{id}/messages`) removed
- [x] **EP-03**: `alternatives` field renamed to `suggestions` in response schema
- [x] **EP-04**: `lang` is required when `chat_id` is absent (no silent English default)

## Out of Scope

| Feature | Reason |
|---------|--------|
| Token creation endpoint | This service is not an identity provider |
| python-jose | Abandoned library; PyJWT 2.11.0 is installed and used by all test infrastructure |
| Per-request ChatOpenAI construction | Resource leak; singleton via app.state is correct |
| Discriminated union request body | FastAPI known issue #13213; use flat schema with model_validator |
| 422 in public error contract | Leaks framework internals (Pydantic validation details) |
| Expanding ruff ruleset | Stable at E/W/F/I/UP; no benefit this milestone |
| Verifier DI refactor | get_user_id reads app.state.verifier directly; consistent enough |
