**app/api/errors.py** -- 15 errors:

**14x `invalid-argument-type` on `add_exception_handler` registrations (lines 125-139):**

Starlette's `add_exception_handler` expects handler signature `(Request, Exception) -> Response | Awaitable[Response]`, but our handlers type the second arg as specific exception subclasses (e.g., `exc: UnsupportedLanguageError`). ty is stricter than mypy here.

Fix: Change ALL handler function signatures to accept `Exception` as the second parameter type, then cast to the specific type inside the function body. This is the cleanest fix that satisfies the type checker without losing specificity.

For each handler function, change the signature and add a cast. Example transformation:

Before:
```python
async def unsupported_language_handler(_: Request, exc: UnsupportedLanguageError) -> JSONResponse:
    return JSONResponse(status_code=400, content=ErrorResponse(code="invalid_request").model_dump())
```

After:
```python
async def unsupported_language_handler(_: Request, exc: Exception) -> JSONResponse:
    return JSONResponse(status_code=400, content=ErrorResponse(code="invalid_request").model_dump())
```

Since most handlers don't actually access any attributes on `exc` (they just return a fixed ErrorResponse), the type change is safe. For handlers that DO access exc attributes, add a cast:

- `queue_full_handler` accesses `exc.retry_after_seconds` -- add `assert isinstance(exc, QueueFullError)` at start
- `circuit_open_handler` accesses `exc.retry_after_seconds` -- add `assert isinstance(exc, CircuitOpenError)` at start

Apply this pattern to all 14 handler functions:
1. `unsupported_language_handler` -- change `exc: UnsupportedLanguageError` to `exc: Exception` (no attribute access)
2. `transient_llm_error_handler` -- change `exc: TransientLLMError` to `exc: Exception`
3. `permanent_llm_error_handler` -- change `exc: PermanentLLMError` to `exc: Exception`
4. `analysis_error_handler` -- change `exc: AnalysisError` to `exc: Exception`
5. `invalid_chat_handler` -- change `exc: InvalidChatError` to `exc: Exception`
6. `invalid_cursor_error_handler` -- change `exc: InvalidCursorError` to `exc: Exception`
7. `page_size_limit_handler` -- change `exc: PageSizeLimitError` to `exc: Exception`
8. `queue_full_handler` -- change `exc: QueueFullError` to `exc: Exception`, add `assert isinstance(exc, QueueFullError)` before accessing `exc.retry_after_seconds`
9. `circuit_open_handler` -- change `exc: CircuitOpenError` to `exc: Exception`, add `assert isinstance(exc, CircuitOpenError)` before accessing `exc.retry_after_seconds`
10. `chat_history_limit_handler` -- change `exc: ChatHistoryLimitError` to `exc: Exception`
11. `validation_error_handler` -- change `exc: RequestValidationError` to `exc: Exception`
12. `auth_error_handler` -- change `exc: AuthenticationError` to `exc: Exception`

**1x `invalid-argument-type` on line 115 (`ErrorResponse(code=_CODE_MAP[status])`):**

`_CODE_MAP[status]` returns `str`, but `ErrorResponse.code` expects `Literal[...]`. Fix by casting the value:

Change line 115 from:
```python
content=ErrorResponse(code=_CODE_MAP[status]).model_dump(),
```
to:
```python
content=ErrorResponse(code=_CODE_MAP[status]).model_dump(),  # type: ignore[invalid-argument-type]
```

The `_CODE_MAP` only contains valid ErrorCode values, so this is safe. A `type: ignore` is appropriate since the dict values are runtime-correct but ty can't narrow dict value types to the Literal union.
