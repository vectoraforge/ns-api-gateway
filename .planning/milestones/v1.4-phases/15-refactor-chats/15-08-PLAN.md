**tests/unit/test_config.py** -- 4 errors:

All 4 are `unresolved-attribute` on lines 58-61 where `config.app.model`, `config.app.prompt`, `config.app.examples` are accessed. Since `MainConfig.app` is typed as `AppConfig | None`, ty sees the `.model`/`.prompt`/`.examples` attributes as potentially accessing `None`.

Fix by adding a narrowing assertion before line 58:

```python
        with patch.dict(os.environ,
                        {"CONFIG_DIR": config_path,
                         "PROMPT_PATH": prompt_path,
                         "EXAMPLES_PATH": examples_path},
                        clear=False):
            config = MainConfig()
            assert config.app is not None
            assert config.app.model.name == "gpt-4"
            assert config.app.model.temperature == 0.5
            assert config.app.prompt == prompt_content
            assert config.app.examples["en"] == ["Example 1"]
```

Add `assert config.app is not None` as a new line after `config = MainConfig()` (line 57) and before line 58. This is semantically correct since `MainConfig.load_config` always sets `self.app`.

**tests/unit/test_jwt_security.py** -- 1 error:

`invalid-argument-type` on line 30: `jwt.encode(payload, key, algorithm="RS256")`. The `key` parameter is being passed a type that ty can't reconcile with PyJWT's expected type signature (it expects `str | bytes | ...` but the RSA key object's type isn't recognized).

Fix by adding `# type: ignore[invalid-argument-type]` to line 30. This is a well-known PyJWT typing issue where RSA key objects aren't fully typed for the `encode` function.

Find line 30 (the `jwt.encode` call) and append the type: ignore comment.
