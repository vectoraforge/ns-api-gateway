**Method 1 -- try_increment (per D-04, D-06, D-07):**
Two-statement approach preserving atomicity:

Statement 1 -- ensure row exists:
```python
await self.session.exec(
    pg_insert(UsageMonthly)
    .values(id=uuid7(), user_id=user_id, month=month, used=0)
    .on_conflict_do_nothing(index_elements=["user_id", "month"])
)
```
CRITICAL: Must pass `id=uuid7()` explicitly -- `pg_insert` bypasses SQLModel `default_factory`.
`index_elements=["user_id", "month"]` maps to `UniqueConstraint("user_id", "month")` on the model.

Statement 2 -- atomic conditional increment with RETURNING:
```python
result = await self.session.exec(
    update(UsageMonthly)
    .where(UsageMonthly.user_id == user_id,
           UsageMonthly.month == month,
           UsageMonthly.used < monthly_quota)
    .values(used=UsageMonthly.used + 1)
    .returning(UsageMonthly.used)
)
return result.first() is not None
```
`result.first()` returns a Row or None. `is not None` gives the bool return.

**Method 2 -- get_usage (per D-03):**
Use `select(UsageMonthly.used)` which returns `SelectOfScalar`. SQLModel's `session.exec()` auto-applies `.scalars()`, so `.first()` returns the int directly (not a Row tuple):
```python
result = await self.session.exec(
    select(UsageMonthly.used)
    .where(UsageMonthly.user_id == user_id, UsageMonthly.month == month)
)
used = result.first()
return used if used is not None else 0
```

**Method 3 -- reset_usage (per D-05):**
Simple UPDATE without RETURNING:
```python
await self.session.exec(
    update(UsageMonthly)
    .where(UsageMonthly.user_id == user_id, UsageMonthly.month == month)
    .values(used=0)
)
```

**Coding style (per CLAUDE.md):**
- Method definitions use opening delimiter alignment (one param per line, aligned to opening paren) -- the existing signatures already follow this, keep them as-is.
- Method calls collapse into 1+ lines -- chain `.where()`, `.values()`, `.returning()` on separate lines for readability.
- Use `self.session.exec()` everywhere, never `self.session.execute()`.
