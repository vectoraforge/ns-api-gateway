### Phase 6: LLM Output Parsing Hardening
**Goal**: LLM responses are schema-guaranteed by the API provider, eliminating the fragile `JsonOutputParser` -> `model_validate` pipeline
**Depends on**: Phase 5 (green test suite as baseline -- any failure is attributable to parsing changes)
**Requirements**: LLM-01
**Success Criteria** (what must be TRUE):
  1. `app/services.py` uses `self.llm.with_structured_output(AnalyzeResponseLLM)` instead of `JsonOutputParser()`
  2. `AnalyzeResponseLLM` Pydantic model exists in `app/schema.py` representing the LLM output schema (separate from the API response schema `AnalyzeResponse`)
  3. Unit tests for the analyze chain pass with mocks returning `AnalyzeResponseLLM` instances (not raw dicts)
  4. A malformed LLM response does not trigger the retry loop (parsing failure is classified as permanent, not transient)
**Plans:** 1 plan
Plans:
- [x] 06-01-PLAN.md -- Replace JsonOutputParser with structured output and update test mocks

### Phase 7: PEP8 Compliance
**Goal**: Codebase follows consistent style enforced by ruff, with dev tooling properly separated from runtime dependencies
**Depends on**: Phase 6 (formatting applies to final state of code; avoids formatting deleted or soon-to-change code)
**Requirements**: STYLE-01
**Success Criteria** (what must be TRUE):
  1. `pyproject.toml` contains a `[tool.ruff]` section with rules E, W, F, I, UP and line-length=120
  2. `ruff check .` and `ruff format --check .` both exit 0 (no violations, no formatting changes needed)
  3. `ruff` and `ty` are listed under `[dependency-groups] dev`, not under `[project] dependencies`
  4. All tests pass after formatting changes
**Plans:** 1 plan
Plans:
- [ ] 07-01-PLAN.md -- Add ruff config, fix violations, format codebase, move dev deps

### Phase 8: Resilience Layer Extraction
**Goal**: AnalysisService focuses on orchestration only; retries, circuit breaking, and concurrency gating live behind a unified resilience interface (e.g., `policy.invoke(...)`)
**Depends on**: Phase 7 (code is formatted and linted before structural refactor)
**Requirements**: RESIL-01
**Success Criteria** (what must be TRUE):
  1. AnalysisService no longer directly references CircuitBreaker, LLMExecutionGate, or retry logic
  2. A single resilience layer/policy interface wraps all resilience concerns
  3. AnalysisSettings (or equivalent) is a passive config grouping, not behavior
  4. All existing tests pass without regressions
**Plans:** 1 plan
Plans:
- [ ] 08-01-PLAN.md -- Create ResiliencePolicy facade and wire into service/tests

### Phase 9: Health Endpoint Simplification
**Goal**: Health endpoint reports only whether the app initialized successfully; ReadinessCache and all backend readiness checks are removed
**Depends on**: Phase 8 (resilience refactor may affect health-related imports)
**Requirements**: HEALTH-01
**Plans:** 1 plan
Plans:
- [x] 09-01-PLAN.md -- Remove ReadinessCache and simplify health endpoint to unconditional 200/up
**Success Criteria** (what must be TRUE):
  1. `ReadinessCache` class no longer exists in the codebase
  2. Health endpoint returns UP/DOWN based solely on initialization status
  3. No backend connectivity checks (DB, LLM, etc.) run during health checks
  4. All existing tests pass without regressions
