## Phase Details

### Phase 14: DB Query Optimization
**Goal**: Every request handler makes at most 1 DB read call by folding ownership checks into data queries, deriving capacity from loaded data, and removing all orphaned code
**Depends on**: Phase 13 (v1.3 complete)
**Requirements**: QOPT-01, QOPT-02, QOPT-03, QOPT-04, QOPT-05, DEAD-01, DEAD-02, DEAD-03, DEAD-04, DEAD-05
**Success Criteria** (what must be TRUE):
  1. `list_messages` returns messages via a single LEFT JOIN query with user_id filter; 404 for non-existent/wrong-user chats without separate ownership check
  2. `delete_chat_owned` uses single `DELETE WHERE id AND user_id` with rowcount check; no prior SELECT
  3. `load_history` for continuation uses single JOIN with user_id filter, replacing separate `get_chat_owned` + history load
  4. Continuation path capacity check derived from loaded history in Python — no `get_message_counts` call
  5. New chat path skips `load_history` entirely — empty history assigned directly
  6. `GET /chats/{id}/messages` endpoint calls data access layer through single owned method, no separate ownership check in router
  7. `get_chat_owned`, `get_message_counts`, `_ensure_history_capacity` no longer exist — grep returns zero matches
  8. `ChatOwnershipError` class, handler, and registration all removed — no import, no definition, no reference
  9. Test files contain no phantom mock setups for removed methods
  10. `ruff check` passes and full test suite (unit + integration) passes
  11. API behavior unchanged — same responses, errors, status codes for all success and failure cases
**Plans:** 2/2 plans complete

- [ ] 14-02-PLAN.md — Rewrite all tests for new API surface, remove phantom mocks

### Phase 17: Simplify error handling in errors.py and related files
**Goal:** Replace 12 per-exception handler functions in errors.py with a single data-driven service_error_handler by encoding HTTP metadata (status_code, error_code, log_level, extra_headers) directly on exception classes in exceptions.py. Net ~80 line reduction, identical API behavior.
**Depends on:** Phase 16
**Requirements**: ERR-SIMPLIFY-01, ERR-SIMPLIFY-02
**Success Criteria** (what must be TRUE):
  1. ServiceError base class has status_code, error_code, log_level class attributes and extra_headers() method
  2. All 12 ServiceError subclasses have correct metadata matching current handler behavior
  3. TransientLLMError and PermanentLLMError explicitly set log_level = None (override AnalysisError inheritance)
  4. Single service_error_handler replaces 12 individual handler functions in errors.py
  5. validation_error_handler, http_exception_handler, generic_error_handler remain as separate handlers
  6. register_exception_handlers has exactly 4 registrations (ServiceError, RequestValidationError, StarletteHTTPException, Exception)
  7. `python -m pytest tests/unit/test_exception_handlers.py tests/unit/test_error_contract.py -x` passes unchanged
  8. `python -m pytest tests/unit/ -x` passes
  9. `ruff check app/exceptions.py app/api/errors.py` passes
  10. API error contract unchanged: same 5 status codes, 5 error codes, same headers for all exception types
**Plans:** 1/1 plans complete
