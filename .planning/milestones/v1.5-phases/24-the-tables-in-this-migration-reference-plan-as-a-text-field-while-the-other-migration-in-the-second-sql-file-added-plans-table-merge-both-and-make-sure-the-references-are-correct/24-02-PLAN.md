  <action>
    This task requires the user to run pogo migrate against their local PostgreSQL database. The database connection is configured in `pyproject.toml` under `[tool.pogo]` using env vars `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME`.

    Since this is a pre-production project with no live data, the safest approach is to drop all tables (including pogo's internal tracking table) and re-apply from scratch.

    Steps for the user:

    1. Connect to PostgreSQL and drop the schema (this drops ALL tables including `_pogo_migration`):
       ```
       psql -h $DB_HOST -p $DB_PORT -U $DB_USER -d $DB_NAME -c "DROP SCHEMA api CASCADE; CREATE SCHEMA api;"
       ```
       Note: The pogo config uses `schema = 'api'`, so all tables live under the `api` schema.

    2. Apply the merged migration:
       ```
       uv run pogo apply
       ```
       This will apply `migrations/20260322_01_initial-release.sql` which creates all 7 tables in FK dependency order with plans seed data.

    3. Verify the migration was applied:
       ```
       uv run pogo history
       ```
       Should show exactly 1 migration applied: `20260322_01_initial-release`.
  </action>
