# Requirements: sn-api-gateway

**Defined:** 2026-02-25
**Core Value:** The analysis pipeline must work reliably — correct LLM invocation, proper resilience under load, and safe per-user data isolation.

## v1.1 Requirements

### Exception Hierarchy

- [x] **EXCP-01**: API returns typed 401 responses for missing, invalid, and expired tokens (via `AuthError` subtypes and registered handlers)
- [x] **EXCP-02**: API returns typed 404 when a user accesses another user's chat (via `ChatOwnershipError`)
- [x] **EXCP-03**: Database startup failure raises `DatabaseNotInitializedError` instead of bare `Exception`
- [x] **EXCP-04**: Each exception handler is covered by a parametrized test verifying HTTP status code and response body shape

### JWT Auth Structure

- [x] **AUTH-01**: Auth module exposes a `TokenVerifier` protocol that any verifier implementation satisfies (structural subtyping via `typing.Protocol`)
- [x] **AUTH-02**: `UnsafeBase64Verifier` implements the protocol, preserving current decode behavior as the development stub
- [x] **AUTH-03**: `get_user_id` dependency resolves the verifier from `app.state` so providers can be swapped via config without touching routes

### Security Tests

- [x] **TEST-01**: Integration tests verify user A cannot read, post to, or delete user B's chats (real database, no mocked data layer)

### LLM Error Chain

- [x] **RETRY-01**: LLM retry loop raises typed exception subtypes for transient vs permanent LLM failures, preserving the original exception chain

### Cursor Validation

- [x] **CURS-01**: API returns 400 when a cursor parameter is malformed (validated before base64 decode attempt)

### Circuit Breaker

- [x] **CB-01**: Circuit breaker's in-memory state limitation is documented in code with a clear migration path for multi-instance deployment

## Future Requirements

### Rate Limiting

- **RATE-01**: Application-level rate limiting on `/prompts/examples` — deferred; Envoy Gateway handles rate limiting at the infrastructure level
- **RATE-02**: Per-user rate limiting on LLM endpoints — deferred; Envoy Gateway

### JWT Signature Verification

- **AUTH-04**: Real JWT signature verification via JWKS endpoint — deferred; blocked on auth provider selection (Auth0, Cognito, Firebase, etc.)

## Out of Scope

| Feature | Reason |
|---------|--------|
| CORS middleware | Envoy Gateway handles CORS at the infrastructure level |
| Security headers (X-Frame-Options, etc.) | Envoy Gateway handles HTTP security headers |
| Trusted host validation | Envoy Gateway perimeter control |
| Application-level rate limiting (slowapi) | Envoy Gateway owns rate limiting; adding app-level would be redundant |
| Redis-backed circuit breaker | Single-instance deployment; note migration path in CB-01 instead |
| LangChain/OpenAI provider abstraction | No multi-provider requirement yet |
| Message content encryption-at-rest | Infrastructure layer concern |
| Load/stress tests | Not a current priority |
