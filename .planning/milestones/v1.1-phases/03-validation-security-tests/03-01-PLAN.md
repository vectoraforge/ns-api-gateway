
    2. In app/errors.py, add handler function and register it:
       - Import InvalidCursorError alongside other imports
       - Add handler:
         ```python
         async def invalid_cursor_error_handler(_: Request, exc: InvalidCursorError) -> JSONResponse:
             return JSONResponse(status_code=400, content={"status": 400, "error": str(exc)})
         ```
       - In register_exception_handlers, add:
         `app.add_exception_handler(InvalidCursorError, invalid_cursor_error_handler)`
         Register it before the generic HTTPException handler so typed exceptions take priority.

    3. In app/routers/prompts.py, in list_chat_messages:
       - Import InvalidCursorError at the top (alongside ChatOwnershipError)
       - Add validation before calling list_messages. A valid cursor is a non-empty string that
         survives base64url padding and contains exactly one '|' after decoding:
         ```python
         if cursor is not None:
             try:
                 padded = cursor + "=" * (-len(cursor) % 4)
                 decoded = base64.urlsafe_b64decode(padded.encode()).decode()
                 if "|" not in decoded:
                     raise ValueError
             except Exception:
                 raise InvalidCursorError()
         ```
       - Add `import base64` at the top of prompts.py if not already present
       - Remove the existing try/except ValueError block that wraps list_messages and raised
         bare HTTPException — with pre-validation, _decode_cursor will always succeed on
         well-formed input.

    The validation must happen BEFORE service.chats.list_messages is called, not inside it.
    Do not add validation inside _decode_cursor in chats.py — keep it at the route entry point.

    ```python
    def __init__(self, failure_threshold: int, reset_seconds: int):
    ```
