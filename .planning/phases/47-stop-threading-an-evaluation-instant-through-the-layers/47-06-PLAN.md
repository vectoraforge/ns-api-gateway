<objective>
The challenge store stops being told what time it is, and `AuthService` stops holding an instant at all.

**Adopted from RESEARCH Open Question 4, as written.** `crud/challenges.py` is not in the roadmap's
Touches list, but `ChallengesDB.issue`, `.claim` and `.consume` each take a `now: datetime` and each
receives the shared instant from a router or from `AuthService`. Criterion 2's wording — "no crud
method receives one from a service" — covers them. Leaving them would leave the phase half done under
a different parameter name.

**D-01, second application.** `ChallengesDB.claim` is the second of the product's two SQL comparisons
against the current time, and it is the only expiry evaluation anywhere. Its `expires_at >` predicate
and its `claimed_at` write both become `func.clock_timestamp()` **in the same statement**, so the
value that decides and the value that is recorded can never disagree. `func.now()` is not used, for
the reason recorded in plan 47-01: it is `transaction_timestamp()`. The `now()`-versus-savepoint
hazard does not bite here in either direction — `expires_at` is issue time plus 300 seconds, so an
earlier clock only makes a challenge look more alive — but one clock per class is the point.

**One coverage change, named rather than hidden.** `tests/e2e/test_challenge_store.py` today proves the
predicate is `>` and not `>=` by claiming at exactly `expires_at`. Against a database clock that
equality is unreachable: no test can make `clock_timestamp()` land on a stored value. The property does
not get dropped — it moves to an assertion over the **compiled SQL**, using the
statement-to-literal-SQL technique `tests/schema/test_grant_locks.py` already uses. What is lost is the
round trip, not the guarantee.

**Phase boundary.** Phase 49 moves `ChallengesDB` construction into `AuthService` and deletes
`get_challenge_store`. This plan owns the three method signatures only. Do not touch `__init__`,
`__repr__`, the `challenge_store` constructor argument, `get_challenge_store`, or any `AuthIdentity`
annotation (Phase 48's).

Purpose: criteria 1, 2 and 3 for the challenge store and the auth service.
Output: three crud methods and one service with no instant, one handler that declares none, and the
expiry boundary pinned in SQL.

**Reversibility:** `reversible` — three signatures, one SQL expression, and their call sites.

**Executor note.** `IS_WORKTREE` is **false** in this repository: GSD's detector reports true because
this repo is a submodule whose `.git` is a file, and believing it makes tracking writes vanish.
</objective>

Drop the `now` parameter from the file's local `issue(...)` helper and from every `store.claim(...)` and
`store.consume(...)` call. The store now reads its own time, so the cases must arrange the **row**
rather than the clock.

Rewrite each case by what it proves:

- **An expired challenge is refused.** Issue normally, then move the row's `expires_at` into the past
  with a direct `UPDATE core.auth_challenges SET expires_at = ... WHERE challenge_id = ...` on the
  session the case already holds, then claim and assert `False`. This is the stored-state replacement
  for issuing at a long-ago instant.
- **A challenge inside its window is claimable.** Issue and claim immediately. The TTL is 300 seconds,
  so no offset is needed; delete the case's `now + timedelta(seconds=CHALLENGE_TTL_SECONDS - 1)`
  arithmetic.
- **A claim wins once.** Issue, claim twice, assert `True` then `False`. Delete the sixty-second offset
  on the second claim; it was only there to prove the second call was later, which two sequential calls
  already are.
- **Consume ordering.** Issue, consume before claiming and assert `False`; then claim, consume and
  assert `True`; then consume again and assert `False`. No instants.
- **The exact-expiry case.** Delete the case that claims at exactly `expires_at`. Against a database
  clock no test can make `clock_timestamp()` land on a stored value, so the equality is unreachable.
  Replace it, in the same commit, with a case that compiles `ChallengesDB.claim`'s `update` statement to

  `postgresql.asyncpg.dialect()` and `compile_kwargs={"literal_binds": True}` — and asserts the rendered
  text contains `expires_at > clock_timestamp()` and does **not** contain `expires_at >=`. Give the case
  a docstring of one line stating why the boundary is asserted in SQL: a live database clock never lands
  on a stored value. Add a positive control asserting the rendered text is non-empty and names the
  `auth_challenges` table, so a compile that silently produced nothing cannot pass the negative check.

Keep every other case, every assertion about `ChallengeConsumed` and `ChallengeIdentityMismatch`, and
the binding cases exactly as they are. Delete no case except the exact-expiry one, and only because its
replacement lands in the same commit.
