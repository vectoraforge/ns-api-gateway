## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| client → `POST /auth/challenge` | Untrusted JSON body; caller has proven a Firebase identity but owns no account | Operation string; a secret capability handle returns |
| client → `POST /auth/create-user` | Untrusted body carrying a secret capability handle | `challenge_id`, provider data |
| handler → `core.auth_challenges` | A secret capability handle is minted and stored | Handle, bound identity or keyed subject hash |
| completion handler → consuming transaction | Where UNIQUE constraints decide whether an identity may be linked | Account and identity rows |
| process → Google credential source | Admin SDK identity acquired from the environment, not a shipped file | ADC / Workload Identity token |
| Admin app → Firebase project | An app bound to the wrong project would read other users' data | `projectId`, subject lookups |
| adapter module → provider SDK | The seam module is the line an SDK import must never cross | — (enforced import roots) |
| app → LLM provider | Non-deterministic output crosses back and is persisted as message content | User phrase out; JSON object back |
| admission rejection → log pipeline | The structured rejection event is the only record a rejection leaves | Result, bounded reason, route template |
| written record → a later phase's author | A requirement note is the only channel carrying this phase's decisions to phases 38–46 | — |
