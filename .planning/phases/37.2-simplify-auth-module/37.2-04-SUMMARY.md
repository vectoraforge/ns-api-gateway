# Phase 37.2 Plan 04: Adapter Seam and Facade Deletion Summary

**Eight speculative adapter types, two unconsumed Protocol methods, and the ninety-eight-line lazy re-export facade at the auth package root are deleted, leaving an `adapters.py` that describes one seam and a package init that exposes nothing — at a cost of zero import-site edits.**

- **Commits:** 2

- **Net lines:** +26 / −369

## Accomplishments

### Task 1 — `adapters.py` shrunk to the providerData seam, package init emptied (`d16b4d2`)

Deleted from `src/nativespeaker/api/auth/adapters.py`: `RevocationOutcome`, `VerifiedNotification`,
`VerifiedTransaction`, `StoreState`, `StoreAdapter`, `ClaimKind`, `DeviceBitState`, and
`VendorProofAdapter` — nine declarations across three seam categories, none of which had a consumer
anywhere outside `adapters.py`, the facade, and the interface suite. `FirebaseAdminAdapter` lost
`verify_id_token` and `revoke_refresh_tokens`, keeping exactly `get_user_provider_data`.

Four names survive unchanged in shape because live code depends on them: `auth/firebase.py` imports
`ProviderDataEntry`, `ProviderDataOutcome` and `ProviderDataResult`; `auth/retry.py` imports
`ProviderDataOutcome` and `ProviderDataResult`.

The imports that died with the deletions went too — `VerifiedClaims` (the return type of the deleted
token-verification declaration), `datetime` and `UUID`. The module docstring was trimmed from
describing the whole seam *category* to describing the one surviving seam, keeping its
no-provider-SDK, no-I/O and no-leaked-provider-text rules verbatim, since those still bind the module
and three test cases assert their exact phrasing.

`src/nativespeaker/api/auth/__init__.py` went from 98 lines to 1: a single docstring saying the auth
package exposes nothing from its root and that consumers import from the concrete submodule. Gone are
`__all__`, the eager 40-name import block, the `TYPE_CHECKING` block, the `_LAZY_NAMES` mapping,
`__getattr__` and `__dir__`.

The plan's claim that this costs zero import-site edits held exactly. Every
`from nativespeaker.api.auth import X` across `src/` and `tests/` — nine sites — imports a *submodule*
(`adapters`, `classifier`, `creation`, `firebase`, `identity`, `telemetry`), which keeps resolving
against an empty init. No import site was touched.

### Task 2 — interface suites retargeted onto the surviving surface (`c9e84c1`)

`tests/unit/test_adapter_interfaces.py` went from 363 to 250 lines. `PROTOCOLS`, `ENUMS`, `FROZEN`
and `ADAPTER_METHODS` were retargeted onto the four surviving names; `TestStoreAdapter` and
`TestVendorProofAdapter` were deleted in full; the three `TestClosedOutcomeSets` cases asserting
deleted enums' member lists went with their subjects; `TestFirebaseAdminAdapter` lost the two
return-type cases for deleted methods and reduced its declared-method-set case to the one survivor.

`tests/unit/test_firebase_adapter.py` lost the parametrized case asserting the concrete lookup class
does *not* implement the two deleted Protocol methods (they no longer exist to not-implement) and
`TestTheLazyReExport` in full — four cases asserting the root's declared name list, lazy-name
identity, resolver `AttributeError` behavior, and `__dir__` listing, every one of them dead once the
init is empty. The case asserting the concrete class is not in the Protocol's MRO survives.

The guards worth keeping are all still firing: the closed four-member outcome set, the frozen and
slotted result types, the stub-only declaration rule, `ALLOWED_IMPORT_ROOTS`, and the path-keyed
`ADAPTER_IMPLEMENTORS` permission mapping with both of its controls.

## Deviations from Plan

### 1. [Rule 1 — Bug] The entry-scope control would have gone vacuous

- **Found during:** Task 2
- **Issue:** `test_an_entry_permits_the_methods_it_names_and_no_others_control` fed itself a synthetic
  source line naming `revoke_refresh_tokens` against a path listed in `ADAPTER_IMPLEMENTORS`. Once
  `ADAPTER_METHODS` shrank to the single member `get_user_provider_data` — which *both* allow-listed
  entries permit — the naive retarget would have found zero offenders and asserted `[] == []`, passing
  while proving nothing. The plan anticipated this and required a rewrite.
- **Fix:** The case now passes an explicit `{listed: frozenset()}` implementors mapping through
  `_adapter_method_offenders`'s existing `implementors` parameter and asserts the method *is* reported.
  The control's meaning survives: an exemption admits a named method, not the module holding it.
- **Files modified:** `tests/unit/test_adapter_interfaces.py`
- **Commit:** `c9e84c1`

### 2. [Rule 3 — Blocking] Task 1's `<verify>` cannot pass before Task 2 runs

- **Found during:** Task 1
- **Issue:** Task 1's automated verify is
  `python -c "import nativespeaker.api.app.main" && pytest -q --collect-only`. The collect-only half
  necessarily fails after Task 1, because `tests/unit/test_adapter_interfaces.py` still imports the
  eight names Task 1 deletes — and Task 2 is the task that fixes exactly that. The gate is
  unachievable in isolation; it is a plan-sequencing artifact, not a defect in the code.
- **Fix:** Verified Task 1 by running collection with only that one file ignored — `790/1103 collected,
  0 errors`, confirming the deletion broke nothing *except* the suite Task 2 retargets — plus the
  application import (exit 0), `ruff check src` (exit 0), and all six of Task 1's structural
  acceptance criteria. Full unmodified collection passes after Task 2.
- **Files modified:** none (verification-procedure deviation only)
- **Commit:** n/a

## Unmet Acceptance Criteria

**`wc -l < tests/unit/test_adapter_interfaces.py` is < 200 — MISSED (actual: 250).**

Every other acceptance criterion across both tasks passed. This one did not, and the shortfall is
reported rather than engineered around.

The file shrank 363 → 250 (−31%), and every case removed lost its subject to Task 1's deletions.
Reaching 200 would have required deleting roughly 50 more lines of guards that the plan's own action
block explicitly says to keep (`ALLOWED_IMPORT_ROOTS` and its enforcing case, `ADAPTER_IMPLEMENTORS`
and both controls, the stub-only and side-effect-free import classes) or that its `<behavior>` block
names as surviving proofs. Deleting live guards to satisfy a line-count proxy would have violated the
plan's `must_haves.truths`, which say nothing about file length.

Assessment: the 200-line figure is a planning-time estimate of the residue, and it undercounted. The
binding contract — the five `must_haves.truths` — is fully satisfied. No code change is warranted;
plan 06, which updates `ADAPTER_IMPLEMENTORS` when modules merge, is the natural place to revisit the
file's size if it matters.
