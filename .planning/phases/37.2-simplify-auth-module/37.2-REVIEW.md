## Critical Issues

### CR-01: Duplicate `Authorization` headers are first-wins, not rejected — the deleted `extract_bearer` was the only enforcement

**File:** `src/nativespeaker/api/app/dependencies.py:54,57-62`

**Issue:** Phase 37.2/37.4 replaced `nativespeaker.api.auth.wire.extract_bearer` with `HTTPBearer(auto_error=False)` (commit `57135d5`). The deleted function counted the raw `authorization` values *before reading any of them* and returned `BoundedReason.duplicate_authorization` for more than one — with the comment *"Counted before any value is read: `Headers.get` returns the first and hides the rest."* `HTTPBearer` calls exactly that `Headers.get`, so the check is gone and nothing else replaces it.

`SHARED-INVARIANTS.md` § Wire contract and `02-create-user.md:81` are explicit: *"Exactly one Authorization field value with one well-formed Bearer credential (case-insensitive field name — differently-cased duplicates are duplicates …); zero/multiple/comma-joined values, empty token, or trailing content reject — **never take first/last**."*

Reproduced against the real dependency with the project's own test verifier:

```
headers=[('authorization','Bearer not.a.jwt'), ('authorization','Bearer <valid>')]  -> 401
headers=[('authorization','Bearer <valid>'), ('authorization','Bearer not.a.jwt')]  -> 200 {"subject":"test-user"}
```

The second case must be a 401. `tests/unit/test_auth_security.py:98` covers only the *comma-folded* single-header form (`"Bearer t, Bearer t"`), which rejects incidentally because the joined string is not a parsable JWT; the two-header-line form is untested and passes.

Honest scoping: the token that *is* taken is still fully verified, so this is not by itself an authentication bypass, and Envoy folds duplicate `authorization` values before the backend sees them. But `SHARED-INVARIANTS.md` § Wire contract states *"Envoy's JWT filter is defense-in-depth only; no backend correctness depends on it"* — the backend is required to enforce this itself, and no longer does. `BoundedReason` also lost `duplicate_authorization`, `missing_token` and `malformed`, so the security log can no longer name which wire condition fired.

**Fix:** Keep `HTTPBearer` for the ordinary path but re-add the multiplicity check ahead of it, reading `request.scope["headers"]` rather than the merged view:

```python
_AUTHORIZATION = b"authorization"

async def get_identity(request: Request,
                       credential: HTTPAuthorizationCredentials | None = Depends(_bearer),
                       ) -> Identity:
    # ASGI lowercases header names, so differently-cased duplicates fold into this one key.
    # Counted before any value is read: `Headers.get` returns the first and hides the rest.
    if sum(1 for k, _ in request.scope["headers"] if k == _AUTHORIZATION) > 1:
        raise InvalidExternalJwt(bounded_reason=BoundedReason.duplicate_authorization)
    if credential is None:
        raise InvalidExternalJwt(bounded_reason=None)
    ...
```

and restore `duplicate_authorization` to `BoundedReason` in `auth/jwt_verifier.py`. Add the two-header-line case to `TestBearerTokenEdgeCases`.

### CR-10: `/auth/restore-subscription` admits an anonymous account as the restore destination

**File:** `src/nativespeaker/api/routers/auth.py:159-170`
**Issue:** The route narrows only to *linked* callers (`Depends(get_linked_identity)`), and the comment on line 159 says so explicitly. `get_linked_identity` (`app/dependencies.py:78-86`) admits an identity row whose `provider` is `IdentityProvider.anonymous`. Nothing downstream compensates: `grep -n "provider" src/nativespeaker/api/services/restore.py` matches only `PurchaseProvider`, and `restore.py` imports no `IdentityProvider` at all. Every sibling operation-gated route *does* gate on the stored provider — `services/auth.py:172` (`ClaimantNotAnonymous`) and `services/auth.py:223` (`ClaimantNotRegistered`) — which makes restore's omission an inconsistency, not a design choice.

Spec 10 (`specs/auth-refactor-phases/10-restore-subscription.md`) forbids this in four places:
- Description: "by a signed-in, **linked, registered, active** user".
- Branch model: "Destination must be an active, **registered** account. 'Anonymous' = zero provider-bearing `core.external_identities` rows (no `google`/`apple` row). Anonymous destination → audit `restore_destination_anonymous`, **rejected before any ownership, grant, or cap change**, enforced by the backend from stored identity state."
- Locked step 14: "re-confirm registered destination else `restore_destination_anonymous`".
- Error mapping: "`restore_destination_anonymous` keeps its own distinct operation-specific rejection in the shared response shape."

Consequence, not merely a missing check: restore sets `core.subscriptions.restore_bound_user_id` for life ("never changed once set"; "moving the binding is manual operator repair only"). Spec 11 states that an anonymous Firebase account becomes permanently unreachable after sign-out or reinstall ("no later sign-in ever resolves to it; there is no anonymous-account recovery path"). So a user who restores while still anonymous permanently binds a paid subscription to an account that can never be signed into again, and the only remedy is an operator DB edit. That is entitlement loss on a paid path, reached through the ordinary happy flow with no attacker required.

**Fix:** Gate at the route, before `service.restore` runs, alongside the existing `RestoreProviderUnknown` surface gate — the spec places this gate "before restore's client error mapping", so the router is the right seam:

```python
from nativespeaker.api.errors import RestoreDestinationAnonymous
from nativespeaker.api.tables.identities import IdentityProvider

    if identity.identity.provider is IdentityProvider.anonymous:
        # Spec 10: the destination must be a registered account; the binding is for life.
        raise RestoreDestinationAnonymous
```

Adding the class is admissible here rather than a near-duplicate: SHARED-INVARIANTS says "add a class only where the spec names one", and spec 10's mapping table names `restore_destination_anonymous` as its own distinct rejection. Register it in `errors.py` next to the other `Restore*` arms; do **not** fold it into `RestoreRefused` (404 `restore_not_found`), because that class's copy is "no active subscription found", which is not what happened.

### CR-20: A store notification with no term end mints a permanent paid grant

**File:** `src/nativespeaker/api/services/subscriptions.py:147-149` (writer: `src/nativespeaker/api/crud/subscriptions.py:314-321`)

**Issue:** `ingest` passes the notification's term end straight through to `write_subscription_grant`:

```python
ends_at=(notification.grace_period_expires_at
         if status is SubscriptionStatus.grace_period else notification.expires_at),
```

Both fields are `datetime | None` (`auth/store_notifications.py:26-27`) and both are reachable as
`None` while `status` is still in `ENTITLED_STATUSES`:

- Apple, `_crossed` (`auth/app_store.py:71-72`): `expires_at=_instant(transaction.expiresDate)` and
  `grace_period_expires_at=None if renewal is None else ...`. `verify` explicitly returns
  `_crossed(payload, transaction, None, status=status, ...)` at `app_store.py:112-113` when
  `data.signedRenewalInfo` is absent — so `data.status = BILLING_GRACE_PERIOD` with no renewal payload
  yields `status=grace_period, grace_period_expires_at=None`. An absent `expiresDate` on
  `Status.ACTIVE` does the same for the active arm.
- Play (`auth/google_play.py:260`): `expires_at=expiry` where `expiry` is `line_item.expiryTime`
  (`datetime | None = None`, `google_play.py:78`), and `_status_for` only consults expiry on the
  CANCELED branch — `SUBSCRIPTION_STATE_ACTIVE` returns `active` regardless.

`write_subscription_grant` inserts the `AccessGrant` with no validation, and
`_effective_grants_statement` (`crud/grants.py:33-34`) treats `ends_at IS NULL` as **unbounded**. The
result is a `status='active'`, `source='subscription'`, `tier_id='paid'` (1000 credits/month) grant that
never expires and is only ever ended if another notification for the same subscription arrives.

The codebase already knows this failure mode and guards it everywhere else: `RestoreService.restore`
refuses it outright (`services/restore.py:63-67`, "A proof carrying no open term entitles nothing"), and
`auth/google_play.py:242-243` carries the comment *"Left as None, every grace-period subscriber's grant
would be written with no end date."* The webhook writer is the one path with no guard.

**Fix:** compute the term once in `ingest` and refuse to write an entitled grant without one, mirroring
the existing `store_notification_without_tier` handling at `services/subscriptions.py:37-40`:

```python
term_ends_at = (notification.grace_period_expires_at
                if status is SubscriptionStatus.grace_period else notification.expires_at)
if status in ENTITLED_STATUSES and term_ends_at is None:
    # An entitled status with no term end would insert an ends_at IS NULL grant, which
    # `_effective_grants_statement` reads as unbounded. Fail closed; the store resends.
    logger.error("store_notification_without_term", event_type=notification.event_type)
    raise InternalError
...
    ends_at=term_ends_at,
```

While fixing this, also reject `term_ends_at <= starts_at` here rather than letting the
`CHECK (ends_at IS NULL OR ends_at > starts_at)` fire as a non-unique `IntegrityError` that
`write_subscription_grant` re-raises as a bare 500 on every redelivery.

### CR-40: the ingestion case locks in an unbounded paid grant, and contradicts the restore case for the identical shape
**File:** `tests/schema/test_subscription_ingestion.py:691-700`
**Issue:** `test_an_absent_grace_end_writes_a_grant_carrying_no_end_at_all_control` asserts that a `grace_period` notification carrying `grace_period_expires_at=None` writes a grant with `ends_at IS NULL`:

```python
await buyer.deliver(event_type=GOOGLE_RENEWED,
                    status=SubscriptionStatus.grace_period,
                    expires_in=timedelta(days=16), grace_period_in=None)
# Unbounded, not ineffective: `expires_at` was never read for a grace-period term.
assert [row["ends_at"] for row in await buyer.grants()] == [None]
```

That is paid entitlement no store event can ever end: `services/subscriptions.py:148-149` sets `ends_at = notification.grace_period_expires_at` whenever the status is `grace_period`, and `auth/app_store.py:72` yields `None` for that field whenever the renewal payload omits `gracePeriodExpiresDate`. The docstring frames it as "P-01's first failure, reproduced" — i.e. the test asserts the failure is still there, which turns a red test into a green one and freezes the behaviour.

Two authorities say this is wrong, not the spec:
- SHARED-INVARIANTS, *Fail-closed defaults*: "Anything unresolvable, indeterminate, malformed, or of unexpected shape rejects." A grace notification with no grace end is exactly an indeterminate term.
- `tests/e2e/test_restore_subscription.py:323-341` asserts the **opposite** for the same shape on the restore path, and states the reason in its own comment: "the term is the only end this path could write, so a grant attached here would carry a NULL end -- paid access no store event can ever end." That case answers 404 and writes nothing.

So the same `(grace_period, no grace end)` input is refused by restore and granted-forever by the webhook, and this file is what makes the second acceptable.
**Fix:** Treat an absent grace end on a `grace_period` notification as a refusal in `SubscriptionsService`, matching the restore path, and rewrite the case to assert that:

```python
async def test_a_grace_delivery_with_no_grace_end_writes_no_grant(self, _schema_db_uri):
    """Fail closed: an indeterminate term may not become an entitlement with no end."""
    async with _buyer(_schema_db_uri, provider=PurchaseProvider.google_play) as buyer:
        await buyer.deliver(event_type=GOOGLE_RENEWED,
                            status=SubscriptionStatus.grace_period,
                            expires_in=timedelta(days=16), grace_period_in=None)
        assert await buyer.grants() == []
        assert await buyer.effective() == []
```

If the behaviour is deliberate and the spec is to change, that change belongs in `specs/auth-refactor-phases/`, not in a test docstring — and `tests/e2e/test_restore_subscription.py:323-341` must move with it.

### WR-01: A startup failure after `build_admin_apps` poisons every later boot in the process, and leaks both httpx clients

**File:** `src/nativespeaker/api/app/lifespan.py:99-171`

**Issue:** Everything from `build_admin_apps` (line 102) to `yield` (line 161) runs unguarded, and the teardown block (lines 163-169) sits after `yield` with no `try`/`finally`. Any exception in between — `create_async_engine` on a malformed DSN, `JWTVerifier(...)` at line 149 when the Google JWKS host is briefly unreachable (that constructor deliberately raises, `jwt_verifier.py:110`), `LLMService(...)` — skips the whole teardown. The code's own comment at line 167 states the consequence: *"firebase_admin registers named apps process-globally and raises on a repeat, so a second boot needs these gone."* So a partially failed startup leaves `issuer:https://securetoken.google.com/<pid>` registered, and the next `build_admin_apps` in the same process raises `ValueError`. `devicecheck_client` and `play_client` leak on the same path, and a lifespan cancellation at `yield` skips teardown too.

**Fix:** Wrap the body in `try`/`finally` and put every disposal in the `finally`, guarding each object with the local that may not exist yet:

```python
db_engine = devicecheck_client = play_client = None
firebase_apps: dict[str, firebase_admin.App] = {}
try:
    ...
    yield
finally:
    if db_engine is not None:
        await db_engine.dispose()
    for client in (devicecheck_client, play_client):
        if client is not None:
            await client.aclose()
    for firebase_app in firebase_apps.values():
        firebase_admin.delete_app(firebase_app)
    logger.info("shutdown")
```

**File:** `config/config.yaml:22-30` (in particular 28-30)

**Issue:** The file asserts *"The YAML is authoritative for anything it declares: AppConfig is built as AppConfig(\*\*yaml_data, …) and pydantic-settings ranks init_settings above env_settings, so no environment variable can override a key declared here. ### WR-03: The only backend 429 the service raises carries no `Retry-After`

**File:** `src/nativespeaker/api/errors.py:130-135,195-198`

**Issue:** `SHARED-INVARIANTS.md` § Errors: *"Rate-limit rejections (gateway ones included) return 429 with `Retry-After` where computable AND the shared JSON error body naming the class."* `QuotaExceededError` is the only 429 any backend path raises (`services/quota.py:38,73`) and it inherits `AppError.extra_headers()`, which returns `self._headers` — always `None`, because nothing constructs it with headers. `grep -rn "Retry-After" src/` finds it only on `QueueFullError` and `CircuitOpenError`, both 503s. The wait *is* computable: the allowance rolls over on the UTC month boundary, derived from the same `evaluated_at` the charge already holds (`quota.py:56`).

**Fix:** Carry the seconds to the next UTC month on the exception and emit the header, mirroring `QueueFullError`:

```python
class QuotaExceededError(RateLimited):
    status = 429
    code = "quota_exceeded"

    def __init__(self, *args, retry_after_seconds: int | None = None) -> None:
        self.retry_after_seconds = retry_after_seconds
        super().__init__(*args)

    def extra_headers(self) -> dict[str, str] | None:
        if self.retry_after_seconds is None:
            return None
        return {"Retry-After": str(self.retry_after_seconds)}
```

and compute it in `QuotaService.charge` from `evaluated_at`. If the project has decided that a month-long `Retry-After` is worse than none (the reasoning in `k8s/templates/NOTES.txt:10-15` is adjacent to this), record that as a divergence under the requirement — the invariant text as written is not satisfied.

### WR-04: A client-attributable provider rejection trips the circuit breaker for every user

**File:** `src/nativespeaker/api/resilience.py:155-160`

**Issue:** `attempt()` calls `record_failure()` for *every* exception out of `operation()`, then classifies. A permanent 4xx from the provider — a content-policy `BadRequestError` 400 triggered by one user's phrase, a rejected `max_tokens` — is not transient, so it is not retried, but it has already incremented `_failure_count`. With `circuit_breaker_failure_threshold: 5` and `circuit_breaker_reset_seconds: 60` (`config/config.yaml:14-15`), five such requests with no success in between open the breaker and every subsequent caller gets 503 `service_unavailable` for a minute. At pre-launch traffic one user can produce five in a row trivially. The comment on line 157 (*"every classification is the provider's"*) is the reasoning that hides this: the classification is the provider's, but the *cause* can be the client's.

**Fix:** Record the failure only where it is attributable to provider health, i.e. after the transient/permanent split:

```python
except Exception as e:
    if _is_transient_error(e):
        await self._circuit_breaker.record_failure()
        raise TransientLLMError(str(e)) from e
    # A permanent provider rejection says nothing about provider availability.
    raise PermanentLLMError(str(e)) from e
```

Note this also means `record_success()` must still run for the permanent case if you want the counter reset; if not, leave it — a permanent error then neither trips nor clears the breaker, which is the intended reading.

### WR-05: Every 4xx writes an ERROR access line, so ERROR-rate alerting cannot distinguish an outage from a client typo

### WR-20: an Apple notification with no `data.status` becomes a permanent 500 retry loop

**File:** `src/nativespeaker/api/auth/app_store.py:105-109`
**Issue:** `status = _APPLE_STATUSES.get(data.status)` treats `None` as "a status outside Apple's own enum" and raises `UnknownStoreSubscriptionStatus`, which is an `InternalError` → HTTP 500. But `Data.status` is `Optional[Status]` and is documented as the status *of an auto-renewable subscription* (`.venv/.../appstoreserverlibrary/models/Data.py:65-74`); Apple omits it entirely for the notification types that carry a signed transaction but no subscription status — `CONSUMPTION_REQUEST`, `ONE_TIME_CHARGE`, `EXTERNAL_PURCHASE_TOKEN` are all present in the library's `NotificationTypeV2`. **Fix:** Distinguish absent from unrecognized, using `rawStatus` as the module already does for `rawNotificationType`. An absent status is a verified notification that names no subscription state, which is the same "carrying nothing a subscription row needs" case line 98 already handles with a 200:

```python
if data.rawStatus is None:

    return _crossed(payload, transaction, None, status=SubscriptionStatus.expired, tier_id=None)
status = _APPLE_STATUSES.get(data.status)

    raise UnknownStoreSubscriptionStatus(PurchaseProvider.apple)
```

Note the `tier_id=None` arm routes into `SubscriptionsService.ingest`'s existing `external_id is None or product_id is None` early return only if `external_id` is also None; pass `transaction=None` instead if you want the existing no-op path verbatim.

### WR-22: `BoundedReason` implements five of the eight rejection reasons the spec closes over

**File:** `src/nativespeaker/api/auth/jwt_verifier.py:22-28`
**Issue:** Spec 11 enumerates the closed set as "one of `missing_token`, `malformed`, `duplicate_authorization`, `bad_signature`, `issuer_mismatch`, `audience_mismatch`, `expired`, `empty_subject`". The enum has five; `missing_token`, `malformed` and `duplicate_authorization` are absent. In practice:
- A request with no credential raises `InvalidExternalJwt(bounded_reason=None)` (`app/dependencies.py:62`), so the log line carries `bounded_reason: null` — not one of the eight.
- A duplicate `Authorization` header is joined by Starlette into `"Bearer a, Bearer b"`, the resulting token fails to decode, and `bounded_reason_for` falls through its final `return BoundedReason.bad_signature` (line 69). The *outcome* is correct (rejected, never resolved by first/last), but the recorded reason is wrong.
- A structurally malformed JWT likewise lands on `bad_signature`.

Spec 11 makes this consequential: "Barrier rejections also increment the mandatory bounded-cardinality counter metric (labeled by result, bounded reason, route) that drives the invalid_external_jwt spike alert." Collapsing three distinct populations — clients that send no token, clients that send garbage, and an actor forging signatures — into `bad_signature`/`null` means the alert cannot separate a misconfigured client rollout from a credential-stuffing attempt, which is the alert's whole purpose.

**Fix:** Add the three missing members to `BoundedReason`, raise `InvalidExternalJwt(bounded_reason=BoundedReason.missing_token)` at `dependencies.py:62`, and split `bounded_reason_for`'s tail so a `DecodeError`/`InvalidTokenError` that is not a signature failure returns `malformed`. This *extends* the enum toward the spec's set rather than beyond it, so it does not widen the closed vocabulary.

### WR-23: a JWKS-endpoint outage is recorded as `bad_signature`

**File:** `src/nativespeaker/api/auth/jwt_verifier.py:161-165`
**Issue:** `PyJWKClientConnectionError` is a subclass of `PyJWKClientError`, so an unreachable or erroring Google JWKS endpoint takes this arm, fails the `_DEFINITIVE_KID_MISS` substring test (correctly — the comment at line 162 is right not to cache it), and then returns `bounded_reason_for(exc)`, which falls through to `BoundedReason.bad_signature`. During a JWKS outage every user in the fleet is rejected, every rejection is labelled `bad_signature`, and the spike alert spec 11 mandates fires reporting a mass forgery attempt. The operator's dashboard actively misdirects the investigation, and there is no signal anywhere naming the real cause.

The obvious fix — a new `BoundedReason` — is **not** valid: spec 11 closes the bounded-reason set at eight named values and `jwks_unavailable` is not among them, so widening the enum past that set would contradict the clause quoted in WR-22.

**Fix:** Keep the returned reason at `bad_signature` (the client-visible answer and the metric label must not change) and emit a separate operator log line at the one site that knows the cause:

```python
except PyJWKClientError as exc:
    if isinstance(exc, PyJWKClientConnectionError):
        # Named here because the bounded reason is closed at eight values and cannot carry it.
        logger.error("jwks_endpoint_unreachable")
    elif cache_key is not None and _DEFINITIVE_KID_MISS in str(exc):
        self._record_unknown(cache_key)
    return None, bounded_reason_for(exc)
```

(The module currently holds no logger; adding one here is consistent with `firebase.py` and `google_play.py`, and this line carries no token material.)

### WR-25: an empty or oversized Pub/Sub `data` field is a permanent 422 redelivery loop

**File:** `src/nativespeaker/api/schemas/webhooks.py:20-25`
**Issue:** `data: str = Field(..., min_length=1, max_length=PUBSUB_DATA_LIMIT)`. FastAPI validates the body model before any dependency body runs, so a message whose `data` is empty or exceeds 16384 characters answers 422 `validation_error`. # google_play.py
```python
def developer_notification_from(data: str) -> DeveloperNotification | None:

        logger.error("google_play_message_unusable")

    ...
```

### WR-26: `read()` skips the path-segment and length guards `read_for_restore()` applies to the same value

**File:** `src/nativespeaker/api/auth/google_play.py:215-222` vs `264-277`
**Issue:** `read_for_restore` refuses a dot-only `package_name` or `purchase_token` before calling `_get` (lines 272-277). `read` calls `_get` with `purchase_token` straight off the RTDN body and applies neither guard. `_get`'s own docstring admits the asymmetry at line 334: "Escaping confines each value to one segment, except dots, which `read_for_restore` refuses." `SubscriptionNotification.purchaseToken` (line 96) is a bare `str` with no `min_length` and no `max_length`.

The concrete effect uses this module's own established fact (line 155-157): `quote` leaves `.` unescaped and httpx removes dot segments, so a `purchaseToken` of `".."` produces `.../purchases/subscriptionsv2/` — a different Play URL from the one intended — and an empty token produces `.../tokens/`. async def read(self, *, package_name: str, purchase_token: str, ...):

```python
        raise Unavailable(stage="play_subscriptions_read")

```

Returning `None` (not raising) keeps the 200-and-acknowledge contract this route needs.

**Issue:** `test_a_grace_window_already_past_leaves_no_effective_grant_control` claims "the case above passes on the window, not on the delivery reaching a write at all", but it delivers `status=SubscriptionStatus.expired`, which leaves the entitled set entirely and takes a different branch from the grace case it controls. The Google twin (702-713) does it correctly, holding `status=grace_period` and moving only the window.
**Fix:** Mirror the Google twin — keep `status=SubscriptionStatus.grace_period` and set `grace_period_in=-timedelta(minutes=1)` — so the status is held constant and only the window varies.
