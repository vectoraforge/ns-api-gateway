# Phase 37.2 Plan 02: Firebase Credential Collapse Summary

**Application Default Credentials is now the only Firebase credential source: the `credentials.Certificate` branch, the `FirebaseConfig` class, the `AppConfig.firebase` field, and the `.env.example` key entry are all deleted, and the absent-credential warning names only a route that still exists.**

## Performance

## Accomplishments

- `build_admin_apps` is one-source: it probes ADC, warns and returns `{}` when absent, and otherwise builds the named app. The explicit-key arm and its `else:` are gone and the surviving body is de-indented one level (D-06).
- `FirebaseConfig` is deleted in full — the `SecretStr` field, the `PrivateAttr`, the JSON-parsing `@model_validator`, and `credential_dict()` — along with the `AppConfig.firebase` field and the `json`/`PrivateAttr` imports that became unused.
- `.env.example` documents one credential route instead of "EITHER of the two below", and tells developers to delete the now-inert variable from their own gitignored `.env`.
- The credential test surface shrank from 17 cases to 2 build cases plus the two absent-credential cases; net −268/+68 lines across the plan.
- Verified empirically (not just by argument) that a leftover `FIREBASE_SERVICE_ACCOUNT_JSON` in a real `.env` loads and boots: pydantic-settings ignores the undeclared key. That is T-37.2-07's mitigation, and it now has a standing test.

- `src/nativespeaker/api/config.py` — `FirebaseConfig` and `AppConfig.firebase` deleted; `json` and `PrivateAttr` imports dropped. `model_validator` stays (`EnvironmentConfig`), `SecretStr` stays (`DatabaseConfig.password`).

## Decisions Made

- **The `.env.example` cleanup note describes the variable instead of naming it.** The plan asked for a line telling developers to delete their local copy *and* for `grep -rn 'FIREBASE_SERVICE_ACCOUNT' .env.example src` to return nothing. Both cannot hold if the note spells the token, so the note reads "the service-account key variable this file used to document". The acceptance criterion wins; the developer still knows which line to delete because this file is where they copied it from.
- **`credentials.ApplicationDefault()` stays explicit.** Passing `None` to `initialize_app` and letting the SDK fall back would delete the separate `google.auth.default()` probe, and the probe is the entire mechanism behind D-07 warn-and-boot.
- **The surviving build case asserts the full options mapping, not just `projectId`.** See deviation 2.

## Issues Encountered

- **Two plan acceptance criteria are mis-specified and were read for intent.** `grep -c 'run_in_threadpool' src/nativespeaker/api/auth/firebase.py is 1` reads **2** — the import on line 7 plus the call — both before and after this plan's edits, so the criterion could never have held. The stated intent (the threadpool hop survived the edit) does hold. Likewise the plan's "update **both** call sites" for `_admin_credential_configured` — there is exactly **one** call site (`anonymous_firebase_credential`); the definition was presumably counted as the second.
- **No `.venv` exists inside a git worktree.** The plan's verify commands are all `.venv/bin/…`. Symlinked the main checkout's `.venv` into the worktree and ran everything with `PYTHONPATH=<worktree>/src` so the **worktree** source was under test rather than the editable install pointing at the main checkout (confirmed by printing `nativespeaker.api.config.__file__`). Symlink removed before the metadata commit; `git status` is clean.
- **`pytest-dotenv` resolves `.env` by walking up from the worktree**, so it picked up the main checkout's `.env` — which is why the e2e suite had real DB and Firebase credentials available here.
