**User's choice:** Delete the subsystem entirely.
**Notes:** Consistent with `AGENTS.md`'s instruction not to over-engineer for a threat model this
product does not have. Recorded as a flagged SHARED-INVARIANTS §4 conflict per the standing rule,
not silently resolved. Follows the same pattern as Phase 36 retiring `RejectionCounter` and Phase 37

## The auth barrier and the route registry

Raised by the developer after the audit decisions were recorded: *"remove auth/registry.py - that's
the ugliest thing I've seen so far. It's so stupid to write thousands of code just to keep JWT
validation in a middleware. Move validation to dependencies, I have to specify whether each route is
authenticated or not anyway in both cases, so middleware makes no sense here."*

No options were presented — the directive was unambiguous and the codebase corroborated it. What
scouting added: `app/dependencies.py:72` already exposes `get_linked_identity`, so routes already
declare their auth level via `Depends()` and the registry is a second declaration of the same fact.
`assert_route_enumeration` conditions 1-3 exist only to detect drift between the two copies.
`dependencies.py:77-82`'s own docstring names the failure mode as "a route's registry declaration and
its handler disagree" — impossible once there is one declaration.

**Outcome:** D-06. `auth/registry.py` (256 lines) and `auth/barrier.py` (258) both deleted;
`verification.py`, `wire.py` and `identity.py` kept and called from a dependency instead.

## Replacing the fail-closed property

The one property the registry genuinely provided: a route registered without a declaration aborts
boot. Under plain `Depends()`, a route that forgets the dependency is silently public.

| Option | Description | Selected |
|--------|-------------|----------|
| One CI test over `app.routes` | ~20 lines replacing 256; assert every route's dependant carries an auth dependency unless allowlisted | |
| Accept the loss | No replacement; route-level `Depends()` is visible in the handler signature, and there are no users yet | |
| Keep it at boot | Same assertion in the lifespan, preserving today's timing | |

**User's choice:** none of the three — *"Use router-level dependency to enforce auth on all
endpoints, and then also include the same dependency on each individual endpoint. It should be
cached, so it shouldn't run twice."*

**Notes:** Better than every option offered, and it was adopted as given. `APIRouter(dependencies=[...])`
makes authentication default-on, so a forgotten per-endpoint declaration cannot open a hole — the
property is obtained structurally rather than by assertion, which is what the three options were all
variations on. The per-endpoint declaration keeps the handler signature self-documenting. FastAPI
caches dependency results per request keyed on the callable with `use_cache=True` by default, so both
levels resolve to one execution.

Verified against the codebase while recording it: the existing router layout already partitions
cleanly by auth level (health public, auth pre-auth, root/examples/chats linked), so no router needs
splitting, and `preauth_callable` disappears rather than moves. Recorded as D-07 and D-08, with the
caching caveat written into D-07 as a planner constraint — a wrapper at one level and the bare
function at the other would defeat the cache and double the identity-resolution query.

## Decisions taken without asking

- **`AuthEventResult` survives as a plain Python enum.** Not a preference — a technical constraint
  with one sane answer. It is the internal outcome vocabulary behind every barrier `Reject`
  (`identity.py:63`) and `CLIENT_CLASS_FOR_RESULT` (`creation.py:93`), not an audit artifact. Only
  its SQLAlchemy binding and the `core.auth_event_result` PG type go. Surfaced to the user, not
  asked as a question.
- **`logger.log`, not stdlib `logging.log`,** for directive 3 — `logs.py:31` configures a structlog
  filtering bound logger that accepts the stdlib integer level directly, and routing through the
  `logging` module would bypass the structlog pipeline and lose contextvars request correlation.
  This honours the directive's intent; the literal reading would silently break log correlation.
