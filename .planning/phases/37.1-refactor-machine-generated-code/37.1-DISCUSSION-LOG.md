## Audit removal

"Remove all auditing" was ambiguous in a high-stakes way: in this repo auditing is a subsystem
(`auth/audit.py` 363 lines, the `audit` PG schema, `AuditWriter` wired into five modules, ~1,200
lines of dedicated tests, 7 ROADMAP success criteria) rather than a logging style.

| Option | Description | Selected |
|--------|-------------|----------|
| Delete the subsystem entirely | Module, writer, call sites, table, indexes, tests; amend the 7 ROADMAP criteria and flag against SHARED-INVARIANTS §4 | ✓ |
| Keep it, strip only its prose | No behavior change; folds into the docstring/comment directives | |
| Stop writing rows, keep the machinery | Remove call sites, leave module and schema for phases 38-45 | |

**User's choice:** Delete the subsystem entirely.
**Notes:** Consistent with `AGENTS.md`'s instruction not to over-engineer for a threat model this
product does not have. Recorded as a flagged SHARED-INVARIANTS §4 conflict per the standing rule,
not silently resolved. Follows the same pattern as Phase 36 retiring `RejectionCounter` and Phase 37
D-04 retiring `BudgetGate`.

## Decisions taken without asking

- **`AuthEventResult` survives as a plain Python enum.** Not a preference — a technical constraint
  with one sane answer. It is the internal outcome vocabulary behind every barrier `Reject`
  (`identity.py:63`) and `CLIENT_CLASS_FOR_RESULT` (`creation.py:93`), not an audit artifact. Only
  its SQLAlchemy binding and the `core.auth_event_result` PG type go. Surfaced to the user, not
  asked as a question.
- **`logger.log`, not stdlib `logging.log`,** for directive 3 — `logs.py:31` configures a structlog
  filtering bound logger that accepts the stdlib integer level directly, and routing through the
  `logging` module would bypass the structlog pipeline and lose contextvars request correlation.
  This honours the directive's intent; the literal reading would silently break log correlation.
