<objective>
Delete the auth-event audit subsystem outright (D-01): `auth/audit.py`, `AuditWriter`, `build_details`, `redact`, every call site, the `AuthEvent` model, the `audit.auth_events` table with its four indexes, the `core.auth_event_result` type, and every test that proves any of it.

Purpose: auditing every auth attempt into a dedicated Postgres schema is machinery built to satisfy `01-foundation.md §4`, not a threat model. It costs ~1,600 lines in a pre-launch sub-$5/month grammar app. `record_rejection`'s `auth_rejected` security-log event is the cheap, no-schema version of the same signal and stays.

Output: an application and a schema with no auth-event audit trail, with the full suite green and `audit.subscription_events` untouched.

**This is the phase tracer.** It is the most self-contained of the three workstreams and its removal is independently verifiable end to end — code, migration, applied database, and suite. Nothing in plan 02 or the prose plans starts until this plan's suite is green.

**This is a one-way change.** Task 1 is a blocking decision checkpoint: the table, its enum type and ~1,600 lines of code and tests are deleted, and restoring them means re-editing the single initial migration, rebuilding the writer, and re-wiring five call sites across phases that will have moved on.

**Task ordering is load-bearing.** Tests are stripped BEFORE production code, and the migration is edited LAST. Each of the three work tasks therefore leaves the suite green at its own commit, which is the only safety net a behavior-reducing refactor has.
</objective>
