## The three not-what-it-looks-like notes the plan named, and where they now live

Each is one plain sentence, placed on the thing it describes rather than in a module preamble.

**1. The JWKS-offload harness self-test is permanent, not scaffolding.**
`tests/unit/test_jwks_offload.py::test_the_harness_detects_a_starved_loop`:

> `"""Permanent, not scaffolding: without this control the case above is a green assertion never shown to fail."""`

The module still has 3 cases and still passes. This is the control that makes the bounded-fetch
count non-zero; deleting it would turn the measured no-starvation assertion into one that passes
vacuously.

**2. The adapter-interfaces no-provider-SDK guarantee is measured over `sys.modules`.**
`tests/unit/test_adapter_interfaces.py::TestNoProviderDependency`:

> `"""No `firebase_admin` in `sys.modules`, so a convenience import anywhere in the auth package fails this too."""`

Stated this way so a maintainer who trips it looks for the stray import rather than relaxing the
assertion.

**3. The auth-security premise is a structural property now, not a registry claim.**
`tests/unit/test_auth_security.py` module docstring:

> `"""What admission refuses at the wire; a route is authenticated because its router declares the dependency."""`

The old prose explained that `/probe` was deliberately *undeclared* so the barrier would fall back
to its strictest disposition — a fallback that no longer exists. The replacement states the D-07
property that replaced it.

Two further notes the plan named in Task 3, both kept:

- `test_error_contract.py` module docstring — *"The contract under test is that every branch within
  an error class returns identical copy."* The anti-oracle property, so a later phase does not
  "improve" a message and break it.
- `test_logging.py::test_request_id_bound_in_context` — *"Request correlation travels through
  contextvars, which is what carries it into every log record."*

### The AST-equality check is what makes "prose only" checkable

Run against `dffecd8` rather than against `HEAD`, so it spans all three commits at once. It parses
both revisions, deletes the docstring statement from every module, class and function, and compares
`ast.dump`. That makes it blind to prose and to line movement while remaining sensitive to any
assertion, fixture signature, parametrize list or marker that changed. It reported `SAME` for
thirty files, which is the plan's T-37.1-13 mitigation discharged mechanically rather than by
review.

Note that **deleting** a docstring also passes this check, and legitimately: the stripped old body
equals the new body. So the check proves no executable line moved; it does not by itself prove a
docstring survived. That half is covered by the measurement command and by the three notes above
being asserted individually.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 — Bug] The first collapse pass truncated wrapped sentences**

- **Found during:** Task 1, on the first file (`test_hmac_keys.py`).
- **Issue:** collapsing a docstring to its first *physical line* produced fragments — e.g.
  ``"""`AppConfig` is a model and reads nothing; `EnvironmentConfig` is the loader that opens"""``
  with the object of the clause on the dropped line. These docstrings wrap one sentence across two
  or three lines, so "first line" is not "first sentence".
- **Fix:** reverted the file with `git checkout --`, then changed the collapse to join the first
  paragraph and take its first sentence. Nothing from the bad pass was committed.

**2. [Rule 1 — Bug] Two docstrings written onto the wrong class**

- **Found during:** Tasks 1 and 3 (`test_conflict_classification.py`,
  `test_quota_resolver.py`).
- **Issue:** the citation grep reports line numbers, and I mapped two of them to the wrong node.
  `TestUnknownTier` received the text belonging to `TestNoEffectiveGrant`, and
  `test_a_historical_row_is_the_historical_result` — which had a perfectly good one-line docstring
  and no citation — was overwritten with a claim that was **factually wrong** (it said the result
  was "identical to the caller" as already-linked, but `historical_identity` maps to
  `account_unavailable` and `identity_already_linked` does not).
- **Fix:** both restored from `git show HEAD:<path>`; the tooling was then changed to print
  `L<line> <qualname>` for every docstring node so a grep hit maps to a node unambiguously. Both
  were caught by re-running the cross-reference grep *after* applying, which is why that check now
  runs on every file both before and after.
- **Commits:** `eedf35f`, `e59eb22`

**3. [Rule 2 — Missing] `test_logging.py` recorded nothing about contextvars**

- **Found during:** Task 3.
- **Issue:** the plan requires keeping "whatever records that the structured pipeline carries
  request correlation through contextvars, because plan 04's change to the error handler depends on
  it". No prose recorded it — the module has no docstring at all, and
  `test_request_id_bound_in_context`, which is precisely the case that proves it, was undocumented.
  The existing prose was entirely about a structlog caching problem.
- **Fix:** added the one-line docstring to that case. Adding a docstring where there was none is
  AST-safe under the equality check and is prose, not an executable line — verified: the file
  still reports `SAME`.

### Environment note (no repository change)

Confirmed the hazard the prompt warned about. The worktree has no `.venv`, and
`nativespeaker.api` is a **namespace** package whose `__path__` spans both this worktree and the
main checkout. Resolved by symlinking `.venv`/`.env` and running every command with
`PYTHONPATH=src`, which puts the worktree first:


`diff -rq` also confirmed the two `src/` trees were byte-identical for this run, so the spanning
could not have masked anything. **Both symlinks were removed before this commit and neither was
ever staged.**
