<objective>
Rewrite the prose across `tests/unit/` (D-13, D-14, D-15, D-16): collapse every multi-line docstring to one line naming what the case proves, remove every multi-line comment block, and delete every citation a reader cannot resolve without the planning directory open.

Purpose: `tests/` carries 419 multi-line docstrings against `src/`'s 155, and the unit suite holds most of them. A test docstring that explains which spec step required the case tells a reader nothing about what breaks when it fails.

Output: twenty-nine unit modules whose prose says what each case proves.

## Pinned definitions

A **multi-line comment block is a run of two or more consecutive own-line comment lines** — the threshold for this phase is two, not three. A surviving note must fit one line within the 120-character limit.

The three commands used verbatim in every acceptance criterion below — **the measurement command**, **the AST-equality check**, and **the cross-reference grep** — are written out in full in the `<objective>` of `.planning/phases/37.1-refactor-machine-generated-code/37.1-03-PLAN.md`. Read that section and use them exactly as written.

**No prose-ratio cap applies to test files.** A one-line docstring naming what a case proves is exactly what D-14 asks for, and a module can legitimately carry one per test. The criteria are `multiline_docstrings=0` and `comment_blocks=0`, nothing more.

## The target register

One line, present tense, naming the observable fact the case proves — "an expired challenge is rejected without consuming it", not "§6.3 step 4's expiry arm, per 37-CONTEXT.md D-07". `tests/unit/test_services.py` (252 lines, 2 prose lines) and `tests/unit/test_exception_handlers.py` (122 lines, 12) are already close to it.

**Note on module names.** Plan 02 may have renamed the barrier-named modules. Use whatever names they carry when this plan runs; the file list in the frontmatter is the pre-rename set.
</objective>
