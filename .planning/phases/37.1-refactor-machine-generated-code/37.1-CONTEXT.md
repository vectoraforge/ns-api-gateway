# Phase 37.1: Refactor machine-generated code - Context

**Gathered:** 2026-08-24
**Status:** Ready for planning

<domain>
## Phase Boundary

Phases 34-37 were executed largely by parallel agents, and the code carries the marks of it:
machinery built to satisfy a spec rather than a need, and source prose written as an audit trail of
the planning process rather than as an explanation for someone reading the code cold.

This phase does three things:

1. **Deletes the auth-event audit subsystem outright** — the `audit.auth_events` table, the writer,
   and every call site.
2. **Replaces the auth barrier middleware and the route registry with FastAPI dependencies** — JWT
   acceptance and identity resolution move into a router-level dependency that every endpoint also
   declares individually.
3. **Rewrites the prose across `src/`, `tests/` and the migration** — docstrings collapsed to one
   line or removed, multi-line comment blocks removed, and everything that survives rewritten in
   plain English.

It is a behavior-reducing refactor. No new capability is added and no endpoint changes shape, with
two exceptions: auth attempts stop writing audit rows, and the mechanism enforcing authentication
changes (though not which routes are authenticated).

**The measured surface:**

| | |
|---|---|
| `src/` | 6,687 lines — 903 comment lines + 1,836 docstring lines = **41% prose** |
| Docstrings in `src/` | 155 multi-line, 46 single-line |
| Multi-line comment blocks in `src/` | 121, across 30 files |
| `tests/` | 17,028 lines across 62 files |
| Audit code | `auth/audit.py` 363 lines + call sites in barrier, router, `creation.py`, lifespan, dependencies |
| Audit tests | 1,202 lines dedicated; referenced in 22 test files total |
| Barrier + registry code | `auth/barrier.py` 258 + `auth/registry.py` 256 = **514 lines** |
| Barrier + registry tests | 1,350 lines across 6 files |

Together the two deletions remove roughly **3,400 lines** before a single docstring is touched.

**Out of scope:** the open `37-REVIEW.md` findings (see Deferred), any change to *which* routes are
authenticated, any endpoint behavior change beyond the audit removal, and phases 38-45's own work.

## Implementation Decisions

### The audit subsystem — deleted

- **D-01: The auth-event audit subsystem is removed entirely.** `src/nativespeaker/api/auth/audit.py`,
  the `AuditWriter` class and every call site (`auth/barrier.py:203`, `routers/auth.py:197`,
  `auth/creation.py:145`, `app/lifespan.py:53`, `app/dependencies.py:122-128`), the
  `audit.auth_events` table and its four indexes, and the dedicated tests. Nothing writes an auth
  audit row afterward.

  The developer's judgement, and it is consistent with `AGENTS.md`: auditing every auth attempt to a
  dedicated Postgres schema is over-engineering for a pre-launch sub-$5/month grammar app. The
  subsystem was built because `01-foundation.md §4` mandates it, not because a threat model asked
  for it. — **Reversibility:** one-way — the table, its enum type and ~1,600 lines of code and tests
  are deleted; restoring means re-editing the single initial migration, rebuilding the writer, and
  re-wiring five call sites across phases that will have moved on.

- **D-02: `audit.subscription_events` stays, and so does the `audit` schema.** It is the
  subscription/purchase event log, not auth auditing. `SCHEMA-07` deliberately relocated it out of
  `core`, and `tests/schema/test_inventory.py:299-302` asserts it survived that move. The webhook
  phases still need somewhere to record store notifications. Only `auth_events` and its indexes are
  dropped; `DROP SCHEMA audit CASCADE` is **not** the mechanism.

- **D-03: `auth/telemetry.py` stays.** `record_rejection` emits the structured `auth_rejected`
  security-log event for rejections. It is the cheap, no-schema version of what the audit table was
  doing, `REBIND-02` already depends on it, and it costs nothing to keep. Its call site moves from
  the barrier into the auth dependency (D-07). Its docstring gets the same plain-English rewrite as
  everything else.

- **D-04: `AuthEventResult` survives as a plain Python enum — this is a hard constraint, not a preference.** It is the internal outcome vocabulary, not an audit artifact:
  `auth/identity.py:63` builds every `Reject` from it, `auth/creation.py:93`'s
  `CLIENT_CLASS_FOR_RESULT` maps it to client-visible error classes, and `auth/retry.py:35` and
  `auth/telemetry.py:24` both consume it. Deleting it would take out the rejection classification
  along with the audit rows.

  What does go: `AuthEventResultType` (`models/auth.py:85`, the SQLAlchemy `Enum` binding it to
  `core.auth_event_result`) and the `core.auth_event_result` PostgreSQL type itself, whose only
  consumer is `audit.auth_events.result` at `migrations/20260818_01_initial-release.sql:673`.

  **`core.auth_operation` and `AuthOperation` stay** — `core.auth_challenges.operation` uses the type
  at `:596`, and `auth/creation.py:147` uses the enum.

- **D-05: The migration is edited in place and the dev/test database dropped and re-applied.** Same
  mechanism 37-01 Task 1 resolved for D-13: `SCHEMA-01` is a shipped requirement reading "no
  incremental migration files are added", and `tests/schema/test_apply_rollback.py::TestMigrationDirectory::test_exactly_one_sql_file`
  enforces it live. That test must stay green **unmodified**. — **Reversibility:** one-way —
  destructive schema change, cheap pre-launch with no deployed database.

### The barrier and the route registry — replaced by dependencies

- **D-06: `auth/registry.py` and the `AuthBarrierMiddleware` are both deleted. JWT acceptance and identity resolution move into FastAPI dependencies.**

  The developer's reasoning, and the code bears it out: a route's auth level has to be declared
  per-route either way, so the middleware buys nothing and costs a parallel declaration table. The
  registry exists *only* because a middleware cannot read per-route declarations — and then
  `assert_route_enumeration` conditions 1-3 exist only to detect that the parallel table drifted
  from the router. That entire failure class is self-inflicted.

  The confirming detail: `app/dependencies.py:72` **already has** `get_linked_identity`, so routes
  already declare what they need via `Depends()`. The registry declares the same fact a second time.
  `dependencies.py:77-82`'s own docstring describes its failure mode as "a route's registry
  declaration and its handler disagree" — a disagreement that cannot exist once there is one
  declaration. — **Reversibility:** costly — 514 lines of source and 1,350 lines of tests are
  deleted, and the wire contract, admission matrix and rejection mapping must be carried across
  intact rather than rewritten.

- **D-07: Enforcement is a router-level dependency that every endpoint also declares individually.**
  The developer's design, chosen over a CI assertion and over accepting the loss.

  - `APIRouter(dependencies=[Depends(...)])` makes authentication **default-on**: an endpoint that
    forgets to declare it is still authenticated, so a typo cannot silently open a hole. This is the
    property `assert_route_enumeration` conditions 1-2 were protecting, obtained structurally
    instead of by assertion.
  - The same dependency is **also declared on each endpoint**, so the handler signature states its
    own auth level and hands the handler the resolved identity.
  - It runs **once**. FastAPI caches dependency results per request keyed on the callable, and
    `use_cache` defaults to `True`, so the router-level `Depends(get_linked_identity)` and the
    endpoint's own resolve to one execution. **Planner: do not pass `use_cache=False` anywhere on
    this path, and keep both levels referencing the identical callable object** — a wrapper at one
    level and the bare function at the other would defeat the cache and double the work, including a
    second identity-resolution query.

- **D-08: Routers are partitioned by auth level. The current layout already fits — no router needs splitting.**

  | Router | Routes | Router-level dependency |
  |---|---|---|
  | `health_router` | `GET /health/ready` | none — public |
  | `auth_router` | `POST /auth/create-user` | `Depends(get_preauth_identity)` |
  | `root_router` | `GET /` | `Depends(get_linked_identity)` |
  | `examples_router` | `GET /examples` | `Depends(get_linked_identity)` |
  | `chats_router` | the `/chats` family | `Depends(get_linked_identity)` |

  This is what makes `preauth_callable` disappear rather than move: the one route admitting an
  unlinked caller is the only route on `auth_router`, so its admission rule is expressed by which
  dependency that router carries. The registry flag, `_PREAUTH_CALLABLE_ROUTE`, and condition 6
  guarding it all become unnecessary.

  It also matches the deployment split already recorded in STATE.md — separate HTTPRoutes per auth
  level.

- **D-09: `get_request_context` becomes the single verification point, and the identity accessors become async.**

  Today the barrier verifies and stashes a `RequestContext` on `request.state`, and
  `get_request_context` (`dependencies.py:62`) reads it. Inverted: `get_request_context` does the
  work — the `auth/wire.py` Authorization contract, `auth/verification.py`'s JWT verify through
  `run_in_threadpool`, `auth/identity.py::resolve_identity`, and the single captured `evaluated_at`
  — and FastAPI's per-request cache guarantees it runs once. `get_linked_identity` and
  `get_preauth_identity` stay exactly what they are today: thin type-narrowing wrappers over it.

  **This preserves 35 D-02 (one captured evaluation time, never recomputed) and SHARED-INVARIANTS'
  single-resolution-point rule** — the dependency cache enforces both, the same way the middleware
  did.

  Consequence the planner must carry: `get_request_context`, `get_linked_identity` and
  `get_preauth_identity` all become `async def`, because resolution touches the database. Every call
  site changes signature, including the five challenge-bearing accessors at `dependencies.py:103+`.

  `auth/verification.py` (255 lines), `auth/wire.py` (58) and `auth/identity.py` (101) are **kept and
  called from the dependency** — they hold the FOUND-02 wire contract and the FOUND-01 admission
  matrix, neither of which is changing. Only their caller moves.

- **D-10: What dies with the registry, itemised, so the planner does not mistake any of it for a regression.**

  - **`quota_checked` and condition 10.** The flag existed only to be cross-checked against the
    charging handler. With no declaration table there is nothing to pair, so the check is not lost —
    its subject is. Quota enforcement itself is untouched: `consume_quota` is called inside
    `create_chat` and `send_message` and stays there.
  - **`Category`, `RouteMetadata`, `VERIFIERS`, `NamedVerifier` and conditions 4-9.** The
    provider-callback verifier seam has no members yet (`VERIFIERS` is empty); phases 43/44 express
    it as a router with its own verifier dependency instead.
  - **`tests/e2e/test_startup_assertion.py`** (62 lines) and **`tests/unit/test_route_registry.py`**
    (380 lines) — delete outright. `tests/e2e/test_barrier_admission.py` (273),
    `tests/unit/test_barrier_wire_contract.py` (136), `tests/unit/test_identity_accessors.py` (335)
    and `tests/unit/test_auth_security.py` (164) test behavior that survives and must be **rewired,
    not deleted** — they are the proof that the admission matrix still holds after the move.
  - **`app/main.py`'s `docs_url=None` / `redoc_url=None` / `openapi_url=None` stay off, and the
    reason gets stronger.** D-04's original rationale was that they would be undeclared registered
    routes. Under D-07 they are worse: FastAPI registers them on `app.router` directly, so they
    would bypass every router-level dependency and be genuinely public. Same for
    `app.router.redirect_slashes = False` at `main.py:47` — keep it.

- **D-11: FOUND-01's substance survives; only its mechanism changes. Flag it, do not silently resolve it.** FOUND-01 requires "a mandatory, default-on pre-handler barrier [as] the only place

### The prose rewrite

- **D-13: Reach is `src/`, `tests/`, and `migrations/20260818_01_initial-release.sql`.** Everything.

- **D-14: Docstrings collapse to one line; docstrings whose purpose is obvious are removed outright.** 155 multi-line docstrings in `src/` alone.

- **D-15: Multi-line comment blocks are removed.** 121 blocks across 30 files in `src/`.

- **D-16: Every comment and docstring that survives is rewritten in plain English.** This is the
  qualitative half of the phase and the part a planner is most likely to under-specify.

  What "plain English" rules out, all quoted from live code:

  - **Spec and plan cross-references as load-bearing text.** `routers/auth.py:1-32` cites `37-09`,
    `35 D-02`, `D-10`, `D-11`, `§02 step 14` and `37-RESEARCH Pitfall 6`. A reader without the
    planning directory open cannot resolve any of them.
  - **Arguing with a hypothetical reader.** `routers/auth.py:16` — "It looks like a stray commit
    otherwise -- it is not." `auth/audit.py:20` — "Raising here with a message naming the problem
    beats a constraint violation at insert time."
  - **Instructions to future maintainers.** `models/auth.py:100` — "Do not add a state column, and
    do **not** add an HMAC key-version column." `routers/auth.py:100` — "exactly two fields. Do not
    add a third."
  - **Markdown emphasis and section symbols inside docstrings.**

  What it must **not** destroy: the non-obvious invariants this prose is currently the only record
  of. `routers/auth.py:12-16` explains that a mid-handler `commit()` is deliberate, because holding
  the challenge claim uncommitted across the provider call would let a second attempt win the same
  challenge. That fact has to survive, as one plain sentence. The rewrite is a change of register,
  not an amnesty on documenting surprises.

### Logging

- **D-17: `_LEVEL_TO_METHOD` is replaced by `logger.log(level, ...)`.** `app/errors.py:19-25` is a
  five-entry dict feeding `getattr(logger, method_name)` at `:31-33`, purely to turn a `logging.*`
  integer into a structlog method name.

  The direct replacement works: `logs.py:31` configures
  `wrapper_class=structlog.make_filtering_bound_logger(...)`, and that bound logger exposes
  `.log(level, event, **kw)` taking the stdlib integer level. So `:30-34` becomes one
  `logger.log(exc.log_level, str(exc), error_type=..., exc_info=...)` call. It is `logger.log`, not
  the stdlib `logging.log` — routing through the `logging` module would bypass the structlog
  pipeline and lose the contextvars request correlation.

### Claude's Discretion

- Plan decomposition. Three independent workstreams: the audit deletion, the barrier/registry
  replacement, and the prose rewrite. Separate commits at minimum; the barrier replacement is the
  one with real behavioral risk and should be able to revert on its own.
- Ordering. Both deletions remove ~3,400 lines that would otherwise be rewritten, so doing them
  before the prose pass is cheaper. Not mandated.
- Whether `auth/audit.py`'s `build_details` has a non-audit consumer worth preserving —
  `routers/auth.py:52` and `auth/creation.py:47` both import it, so check before deleting.
- Whether `app/dependencies.py:127`'s `get_session_factory` has a consumer besides
  `write_standalone`; if not, it goes with D-01.
- Whether `RequestContext` still needs a client-IP bucket field once auditing is gone.
- How aggressively to collapse test docstrings.

## Specific Ideas

- The developer's directives, verbatim. First round: remove all auditing from the code; collapse all
