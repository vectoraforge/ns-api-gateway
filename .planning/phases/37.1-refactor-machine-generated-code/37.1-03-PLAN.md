## The pinned definitions — these make the acceptance criteria checkable

**A multi-line comment block is a run of two or more consecutive own-line comment lines.** CONTEXT.md D-15 says "multi-line", and two lines is literally multi-line; the pattern mapper measured 121 blocks at a three-line threshold and 184 at a two-line threshold, a difference of 63 sites. **The threshold for this phase is two.** A surviving note must therefore fit on one line within the project's 120-character limit; if a fact needs more than that, it belongs in the function's one-line docstring or as one sentence of prose that reads without it.

**The measurement command**, used verbatim in every acceptance criterion below:

```
.venv/bin/python -c "
import ast,sys
for p in sys.argv[1:]:
    s=open(p).read(); L=s.splitlines(); t=len(L)
    c=sum(1 for l in L if l.strip().startswith('#'))
    d=0; m=0
    for n in ast.walk(ast.parse(s)):
        if isinstance(n, ast.Module|ast.ClassDef|ast.FunctionDef|ast.AsyncFunctionDef):
            x=ast.get_docstring(n,clean=False)
            if x is not None:
                b=n.body[0]; d+=b.end_lineno-b.lineno+1
                if x.strip().count(chr(10)): m+=1
    r=0; blocks=0
    for l in L:
        if l.strip().startswith('#'): r+=1
        else:
            blocks += r>=2; r=0
    blocks += r>=2
    print(f'{p} ratio={100*(c+d)/max(t,1):.1f} comments={c} dslines={d} multiline_docstrings={m} comment_blocks={blocks}')
" FILES
```

**The AST-equality check**, proving no executable line moved:

```
.venv/bin/python -c "
import ast,sys,subprocess
for p in sys.argv[1:]:
    def strip(src):
        t=ast.parse(src)
        for n in ast.walk(t):
            if isinstance(n, ast.Module|ast.ClassDef|ast.FunctionDef|ast.AsyncFunctionDef) and ast.get_docstring(n) is not None:
                n.body = n.body[1:] or [ast.Pass()]
        return ast.dump(ast.fix_missing_locations(t))
    old=subprocess.run(['git','show',f'HEAD:{p}'],capture_output=True,text=True).stdout
    print(p, 'SAME' if strip(old)==strip(open(p).read()) else 'CHANGED')
" FILES
```

## The two poles — read these before writing a single line

**Target style, already plain:** `src/nativespeaker/api/logs.py` (2.6% prose — one single-line docstring, one comment), `src/nativespeaker/api/database/chats.py` (1.9% — zero docstrings, every method self-describing), `src/nativespeaker/api/routers/health.py`, `routers/examples.py`, `routers/root.py` (0% — the FastAPI `summary=` and `description=` kwargs carry the user-facing text), `src/nativespeaker/api/models/chats.py` (0%).

What plain English rules out, all quoted from live code: spec and plan cross-references as load-bearing text; arguing with a hypothetical reader ("It looks like a stray commit otherwise — it is not"); instructions to future maintainers ("Do not add a state column"); markdown emphasis and section symbols inside docstrings.

What it must not destroy: the non-obvious invariants this prose is currently the only record of. The rewrite is a change of register, not an amnesty on documenting surprises.
