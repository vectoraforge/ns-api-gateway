# Phase 37.1 Plan 05: Routers, models and services prose rewrite Summary

Rewrote the prose in sixteen files — the two remaining router modules, the whole `models/`
package, and six top-level service and infrastructure modules — dropping 859 lines and adding
110, with every executable line proven unchanged by AST equality against the plan's base commit.

## What was done

**Task 1 (`96508fa`) — `routers/auth.py` and `routers/chats.py`.** The 31-line module docstring
that cited a plan number, three decision ids, a spec step and a research pitfall became one line.
All twelve multi-line docstrings collapsed and all seventeen comment blocks became isolated single
lines. The arguments with a hypothetical reader ("It looks like a stray commit otherwise -- it is
not") and the instructions to future maintainers ("exactly two fields. Do not add a third") are
gone. `routers/chats.py` lost the block describing registry declarations and a decorator
dependency that wave 2 deleted.

**Task 2 (`fb46357`) — the `models/` package, seven files.** Every ruling-numbered per-field
comment, every maintainer instruction and every history note about a dropped column deleted.
`models/users.py` and `models/purchase_tokens.py` — both above 50% prose — now read like
`models/chats.py`.

**Task 3 (`84ef397`) — `quota.py`, `config.py`, `resilience.py`, `database/grants.py`,
`services/chats.py`, `services/llm.py`.** `quota.py`'s 46-line module docstring and
`database/grants.py`'s 15-line one both became a single line carrying the fact the rest of the
module cannot state. `logs.py` was inspected and left untouched.

## Notes for later phases

**1. The generated OpenAPI's `CreateUserRequest` component description changed.** FastAPI derives
`components.schemas.<Model>.description` from a Pydantic model's docstring, so collapsing
`CreateUserRequest`'s eleven-line docstring necessarily changed it. This is not a regression: the
plan mandates collapsing every multi-line docstring including model docstrings, the *route-level*
`summary`/`description` strings the acceptance criterion names are byte-identical, and
`app/main.py` sets `openapi_url=None` / `docs_url=None` / `redoc_url=None`, so the schema is never
served. Worth knowing if a later phase publishes the schema.

**2. `ty check src/` reports 3 pre-existing diagnostics, unchanged by this plan.** All three are
`invalid-argument-type` on `_consuming_rejection` in `routers/auth.py`. Verified identical against
the main checkout's unmodified `src/` before and after. The plan's must_have asked that `ty` stay
clean; it was not clean at baseline, and this plan neither added nor removed a diagnostic. Note
that `ty` needs `VIRTUAL_ENV` set explicitly when run from a worktree with no local `.venv`, or it
reports 93 spurious `unresolved-import` diagnostics.

**3. Two out-of-scope prose defects found, not edited** (both outside this plan's declared
`files_modified`; recorded here rather than in the shared `deferred-items.md` to avoid colliding
with the five sibling wave-3 agents):

- `tests/unit/test_users.py:42` says "as `models/users.py`'s docstring records" — that module
  docstring was deleted by this plan, so the sentence now points at nothing. `tests/` prose is
  plan 07's scope.
- `src/nativespeaker/api/errors.py`'s `ErrorResponse` docstring reads "Exactly one field -- do not
  add more", an instruction to a future maintainer of exactly the kind D-16 rules out. That file
  is plan 04's scope.

**4. The schema suite is flaky under wave-3 parallelism, not under this change.** Running six
executor agents against one shared PostgreSQL means `tests/schema/` — which drops and re-applies
the migration, and whose `test_grant_locks.py` deliberately provokes deadlocks — intermittently
sees a half-built schema or a foreign lock. Observed at baseline before any edit, and cleared on
every re-run. `-m schema` alone passed 115/115 on four separate runs; `-m ""` passed 1140/1140 on
the final run.
