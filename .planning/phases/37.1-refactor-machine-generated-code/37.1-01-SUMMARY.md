# Phase 37.1 Plan 01: Delete the auth-event audit subsystem Summary

Deleted the auth-event audit trail whole — `auth/audit.py`, the `AuthEvent` model, the
`audit.auth_events` table with its four indexes, and `core.auth_event_result` — while
`AuthEventResult`, `record_rejection` and the `begin_nested()` savepoint all survive intact.

## What was done

**Task 1 — the one-way gate.** Presented and resolved before this dispatch. **Decision:
`option-a` — proceed with the deletion.** The user was shown that proceeding falsifies two
shipped requirements, conflicts with the binding spec, and strands two unbuilt phases, and chose
to proceed anyway. Those conflicts are recorded below as *flagged, not resolved*.

**Task 2 (`5eb23e1`) — tests stripped first, production untouched.** The three dedicated audit
modules deleted outright (1,202 lines); every audit reference removed from 18 remaining modules.
`git diff --stat HEAD -- src/` was empty at this commit, so the unit and e2e suites stayed green
against unchanged production code — the safety net a behaviour-reducing refactor depends on.

**Task 3 (`e615a71`) — production code.** `auth/audit.py` deleted (363 lines) along with
`AuditWriter`, `build_details`, `redact`, `DETAILS_SCHEMA_VERSION`, the `AuthEvent` SQLModel,
the `AuthEventResultType` binding, `get_audit_writer`, `get_session_factory`,
`AuthBarrierMiddleware._audit`, `_prepare_details`, `_completion_details` and
`creation.py::_details`.

**Task 4 (`098bcab`) — the migration, last.** The `CREATE TYPE core.auth_event_result` (44
labels), the `CREATE TABLE audit.auth_events` (nine CHECKs) and the four `ix_auth_events_*`
indexes deleted from the forward section **by name**. The dev database was rolled back and
re-applied from the edited file.

## 37-REVIEW CR-02 — closed as a side effect

CR-02's whole shape was `_prepare`'s already-linked arm reading `linked.provider` off an ORM
instance that the immediately preceding `await session.rollback()` had expired — a lazy load off
the event loop, turning a 409 into a 500 and telling the caller something the 409 does not.

Both halves were audit-only and went together: the rollback existed solely to free the session
for the standalone write, and `linked.provider` was read solely to populate `actor_provider`. The
arm is now:

```python
linked = await _already_linked(session, identity=identity)
if linked is not None:
    return error_response(IDENTITY_ALREADY_LINKED)
```

Verified: `sed -n '/async def _prepare/,/challenge_store.issue/p' … | grep -c "session.rollback"`
returns **0**.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 3 — Blocking] Task 2 needed temporary inert stand-ins, removed in Task 3**

- **Found during:** Task 2
- **Issue:** The plan's ordering (tests first, production second) means that when Task 2 removes
  the audit *fixtures*, `create_account` still declares `audit_writer` and the route still
  declares `Depends(get_audit_writer)`. FastAPI resolves every declared dependency before the
  handler runs, so simply deleting the overrides raised `AttributeError` on a bare test app, and
  deleting the argument raised `TypeError` from `create_account`. 16 tests failed.
- **Fix:** Task 2 replaced each `_RecordingAuditWriter` with a minimal inert `_InertWriter`
  (no recording, no assertions) carrying an explicit "deleted later in this plan" docstring.
  Task 3 removed all five of them once the production parameters were gone.
- **Files:** `tests/unit/test_create_user_rollback.py`, `tests/unit/test_conflict_classification.py`,
  `tests/unit/test_create_user_modes.py`, `tests/unit/test_create_user_precedence.py`,
  `tests/schema/test_create_race.py`, `tests/schema/test_create_atomicity.py`
- **Plan gap:** Task 3's `<files>` lists no test files, but removing the production dependency
  necessarily strands the test imports and overrides. Test files were therefore touched in both
  Task 2 and Task 3.
- **Commits:** `5eb23e1`, `e615a71`

**2. [Rule 2 — Missing critical coverage] Internal-result assertions re-pointed at the log, not deleted**

- **Found during:** Task 2
- **Issue:** `tests/unit/test_create_user_precedence.py` used `writer.results` as the *only*
  observable distinguishing nine internal results that collapse into four client classes — the
  module's entire subject. A literal reading of "delete the audit assertion" would have deleted
  ~25 assertions and left the precedence suite unable to tell `challenge_expired` from
  `challenge_consumed`.
- **Fix:** The router already logs the specific internal result on every rejection arm
  (`create_user_challenge_rejected`, `create_user_lookup_rejected`,
  `create_user_transaction_rejected`). Added a `_RejectionLog` spy on
  `routers.auth.logger.warning` — following the established `test_identity_resolution.py`
  monkeypatch-spy pattern, not `capture_logs`, per 35-02's caching note — and re-pointed the
  assertions at it. Coverage preserved at zero schema cost, which is exactly D-03's argument.
- **Commit:** `5eb23e1`

**3. [Rule 2 — Missing critical functionality] Bounded `provider_not_linked` cause carried into the log**

- **Found during:** Task 3
- **Issue:** `_classification_cause` (D-12's two-member bounded vocabulary) fed only the audit
  row's `details.failure.cause`. Deleting the row left it an unreachable function — precisely
  the dead machinery this phase exists to remove — and silently dropped a diagnostic.
- **Fix:** `_consuming_rejection` now takes `cause` and emits it in the
  `create_user_lookup_rejected` event, omitted rather than `None`-valued when not applicable.
  The test assertion deleted in Task 2 was restored against the log.
- **Commit:** `e615a71`

**4. [Rule 1 — Bug] Dangling prose extended beyond the plan's named files**

- **Found during:** Task 4
- **Issue:** The plan named only `auth/keys.py` and `auth/challenges.py` for prose repair, but
  its own `<verification>` block requires
  `grep -rn "auth_events" src/ tests/ --include=*.py` to return nothing. Three files outside
  `files_modified` still named the dropped table in comments — statements that had become false.
- **Fix:** One-sentence comment repairs in `auth/identity.py`, `auth/modesignal.py` and
  `models/identities.py`. Also repaired further dead references inside in-scope files
  (`auth/keys.py` ×3, `auth/challenges.py` ×5, `auth/__init__.py`) and in
  `auth/telemetry.py`, whose prose the plan's D-03 prohibition explicitly permits changing and
  which claimed the bounded reason travelled "into the audit row's `details.failure`".
- **No behaviour change** — comments and docstrings only.
- **Commits:** `e615a71`, `098bcab`

### Plan-document drift found (informational)

- **PATTERNS.md §2.5** says `EXPECTED_AUDIT_INDEXES` has "9 entries … keep the 4
  `subscription_events` ones". The live set has **8** (5 `auth_events_*` + **3**
  `subscription_events`). Removed the 5, kept the 3.
- **Plan acceptance criterion** for Task 2 expected
  `grep -rn "auth_events" tests/ --include=*.py` to return hits in
  `tests/schema/test_apply_rollback.py`. That file's six audit references are all to the `audit`
  **schema**, never to `auth_events`, so the grep returns nothing at all — a cleaner outcome than
  specified, and the file remains unmodified as D-05 requires.

### Deliberately not done

- **`_challenge_rejected` keeps its `await session.rollback()`.** It is no longer needed to free
  the session for a standalone write, but it still releases the read transaction `locate` opened
  rather than holding it through the response. Removing it would be a behavioural change beyond
  D-01's scope, and `test_create_user_modes.py` asserts `session.rollbacks == 1` independently.
  Its docstring now says what the rollback is actually for.
- **`_challenge_rejected` still logs the result under the key `stage=`**, while
  `_consuming_rejection` uses `result=`. The key name is misleading (for that helper the stage
  *is* the result) but renaming it changes the log schema, which is out of scope here. The test
  helper reads both keys and documents the quirk.
- **`RequestContext.client_ip_bucket_kind`** and its 8 test call sites left untouched — that
  field's removal belongs to plan 02, which reshapes `RequestContext`.

`.pth` hard-points at the **main checkout's** `src`. Running tests naively would have exercised

`PYTHONPATH=$PWD/src`, then verifying `nativespeaker.api.auth.__path__` resolves to the worktree
alone (`auth` is a regular package, so the deleted `audit.py` cannot fall through to the main
checkout). Both `.venv` and `.env` are gitignored and were never staged.
