<objective>
Replace the auth barrier middleware and `auth/registry.py` with FastAPI dependencies (D-06, D-07). JWT acceptance and identity resolution move into `get_request_context`, declared on each `APIRouter` **and** on each endpoint, resolved once per request by FastAPI's dependency cache.

Purpose: a route's auth level has to be declared per-route either way. A middleware cannot read a per-route declaration, so the registry exists to hold a parallel copy — and `assert_route_enumeration` conditions 1-3 exist only to catch that copy drifting from the router. The whole failure class is self-inflicted. `app/dependencies.py:72` already has `get_linked_identity`; the registry declares the same fact a second time.

Output: 514 lines of source and ~1,766 lines of test deleted or rewired, with the admission matrix, the wire contract, the rejection mapping and every route's authentication status carried across intact.

**This is the only workstream with real behavioral risk and it must be revertable on its own.** The three tasks below are the revert unit; do not fold any of them into another plan.

**D-11 is flagged, not resolved.** FOUND-01 requires "a mandatory, default-on pre-handler barrier [as] the only place JWT acceptance and identity resolution happen". A router-level dependency is mandatory, default-on, runs before the handler, and is the only place resolution happens — every property holds, only the word "barrier" does not. FOUND-03, which requires a route registry and an enumeration assertion, genuinely goes. Plan 08 records both against `SHARED-INVARIANTS.md`; this plan does not silently resolve them.

## Two design decisions this plan makes and records

**1. How the dependency signals a rejection.** `barrier.py:167` *returns* `error_response(error_class)` because `add_middleware` places the middleware outside Starlette's `ExceptionMiddleware`. A dependency runs *inside* it, so the dependency raises instead. But `errors.py` has no `ServiceError` subclass for `PREAUTH_IDENTITY_NOT_ALLOWED` or `ACCOUNT_UNAVAILABLE` — the barrier reached those `ErrorClass` objects directly — and `ServiceError.error_class` is a class attribute.

**Decision: one new subclass, `AuthRejectionError(ServiceError)`, carrying a per-instance `error_class`.** Its `__init__` takes an `ErrorClass` and a message and assigns `self.error_class`, which shadows the class attribute; `service_error_handler` reads `exc.error_class` and produces the identical body. It sets `log_level = None`, so no second log line appears beside `record_rejection`'s `auth_rejected` warning. It does **not** override the extra-headers hook: `AuthenticationError` adds `WWW-Authenticate: Bearer`, and the barrier's 401 never carried that header, so reusing `AuthenticationError` here would be a wire change D-10 forbids. Three subclasses were the alternative; one is shorter, and the `ErrorClass` is already a value rather than a type.

**2. Where the route path template comes from.** `RequestContext.route_metadata` dies with the registry, but three consumers survive: `QuotaGate(route=...)`, the `auth_mode_signal_invalid` log line, and `record_rejection(route=...)`. **Decision: `RequestContext` gains a plain `route: str` field** holding the path template. FastAPI sets the matched route in the ASGI scope inside `APIRoute.matches` (verified in the installed `fastapi/routing.py:803`; Starlette's `Router.app` merges the child scope before dispatch), so `request.scope["route"].path` is available to a dependency — which is exactly what the middleware position denied the barrier and why `barrier.py::_match_full` existed. `_match_full` is deleted outright rather than moved. Re-verify this at execution time with a real request; it is the one load-bearing framework assumption in the phase.
