## Invariants judged load-bearing and kept

Each survives as one plain sentence, sited where a maintainer about to break it would read it.

**`auth/verification.py`** (the three the plan named, T-37.1-15):
- `verify` returns `(claims, reason)` rather than raising, and callers rely on that — module docstring.
- An absent or non-string `kid` shares one sentinel entry, because PyJWT would otherwise refetch for
  each such token. At the `_cache_key_for` call, where the sentinel is chosen.
- A connection error records no `kid`, because caching an outage would prolong it fleet-wide. In the
  `except PyJWKClientError` arm, on the line that decides what to record.
- Also kept: the negative cache stores a deadline only; `verify` runs on the worker threadpool so an
  unsynchronised dict would escape as a 500; the bare `except Exception` is what makes "never raises"
  structural; the explicit `timeout=` exists because PyJWT defaults to 30 seconds.

**`auth/creation.py`**:
- The `begin_nested()` savepoint: a conflict rolls the three inserts back but leaves the consume able
  to commit — the race loser still leaves durable state.
- The ordering constraint: the consume runs on the outer transaction, on success and rejection alike,
  before the commit, and never commits itself.
- Also kept: rollback first and classify second, because until then the session refuses every further
  statement; the re-resolution is not the race arbiter; the constraint names are PostgreSQL-generated
  and a schema test pins them; an unmapped constraint re-raises rather than being swallowed.

**Elsewhere**: byte-for-byte handle comparison and `expires_at` taken from the caller's evaluation
time and never renewed (`challenges.py`); which providerData outcomes are terminal and what each
`None` means (`adapters.py`); the retry predicate keys on the returned result rather than a raised
exception, because the adapter returns (`retry.py`); `route` is the path template, never the
caller's raw path (`telemetry.py`); the query string is parsed here rather than through a
first-value-wins accessor, because a duplicate is its own rejection (`modesignal.py`).

## Deviations from Plan

### 1. [Rule 3 — blocking] Live tests pin docstring *content* in two of the eight files

Found during Task 1, before any edit. Four tests assert on docstring text, and plan 07 — running
concurrently in wave 3 and owning both test files — is explicitly forbidden from altering an
assertion or a parametrize list. So these phrases must survive the phase, in my files:

- `tests/unit/test_adapter_interfaces.py` requires `adapters.__doc__` to contain
  `no provider call while a database lock is held`, `5-10 seconds` and
  `never leak provider text to clients`; `VendorProofAdapter.__doc__` to contain `rate-limit key`
  and `device principal`; `StoreAdapter.__doc__` to contain `coalesc`.
- `tests/unit/test_provider_classifier.py` requires `classifier.__doc__.lower()` to contain five
  phrases: `never take the first recognized entry`, `never classify non-empty providerdata as
  anonymous`, ``never read `firebase.sign_in_provider` ``, `no declaration match`, and
  ``no `required_flow` ``.

The plan's action text for Task 3 says to delete classifier's "bolded three-prohibition list". Its
own must-have truths and acceptance criteria say pytest must exit 0. I kept the phrases and rewrote
them in plain register — bold, the `§02` citation, the `T-37-15` ticket, the `D-12` narration and
the argument with a superseded research document are all gone. The prohibitions themselves are the
one thing in that docstring the code does not say, which is also what the plan's own Task 3 text
asks to preserve ("the classifier is closed").

### 2. `auth/classifier.py` keeps a 3-line module docstring — `multiline_docstrings=1`

This is the one acceptance criterion in the plan that is not met, and it is not satisfiable as
written. The five pinned phrases total 163 characters before any connecting prose; with `"""` they
cannot fit one physical line inside the project's 120-character limit (ruff `E501` is enabled).

Two escapes were tried and rejected:

- **Implicit string concatenation** (used successfully in `adapters.py`) fails here, and the test
  caught it. `test_neither_deleted_concept_appears_outside_the_docstring` removes the docstring from
  the *raw source text* with `source.replace(ast.get_docstring(...), "", 1)`, then asserts
  `sign_in_provider` and `required_flow` appear nowhere in what remains. A concatenated value never
  appears verbatim in the source, so the replace is a no-op and both names survive. The same
  argument rules out a backslash line continuation.
- **A `# noqa: E501` on a ~180-character line** would satisfy all three machine checks. Rejected: a
  180-character docstring is worse to read than three wrapped lines, and suppressing the project's
  line limit to please a metric is the kind of artefact this phase exists to remove.

So classifier's docstring is three physical lines of plain English, down from twenty-seven. Every
other docstring in the eight files is a genuine one-liner. `adapters.py` needed the same treatment
for the same reason and got parenthesised concatenation, which no test there objects to — its
`__doc__` really is one line.

### 3. Deleted `retry.py`'s and `adapters.py`'s section-banner and per-constant commentary

`adapters.py`'s three `# ---` section banners went whole (they carried `§7.1`/`§7.2`/`§7.3` and
nothing else). Four docstrings whose purpose the name and signature already state were removed
outright under D-14 rather than collapsed: `ProviderDataOutcome`, `ProviderDataEntry`,
`FirebaseAdminAdapter.verify_id_token`, and `retry.py::_is_retryable`. This was needed to bring
`adapters.py` under the 18% cap (it sat at 19.7% with all docstrings collapsed but none deleted).

`retry.py`'s module docstring named `retry_if_exception_type` by a deliberate choice recorded in
37-02's summary. The name survives, moved to a single-line comment on the `retry=` argument itself —
the line a maintainer would actually edit when "fixing" the predicate. No test pins its location.

## Out of scope — logged, not acted on

Per the wave-3 isolation rule, these were found but not touched; none is in this plan's
`files_modified`.

1. **The e2e and schema suites are not isolated across concurrent worktree agents, and collide
   destructively.** `tests/schema/conftest.py` drops and recreates a single fixed database,
   `ns_schema_test`, in a session-scoped fixture, and drops it again at session end. Six wave-3
   agents running `pytest` concurrently therefore delete the database out from under each other —
   observed here as `asyncpg.exceptions.InvalidCatalogNameError: database "ns_schema_test" does not
   exist` across 26 schema tests, which passed on the next run untouched. The e2e suite has the same
   shape: `tests/e2e/test_challenge_store.py::_contended_challenge` commits rows through a second
   engine, and `TestTheRollbackIsolatesEveryRow` asserts `core.auth_challenges` is empty — it saw a
   sibling's committed row and failed `assert 1 == 0`, then passed on re-run. Both were confirmed
   environmental: this plan's diff is AST-identical to base, and each suite passed in isolation. A
   per-worker database name (or a `--dist loadfile`-style lock) would fix it.
2. **`src/nativespeaker/api/routers/auth.py` has 3 pre-existing `ty` errors**
   (`invalid-argument-type` on `_consuming_rejection`, at `:342` and `:433`). Present before this
   plan; that file belongs to another plan's file set.
3. **`ty check src/` without `--python` reports 88 spurious `unresolved-import` errors** because the
   worktree has no `.venv`. Not a code defect; worth a note in whatever runs `ty` in CI.
4. **`tests/unit/test_adapter_interfaces.py`'s src-wide scan is a raw text scan** (`if method in
   text`), so an adapter method named in any non-exempt module's *prose* fails it. Not hit here, but
   it constrains what any future prose pass may write in `auth/`.
