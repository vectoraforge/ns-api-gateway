## D-17: the level dispatch table

`_LEVEL_TO_METHOD` and the `getattr(logger, method_name)` dispatch are gone. `service_error_handler`
now logs through one `logger.log(level, str(exc), error_type=..., exc_info=...)` call on the
module-level **structlog** bound logger, so the contextvars request correlation is intact.

**The literal replacement the plan specified would have been a regression, not a refactor.**
structlog's filtering bound logger implements `log()` as:

```python
if level < min_level:
    return None
name = LEVEL_TO_NAME[level]
```

`LEVEL_TO_NAME` is a plain dict with exactly the same five keys the deleted `_LEVEL_TO_METHOD` had,
so `logger.log(exc.log_level, ...)` raises `KeyError` on any other level — where the old
`.get(exc.log_level, "error")` fell back to ERROR. The fallback is preserved as a frozenset
membership test, which is not a level-to-method-name table: no method names and no `getattr`.

Verified by direct comparison of the old and new call paths over 5 configured minimum levels x 12
log levels (the five standard ones plus 0, 5, 15, 25, 35, 45, 55): **zero mismatches**, including
identical `exc_info` and identical filtering behaviour. The same probe confirmed the naive form
raises `KeyError` on 15, 25, 35, 45 and 55.

All grep criteria hold: `_LEVEL_TO_METHOD` 0, `logger.log(` 1, `getattr(logger` 0, `logging.log(` none.

## Invariants deliberately kept

- **`wire.py`** — the raw ASGI header list is read, never a first-value accessor, which returns the
  first value and hides a duplicated or comma-joined `Authorization`. Split across two one-line
  comments at the two points that enforce it.
- **`identity.py`** — admission is a positive test so unrecognized or future state fails closed; the
  join is outer so a broken link stays distinct from an unlinked pair; both `account_unavailable`
  arms do identical work.
- **`context.py`** — one captured evaluation time for the whole request that nothing recomputes, and
  `PreAuthIdentity` carrying nothing an unlinked caller could be read as linked by.
- **`app/dependencies.py`** — both session-source facts, one plain sentence each: the auth dependency
  opens its own short session and closes it before the handler (`:64`), and `QuotaGate` takes the
  session factory (`:142`). Either alternative holds a transaction across the LLM provider round trip.
- **`app/lifespan.py`** — named Firebase apps are given back on shutdown because the SDK registry is
  process-global and the e2e suite boots twice in one process.
- **`errors.py`** — copy is neutral by construction, `register_class` rejects rather than merges, the
  body carries exactly one field, and `AuthRejectionError` carries its class per instance and logs
  nothing because the security log already recorded the rejection.

## Deviations from Plan

**1. [Rule 1 - Bug] D-17's fallback preserved rather than dropped**

- **Found during:** Task 3
- **Issue:** The plan's literal `logger.log(exc.log_level, ...)` raises `KeyError` inside the
  service's central exception handler for any level outside structlog's five. The plan's own text
  requires "the previous fallback to error on an unmapped level" be preserved.
- **Fix:** `level = exc.log_level if exc.log_level in _LOGGABLE else logging.ERROR`, then one
  `logger.log(level, ...)`. Unreachable in production today (only ERROR, WARNING and None are used),
  but the handler must not be the thing that crashes while handling an error.
- **Commit:** 9b32785

**2. [Rule 3 - Blocking] blank line removed inside `auth/__init__.py`'s import block**

- Deleting the comment above the classifier import left a blank line that ruff's `I001` rejected.
  Blank lines are within the plan's allowance. **Commit:** aa73b8c

**3. Corrected the 405 comment in `errors.py`** — `deferred-items.md` recorded it as inaccurate and
`errors.py` is in scope, so it was fixed rather than carried: an unauthenticated caller *can* reach
a 405, because a method mismatch matches no route and so runs no route's auth dependency. The
anti-oracle claim survives on correct reasoning — a 405 discloses only that the path exists.

## Deferred / not done

**The acceptance criterion asking for a test case at a `log_level` outside the five could not be
satisfied here.** `tests/unit/test_exception_handlers.py` is declared in **plan 07**'s
`files_modified` and plan 07 is running concurrently in this same wave; editing it would collide.
The equivalence was instead proven out-of-tree by the probe described above. **Plan 07 or a
follow-up should add the case** — the behaviour it would pin is live in `app/errors.py:19-27`.

**Two cross-reference grep hits survive in `keys.py:53` and `:56`**, both inside
`Field(description=...)` — executable string literals, not comments or docstrings. Rewriting them
would change an executable line, which the plan prohibits (`AST-equality must report SAME`), and
they feed the OpenAPI schema. The plan's `must_haves` truth is scoped to "comment or docstring",
which holds. A future plan that is allowed to touch executable lines should reword them.
