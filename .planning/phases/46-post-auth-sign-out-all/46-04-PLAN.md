  - A scripted `firebase_admin.exceptions.FirebaseError` subclass answers **503** with code

    swallowed the raise is visible in the case name.
  - A scripted `firebase_admin.auth.UserNotFoundError` answers **401** with code `auth_required`
    and the `WWW-Authenticate: Bearer error="invalid_token"` header the `UserNotFound` leaf
    declares (D-06).

    raise `RevocationUnconfirmed(stage="issuer_selection")`, which is exactly what the real seam

    seam boundary and no SDK call happened below it.
  - One case comparing the raw bytes of the two 503 bodies — the outage one and the no-app one —
    and asserting they are equal. A body naming which check refused would fail here. The `stage`
    reaches the operator's WARNING record alone.
  - A repeat call after a confirmed one answers 204 again. The operation is idempotent at the IDP:
    a second revocation only re-asserts a later timestamp, and the route holds no state that a
    repeat could disagree with.

Every docstring is three lines or fewer and every comment is one ASD-STE100 line (D-11).

Add the barrier and logging cases.

Barrier rejections. For each rejection `/auth/sync` already covers — an unverifiable token, an
unlinked subject, a pre-auth identity, a retired identity and a blocked user — post the same
request to both `/auth/sync` and `/auth/sign-out-all` in one case and assert the two responses have
the same status and the same raw body bytes. The barrier is shared and is not re-implemented, so
the answer must not differ by route. Assert additionally that in every one of these the fake
recorded **zero** revocation calls: no barrier rejection may reach Firebase.

Log discipline, using the `_LogSpy` and `_spy_on` helpers, never `capture_logs()`, because the
module-level logger caches its binding.
  - A confirmed revocation records exactly one entry with event `sign_out_all_confirmed`, and its
    fields are exactly `{"identity_row_id": ...}` with the value equal to the seeded identity row's
    id as a string.
  - No captured record for any case in this file contains the subject string or the seeded
    provider uid, in any field value. Write this as one assertion over every captured entry, so a
    later added field cannot slip a subject in.
  - A refused call records **no** `sign_out_all_confirmed` entry. Spy on both `routers/auth.py`'s
    logger and `app/error_handlers.py`'s logger, and assert the refusal produced one WARNING
    record whose event is `revocation_unconfirmed`, which is the class name in snake case.

Every docstring is three lines or fewer and every comment is one ASD-STE100 line (D-11).
