<objective>
Ship the vertical slice of `POST /webhooks/app-store`: Apple's signed envelope arrives with no
Authorization header, is verified through Apple's own library against the vendored Apple Root CA G3,
crosses into this project's own value type, and one transaction writes the canonical
`core.subscriptions` row and its `audit.subscription_events` row and commits before the 200.

Purpose: prove the whole architecture — the partition, the admission gate, the seam, the value
type, the service, the crud and the replay key — on one path, before any expansion task widens it.

Output: a registered, exact-path, unauthenticated-by-design route; `AppStoreNotifications` and
`VerifiedNotification`; `SubscriptionsService`; `SubscriptionsDB`; three ratchet literals
re-measured in the commits that trip them; an e2e round trip and a real-chain unit suite.

**Why Task 1 spans 22 files, deliberately.** The span is inherent to the tracer, not a packing
choice. The three ratchet tests are measured to break in the same commit as the source change that
trips them (RESEARCH P-05, P-06, P-07): `test_app_wiring.py` fails the moment `include_router` runs,
because its two existing literals are compared with `==` against the live app object;
`test_auth_package_shape.py` fails the moment `auth/app_store.py` exists; and
`test_rejection_vocabulary.py` fails the moment the two error leaves exist. Deferring any of them to
Task 2 or to a later plan would land a red suite on `main`, which is what a ratchet is built to
prevent. The `__init__.py` barrel exports are the same case one tier down — a name that is imported
but not exported fails `ruff` in the commit that imports it. The remaining files are one per layer,
which is what a tracer is. The calibrated estimate (47,500 of 100,000 tokens, confidence high) leaves
the headroom this coordination costs.
</objective>

  <behavior>
    - Given a `signedPayload` signed by the configured root's chain and carrying a transaction part,
      the route returns 200, one `core.subscriptions` row exists for `(apple, external_id)`, and one
      `audit.subscription_events` row carries the payload's `notificationUUID`.
    - Given a body whose signature, chain, bundle id or environment does not check out, the route
      returns 401 and the response body is byte-identical for every one of those arms.
    - Given a second delivery of an already-recorded `notificationUUID`, the route returns 200 and no
      second `audit.subscription_events` row is written.
    - Given a notification with no transaction part, the route returns 200 and writes nothing.
    - Given incomplete `app_store` configuration, the route returns 503 and the app still boots.
    - Given the app object, `/webhooks/app-store` is the only route on the webhooks router and declares
      neither identity accessor; `PUBLIC_PATHS` is unchanged as a literal.
  </behavior>
