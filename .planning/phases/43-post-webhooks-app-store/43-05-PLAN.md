<objective>
Execute every remaining outcome instead of arguing it: the two-connection race that decides whether
replay suppression actually holds, the wire-level proof that the route is no oracle, and the
configuration gate that keeps a misconfigured deployment from becoming an open endpoint.

Purpose: this route is publicly reachable with no credential, and its two hardest properties —
"a replay changes nothing" and "every refusal looks the same" — are exactly the two that a unit test
with a stubbed session cannot prove.

Output: a two-connection race against real PostgreSQL, a refusal matrix compared on the wire, and the
configuration cases.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → the route's response body | Whatever differs between refusals is information a prober can read |
| deployment configuration → the verifier | A configuration value decides whether signatures are checked at all |
| two concurrent deliveries → the database | Replay suppression is only real if it holds under contention |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-43-03 | Tampering | replay under contention | high | mitigate | The two-connection race proves one winner and one loser that wrote nothing, arbitrated by `notification_uuid UNIQUE` rather than by the pre-write read |
| T-43-05 | Information Disclosure | the refusal body | medium | mitigate | Every verification arm is compared as raw response bytes, so a differing field is a test failure rather than an oracle a prober can read |
| T-43-04 | Elevation of Privilege | `config.app_store.environment` | high | mitigate | The two library environment values that skip signature verification are refused at configuration load, asserted with string literals so the case survives a library change |
| T-43-19 | Denial of Service | a misconfigured deployment losing six days of notifications | medium | mitigate | A Production-without-app-id configuration boots and answers 503 rather than crashing the pod, and the `stage` field on the rejection warning distinguishes a configuration fault from a forged payload |
| T-43-06 | Information Disclosure | log records | high | mitigate | One case walks every record captured in the module and asserts no signed payload, attribution token or store token value appears, with a control proving the walk sees records |
| T-43-SC | Tampering | package-manager installs | low | accept | This plan installs no package and edits no dependency file |
</threat_model>
