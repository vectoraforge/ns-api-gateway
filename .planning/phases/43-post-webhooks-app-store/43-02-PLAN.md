  </read_first>

  <action>
Add one block to `.env.example`, after the DeviceCheck block, in exactly the shape that block uses.

The header line names the section and where it is used: the App Store Server Notification route
`POST /webhooks/app-store`.

The prose states four things, each in one or two short sentences. First, where each value comes from:
the bundle id and the numeric Apple id are read in App Store Connect under App Information, and the
environment is a decision the deployer makes. Second, that the environment has **no default** and must
be stated in a visible line, because Apple signs sandbox notifications too and a sandbox purchase is
free to anyone with a test build, so an unstated environment would let sandbox traffic reach a
production deployment. Third, that these are not secrets — a bundle id and an Apple id are public —
but they stay out of `config/config.yaml` anyway, because that file is `init_settings` and outranks
every environment variable for a key it declares, so a value written there could never be changed per
environment. Fourth, what the deployment does without them: the service boots, logs one
`app_store_configuration_absent` warning, and the route fails closed as 503
`verification_temporarily_unavailable`; Apple then retries on its own schedule.

Then the three variables, with the same placeholder style the file already uses:
`APP_STORE_BUNDLE_ID`, `APP_STORE_APP_APPLE_ID` and `APP_STORE_ENVIRONMENT` (whose two accepted values
are `sandbox` and `production`).

Do not document `APP_STORE_ROOT_CERTIFICATE_PATH` as a value a deployer must set: it defaults to the
certificate already committed at `config/certs/AppleRootCA-G3.cer`, valid to 2039. Mention the default
in one line so a reader knows why no path variable is listed. Do not add
`app_store.products` here — it belongs in `config/config.yaml`, where plan 43-01 put it, because it is
a public map and an operator edit is the intended remediation loop for an unmapped product.

Every sentence is Simplified Technical English: short, one idea each.
  </action>
