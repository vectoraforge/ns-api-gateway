## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Boot-built objects → per-request code | `get_runtime` is the one crossing point after this phase |
| `Runtime` → logs | The container holds `config`, whose `DatabaseConfig.url` renders a password |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-50-03-01 | Information disclosure | `Runtime` in a log record | high | mitigate | No log call takes the container or `runtime.config` as a value. `logger.info("started", ...)` keeps naming `config.model.name`, `config.resilience.pool_size` and the example languages. The task action states this and the plan-50-07 gate greps for it. |
| T-50-03-02 | Tampering | request-scoped mutation of boot state | medium | mitigate | `frozen=True, slots=True` means a handler cannot rebind a field or add one; pinned by the `FrozenInstanceError` case in task 3. |
| T-50-03-03 | Spoofing | the interim dual state | medium | accept | For this plan only, `app.state.jwt_verifier` and `app.state.runtime.jwt_verifier` both exist. Nothing reads the container's copy of a swapped field yet, so no test is silently neutralised; plans 50-04 to 50-06 close the window one field group at a time. |
| T-50-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed or upgraded; `uv.lock` is not touched. |
