## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pod boot → serving traffic | The stack decides whether a half-built pod becomes Ready |
| Pod shutdown → external resources | An unclosed httpx client or engine holds a credential-bearing connection |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-50-07-01 | Information disclosure | a failing teardown swallowing a leaked client | high | mitigate | `AsyncExitStack` runs every remaining callback and then propagates, so no leak is hidden behind a swallowed exception — measured by task 2's behavioural case, not assumed. The `shutdown_step_failed` handlers that swallowed are deleted. |
| T-50-07-02 | Denial of service | a failed reachability probe leaking a pool | medium | mitigate | `push_async_callback(engine.dispose)` is registered before the probe, so a probe that raises still disposes. Pinned by the criterion-1 line-order assertion. |
| T-50-07-03 | Information disclosure | `logger.info("started", ...)` | high | mitigate | The started line keeps naming `config.model.name`, `config.resilience.pool_size` and the example languages — three scalars, never the container or `config`, whose `DatabaseConfig.url` renders a password. |
| T-50-07-04 | Spoofing | builder ordering | high | mitigate | `build_session_factory` and `build_jwt_verifier` run before the degraded-tolerant providers, so a pod that cannot verify an identity token never reaches the point of building a store seam. Pinned by task 2's criterion-2 ordering case. |
| T-50-07-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed or upgraded in this phase; `uv.lock` is not touched. RESEARCH.md records the Package Legitimacy Audit as not applicable. |
