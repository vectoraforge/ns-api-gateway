<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Bearer token → `get_claims` | The identity barrier; every authenticated route resolves through it |
| Request → database session | `get_db` opens the one session a handler writes through |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-50-04-01 | Spoofing | `get_claims` | high | mitigate | The verifier moves from an attribute read to a container field; the `claims is None` guard, the `BoundedReason` mapping and the `run_in_threadpool` offload are carried over unchanged. `tests/unit/test_auth_security.py` and `tests/unit/test_jwks_offload.py` are verify commands of this task. |
| T-50-04-02 | Elevation of privilege | `get_identity` | high | mitigate | The `PreAuthIdentityNotAllowed` raise on an unresolved pair is unchanged; `tests/unit/test_identity_accessors.py` pins it and runs in the unit gate. |
| T-50-04-03 | Tampering | `dataclasses.replace` in nested e2e fixtures | medium | mitigate | Every fixture saves the field value and replaces the field, reading the then-current container both ways, so an inner fixture's swap is never reverted by an outer one. Stated in the task action and covered by the `-m e2e` run. |
| T-50-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed or upgraded; `uv.lock` is not touched. |
</threat_model>
