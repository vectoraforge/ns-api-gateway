## Assumption A2 — CLOSED before planning, verified against the installed FastAPI 0.135.1

The D-05 cross-check rested on an unverified assumption about FastAPI's introspection surface. It
was executed this session against the pinned version. Result:

- `route.dependencies` — the **raw decorator-level** list. Items are `fastapi.params.Depends`
  objects; the callable is on `.dependency`.
- `route.dependant.dependencies` — the **solved** list. Items are `Dependant` objects; the callable
  is on `.call`. This list also contains **parameter-level** dependencies.

Observed for a route declared `dependencies=[Depends(quota_wrapper)]` whose handler also takes
`p=Depends(param_dep)`:

```
raw route.dependencies:                  [quota_wrapper]
dependant.dependencies top-level calls:  [quota_wrapper, param_dep]
```

**Therefore: condition 10 must read `route.dependencies` and match `.dependency` by identity.** That
list is exactly the decorator-attachment set D-05 describes, so a parameter-level dependency cannot
produce a false positive. `route.dependant.dependencies` would conflate the two. The task below is
written against the verified surface; no alternative inspection strategy is needed.

The D-14 mitigation was re-verified in the same run: with the body model declared on the dependency,
an invalid body yields `422 | calls: []` (the dependency never ran) and a valid body yields
`200 | calls: ['QUOTA-RAN', 'handler']`.
