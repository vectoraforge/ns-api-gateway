<objective>
Close VERIFICATION gap 1 (truth 1, 45-REVIEW CR-02): the status that decides entitlement is taken
from the stored row and the term that becomes the grant's end is taken from the client-presented
proof, and the two are never reconciled.

Purpose: two reachable combinations mint a grant that does not correspond to anything verified — a
`grace_period` stored row plus an Apple proof (whose grace window is always absent) writes
`ends_at = NULL`, a paid grant that never expires; and a stale proof against an `active` stored row
writes an already-past `ends_at` that occupies the account's one slot and cannot self-heal.
Output: one check before any write, the corrected `ends_at` argument, and the e2e cases the phase's
1246+321+222 passing suite never had.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> `POST /auth/restore-subscription` | The caller chooses which signed transaction to present, including an old one. Apple's `originalTransactionId` is stable across renewals, so a stale proof is a normal, cheap thing for a caller to hold. |
| the stored `core.subscriptions` row -> the written `core.access_grants` row | The status crosses from the canonical record and the term crosses from the caller's artifact. This is the boundary the gap sits on. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-45-07-01 | Elevation of privilege | `services/restore.py` -> `crud/subscriptions.py::write_subscription_grant` | high | mitigate | Refuse before any write when the proof's own term for the decided status is absent or already past. Closes the `ends_at = NULL` combination, which grants the paid tier indefinitely because `_effective_grants_statement` reads a NULL end as effective forever. |
| T-45-07-02 | Denial of service | the account's one grant slot (`ix_access_grants_one_active_per_user`) | high | mitigate | Same check: a stale proof can no longer insert a dead grant that occupies the slot, supersede a free grant that `ix_access_grants_one_free_grant_per_user_source` will never allow again, and then answer `replayed` on every retry. |
| T-45-07-03 | Information disclosure | the refusal body as an oracle for another account's subscription state | low | mitigate | The new refusal reuses `RestoreSubscriptionNotEntitled`, so all three arms answer identical bytes. Pinned by `test_the_three_arms_of_the_family_answer_the_same_bytes`. |
| T-45-07-04 | Spoofing | a forged proof | low | accept | Out of scope here and already answered: the artifact is verified by Apple's own library or by Google's live read before this check runs (truths 2 and 4, VERIFIED). |
| T-45-07-SC | Tampering | package-manager installs | low | accept | This plan adds no npm/pip/cargo dependency and does not touch `uv.lock`. No package legitimacy checkpoint is required. |
