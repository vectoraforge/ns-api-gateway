**Case R8 needs care.** The point is that the lifetime free-grant index has no status predicate, so the slot stays occupied forever. Insert the first free grant, set it to `expired`, then attempt a second grant of the **same source** for the **same user** — and confirm the rejection. A test that never expires the first grant proves only R7 over again.

**Case LB is a deferred constraint and needs explicit transaction control (P-6).** Drive it with `await conn.execute("BEGIN")`, the offending INSERT, then `pytest.raises(asyncpg.ForeignKeyViolationError)` around `await conn.execute("COMMIT")`. Do **not** call `ROLLBACK` afterwards: the deferred FK fires at COMMIT, the server has already aborted the transaction by the time the exception surfaces, and a `rollback()` on asyncpg's still-open-looking `Transaction` object raises a second, different exception that masks the first. The `conn` fixture already guards its own teardown rollback for exactly this reason, but the test must not add its own.

Seed through the helpers, not through raw INSERTs copied between tests, and let the per-test transaction own the boundary — the helpers must not commit. Every row value binds through asyncpg `$1` positional parameters; never build row data into a SQL string with an f-string.

Where a test deliberately writes an invalid row, mark it with the repository's deliberate-omission comment convention from `tests/unit/test_models.py:61-64`, so a later reader does not "fix" the test by making the row valid.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test assertions → the constraints they claim to prove | A test that passes for the wrong reason is worse than no test: it converts an unverified constraint into a verified-looking one |
