<objective>
Build the schema-conformance harness and prove the object inventory — the first expansion out from the tracer.

Purpose: SCHEMA-08 requires every acceptance check in `00-schema.md §10` to pass against a freshly migrated database, and D-17/D-18 make that proof programmatic rather than a reviewer eyeball. Index predicates and enum label sets are exactly what human review of a 500-line hand-written DDL file misses. D-13 puts these tests in a new `tests/schema/` package with zero imports from `nativespeaker.api`, because `tests/e2e/conftest.py` imports the application and runs its lifespan, and pytest applies that conftest to every subdirectory beneath it — so nothing under `tests/e2e/` can run while the application is knowingly broken.

Output: `tests/schema/` with its package marker, fixtures, seed helpers, apply/rollback proof, and exact-set inventory suite; a registered `schema` pytest marker; and a captured PostgreSQL 17 inventory record.

**`tests/schema/__init__.py`.** An empty file, exactly like `tests/unit/__init__.py` and `tests/e2e/__init__.py`. That is why cross-module test imports in this repository read `from e2e.conftest import …` and `from unit.conftest import …`, and why the schema modules will import `from schema.helpers import …` rather than `from tests.schema.helpers import …`. A session-scoped `_schema_db_uri` fixture (D-14) drops and recreates the scratch database (`DROP DATABASE IF EXISTS … WITH (FORCE)`, then `CREATE DATABASE …`), connects to it, applies the migration in-process, yields the URI, and drops the database again on teardown. Make this fixture **synchronous** and wrap the one-shot setup and teardown in `asyncio.run()`. The reason is specific: `pyproject.toml` sets `asyncio_mode = "auto"` with `asyncio_default_fixture_loop_scope = "function"`, so a session-scoped *async* fixture would return objects bound to a loop the tests do not run in. The synchronous-plus-`asyncio.run` shape sidesteps that entirely and needs no `loop_scope=` marker anywhere — unlike `tests/e2e/conftest.py`, which carries `loop_scope=` on every async fixture.

Do not shell out to `subprocess.run(["pogo","apply"])` and do not write your own statement splitter — the in-process call exercises the same parser production uses, needs no environment at all, and raises a real exception on failure.
