<objective>
Convert `resilience.py:145-191`'s hand-rolled attempt loop to the same `tenacity` policy 37-02 introduced (D-05), so the codebase carries one retry idiom rather than two.

Purpose: D-04 replaced `BudgetGate` with `tenacity`. Leaving a second, hand-written loop next to it is the two-answers-to-one-question shape Phase 36 removed when it retired `RejectionCounter` (commit 5f275c8). The developer chose this over the narrower BudgetGate-only option.

Output: one converted `ainvoke`, one new characterization test file, and one revertible commit.

**37-CONTEXT.md D-05 calls this the highest-risk item in the phase, and it is not on the phase's critical path.** That loop sits on `POST /chats`, the product's primary route, which Phase 37 otherwise never touches. It carries three non-obvious behaviors a naive conversion will drop:

1. **`on_admitted` fires at most once across every attempt** (`resilience.py:149-161`). The `admit_once` wrapper exists specifically so a retry cannot re-invoke it — a second fire charges a second credit for one request. The flag is set **before** the await, deliberately: a callback that raises has still had its one chance.
2. **`_is_transient_error` gates whether a retry happens at all** (`:184-187`). A permanent error must raise `PermanentLLMError` on the first failure, not after three provider calls.
3. **`record_failure` must fire on provider failures but NOT on the non-provider path at `:175-179`** — `_AdmissionRejected` is the caller's own callback failing, not the provider, so it must not open the circuit breaker.

**Treat the existing behavior as the specification.** Convert under the existing tests; `tests/unit/test_services.py` must stay green **unchanged** — it pins the once-only `on_admitted` contract and is this conversion's primary oracle. Give this its own plan and its own commit so it can be reverted without touching the endpoint. — **Reversibility:** reversible.
</objective>

Replace the `for attempt in range(1, self._retry_max_attempts + 1)` loop in `ResiliencePolicy.ainvoke` with a `tenacity.AsyncRetrying` policy configured to reproduce the existing behavior exactly:

- `stop=stop_after_attempt(self._retry_max_attempts)`
- `wait=wait_exponential(multiplier=self._retry_backoff_base, exp_base=2, max=self._retry_backoff_max)` — verify against Task 1's recorded sleep durations that this yields the same schedule the hand-rolled `min(self._retry_backoff_max, self._retry_backoff_base * (2 ** (attempt - 1)))` produced. If tenacity's parameterization does not reproduce it exactly, use `wait_exponential`'s arguments that do, or a small custom wait callable — matching the observed schedule is the requirement, not using a particular built-in.
- `retry=retry_if_exception(<predicate>)` where the predicate is true only for exceptions that are neither `_AdmissionRejected` nor `QueueFullError` nor `CircuitOpenError` **and** satisfy `_is_transient_error`. Note this is `retry_if_exception`, not `retry_if_result` — unlike `auth/retry.py`, this seam signals through raised exceptions, so the two idioms differ in predicate while sharing the library. Say so in a comment; a reader comparing the two files will otherwise assume one of them is wrong.
- `reraise=True`, which is correct here precisely because there **is** an original exception (the opposite of `auth/retry.py`'s situation — cross-reference it in the comment).

Preserve the three non-obvious behaviors literally:

1. Keep the `admitted` flag and the `admit_once` wrapper exactly as they are, defined **outside** the retrying construct so one flag spans every attempt. Keep the "set BEFORE awaiting" ordering and its comment verbatim — a callback that raises has still had its one chance.
2. Keep `await self._circuit_breaker.before_call()` at the head of each attempt and `await self._circuit_breaker.record_success()` after a successful call.
3. Keep the exception triage in the same order and with the same consequences: `_AdmissionRejected` re-raises `rejected.cause` `from None` with **no** `record_failure`, no retry, and no `TransientLLMError` wrapping; `QueueFullError` and `CircuitOpenError` propagate unwrapped with no `record_failure` and no retry; every other exception calls `await self._circuit_breaker.record_failure()` exactly once, then either retries (transient, attempts remaining) or raises `TransientLLMError` / `PermanentLLMError` according to `_is_transient_error`.

The trap to design around: tenacity's retry predicate runs *after* the attempt body returns, so the `record_failure` call and the `TransientLLMError` / `PermanentLLMError` translation must stay inside the attempt body's own `try`/`except`, not be moved into a `retry_error_callback`. Re-raise from the body so the predicate sees the right exception, and let `reraise=True` deliver the final one.

Delete the trailing `raise TransientLLMError("LLM request failed after all retries")` at the end of the old loop only if `reraise=True` provably covers it; if the converted control flow can still fall through, keep an equivalent guard rather than leaving an implicit `None` return.

Do not change `_is_transient_error`, `_extract_status_code`, `CircuitBreaker`, `LLMExecutionGate`, `_AdmissionRejected`, or `ResilienceConfig`. The conversion is confined to `ainvoke`'s body.
