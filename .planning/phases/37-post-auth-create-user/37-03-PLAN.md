  <action>
Add a `FirebaseConfig(BaseModel)` to `src/nativespeaker/api/config.py` with a single field, `service_account_json: SecretStr | None = Field(default=None)`, and a method that parses it into a dict for `credentials.Certificate` — parse **once**, at configuration time, so a malformed credential is a boot-time failure rather than a first-completion 503. A `json.JSONDecodeError` must be re-raised as a `ValueError` whose message names the field and does NOT include the parsed text; `BaseConfig` already sets `hide_input_in_errors=True`, which covers pydantic's own rendering, and the hand-written path must not undo it.

Declare it on `AppConfig` as `firebase: FirebaseConfig = Field(default_factory=FirebaseConfig)` — defaulted, not required, because the credential is genuinely absent today (RESEARCH § Environment Availability verified: no `service_account` or `private_key_id` string exists under `config/` or in `.env`) and every non-completion path in the phase must stay runnable without it.

**Do NOT add a `firebase:` block to `config/config.yaml`.** Pitfall 7: the YAML is authoritative for anything it declares — `AppConfig` is built as `AppConfig(**yaml_data, ...)` and pydantic-settings ranks `init_settings` above `env_settings` — so a block added there to "document the shape" would make the `.env` value permanently unreachable AND put real key material in a tracked file, defeating D-08 entirely. The env path works through `BaseConfig`'s existing nesting rule (`env_nested_delimiter="_"`, `env_nested_max_split=1`), the same rule by which `JWT_PROJECT_ID` reaches `jwt.project_id`.

Add `FIREBASE_SERVICE_ACCOUNT_JSON=...` to `.env.example` under a comment saying: the whole service-account JSON on one line; obtained from the Firebase console; required only for completion-mode requests; and never committed. Note that `.env.example` is where the shape is documented — that is the file Pitfall 7 permits.

Record explicitly, in a comment on `FirebaseConfig` and in the SUMMARY, the absent-vs-malformed split this plan decides: **absent** is a supported state (the service boots, prepare mode and every substituted test run, and every completion fails closed at the adapter's `selection_failure` arm → 503 `verification_temporarily_unavailable`); **present but unparseable** raises at configuration load and the service does not boot. The alternative — refusing to boot without a credential — would block prepare mode, the mode-signal partition, the classifier, and every substituted-adapter test, all of which the phase deliberately keeps unblocked.

Extend `tests/unit/test_config.py` with the four behaviors above, using `monkeypatch.setenv` / `delenv`. Also assert that the parsed `config/config.yaml` has no `firebase` key — that assertion is the standing guard against Pitfall 7, and it belongs with the config tests, not with a reviewer's memory.
