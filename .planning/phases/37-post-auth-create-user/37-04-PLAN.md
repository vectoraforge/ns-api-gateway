<objective>
Write the Python mirror of `core.subscription_provider` and the SQLModel class for `core.store_purchase_tokens` — and **prove RESEARCH assumption A2 against the real database before any handler depends on it.**

Purpose: CREATE-03 requires the create transaction to mint both purchase-attribution tokens. RESEARCH found there is nothing to insert with: `core.store_purchase_tokens` has **no SQLModel class at all**, and `core.subscription_provider` has **no Python mirror** — `models/__init__.py`'s `__all__` lists 27 names and neither is among them. The table is also deliberately PK-less (`migrations/20260818_01_initial-release.sql:327-338`), so the naive `class StorePurchaseToken(SQLModel, table=True)` fails at **import** with SQLAlchemy's "could not assemble any primary key columns".

**A2 is the phase's highest-risk unverified assumption** (RESEARCH: "the likeliest thing to be discovered mid-execution"): that SQLAlchemy accepts an ORM-level composite primary key on a table whose database definition has none, and INSERTs correctly. It follows from SQLAlchemy's mapper contract — a mapper needs an identity key, not a DDL constraint — but was **not executed against this specific model**. This plan executes it. If it fails, the fallback is a Core `insert()` against a `Table` object rather than a mapped class, and that discovery belongs here, before the tracer is written.

Output: the two symbols, exported from `nativespeaker.api.models`, with a schema test that commits real rows through the ORM.
</objective>

Do NOT add a default factory for `identity_value` or `created_at`. The creating transaction supplies both — `created_at` from the request's single captured `RequestContext.evaluated_at` (35 D-02: never recompute it), and `identity_value` from a fresh `uuid4()` per row. A model-level default would put a second clock and a second RNG on a path that must have exactly one of each.
