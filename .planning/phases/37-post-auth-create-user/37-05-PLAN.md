<objective>
Build the codebase's first concrete provider adapter — the issuer-selected Firebase Admin integration behind foundation's `§7.1` seam — and §02 step 9's closed providerData classifier.

Purpose: `firebase-admin>=7.3.0` is declared at `pyproject.toml:24` and imported **nowhere** in `src/`. Phase 35 removed the last Firebase client at boot (`app/lifespan.py:66-69`) and this phase reintroduces Firebase — behind the seam, never as an ambient startup client.

Output: `auth/firebase.py` (the adapter and the boot-time app builder) and `auth/classifier.py` (the closed classifier), both unit-tested without a network and without a credential.

**Under D-12 the classifier does one job only.** RESEARCH described `auth/classifier.py` as owning the classification *plus* the declaration match *plus* `required_flow` derivation; D-12 deletes the client flow declaration, so the declaration match (§02 step 9's second half) and `required_flow` do not exist. The closed classifier itself is unchanged. A rejecting shape is an unclassifiable **account**, not a declaration mismatch, and routes to `operation_not_allowed` via the invalid-shape `provider_not_linked` cause. `provider_not_linked`'s bounded cause therefore loses `supported-provider-mismatch`; `empty` and `invalid-shape` remain.
</objective>

Keep the empty-uid guard even though the SDK raises first on that shape (Pitfall 3, handled in Task 2): the classifier is also driven by substituted adapters in tests and by phases 40/41/42 later, and it must not depend on an upstream raise for a correctness rule of its own.

Create `src/nativespeaker/api/auth/firebase.py` holding a boot-time app builder and the adapter class. It must live **outside** `auth/adapters.py` (`tests/unit/test_adapter_interfaces.py` fails the moment an implementation appears there).

`build_admin_apps(config) -> dict[str, firebase_admin.App]`: when `config.firebase.service_account_json` is present, parse it once (37-03's `FirebaseConfig` already did the parse and the validation, so read the parsed dict rather than re-parsing), build `credentials.Certificate(<dict>)`, and call `firebase_admin.initialize_app(cert, {"projectId": config.jwt.project_id, "httpTimeout": FIREBASE_HTTP_TIMEOUT_SECONDS}, name=f"issuer:{config.jwt.issuer}")`, returning `{config.jwt.issuer: app}`. When it is absent, return `{}` and emit one structlog warning naming the consequence in plain terms — completion mode will fail closed as `verification_temporarily_unavailable` until the credential is set. Declare `FIREBASE_HTTP_TIMEOUT_SECONDS = 8` as a module constant with a comment citing `adapters.py:16-17`'s fixed 5-10 s per-attempt requirement and noting that `httpTimeout` is an **app-level** option because this SDK exposes no per-call timeout (RESEARCH A5: not separately measured; a slow test is the detector).

**Never call `firebase_admin.initialize_app()` with no credential, and never create a `[DEFAULT]` app at all.** ADC would silently pick up the developer's local gcloud user credentials, which SHARED-INVARIANTS § Wire contract forbids ("No ambient, default, global, or fallback client exists") and D-08 rejects explicitly. Not creating a `[DEFAULT]` app is what makes a call site that forgets `app=` fail loudly instead of falling back.

The adapter class takes the app mapping at construction and exposes `async def get_user_provider_data(self, issuer: str, subject: str) -> ProviderDataResult`. It looks the app up by exact issuer match; a miss returns `ProviderDataResult(ProviderDataOutcome.selection_failure)` with no call — selection fails closed and never falls back to another project. On a hit it awaits `run_in_threadpool(<sync reader>, app, subject)`, matching the house rule plan 35-12 pinned: any synchronous call on the request path that can perform I/O is awaited through `starlette.concurrency.run_in_threadpool`, never called inline.

The sync reader is the load-bearing part. Inside it, call `auth.get_user(subject, app=app)` and **materialize** `record.provider_data` into a `tuple[ProviderDataEntry, ...]` right there, in the same `try`. `provider_data` is a *lazy property* that constructs `ProviderUserInfo`, whose `__init__` raises `ValueError('User ID must not be None or empty.')` on an empty `rawId` — so if it is first touched after the threadpool returns, the exception escapes the tenacity policy entirely and becomes an unhandled 500 (Pitfall 3). Map `auth.UserNotFoundError` → `user_not_found` (definitive, non-retryable, spends no attempts — `adapters.py:52-54`), `ValueError` → `retryable_failure` (§02 step 8 classifies a malformed or indeterminate response as retryable), and `exceptions.FirebaseError` → `retryable_failure` (outage or integration-auth failure). Return foundation's own frozen `ProviderDataEntry(provider_id=..., uid=...)` dataclasses, never the SDK objects. Log the provider's diagnostic text; **never attach it to the returned result** (`adapters.py:19-20`).

**A decision to record, not discover.** `FirebaseAdminAdapter` declares three methods; this class implements only `get_user_provider_data`. `verify_id_token` is not implemented — the barrier's JWKS-backed `TokenVerifier` is the service's only verification path and §02's hardenings forbid a handler re-implementing verification, so an implementation here would be unreachable structure of exactly the kind D-03 refuses. `revoke_refresh_tokens` is not implemented — §7.1 assigns the revocation adapter, its retry budget, and any in-flight coalescing to the sign-out-all phase (Phase 46), and building it here would be building another phase's adapter. The Protocol is structural and not `@runtime_checkable`, so nothing breaks at runtime; do **not** annotate this class as `FirebaseAdminAdapter` anywhere, since it does not satisfy the full Protocol. Note this diverges from RESEARCH open question 3's recommendation, cite D-03's precedent as the reason, and carry it into the SUMMARY as a flagged assumption for Phase 46. — **Reversibility:** reversible.

Tests in `tests/unit/test_firebase_adapter.py` cover the eight behaviors above with `firebase_admin.auth.get_user` monkeypatched — no network, no credential, no real app. Add one case asserting `build_admin_apps` with an absent credential returns `{}` and that `firebase_admin._apps` (or `firebase_admin.get_app()`) has no `[DEFAULT]` entry afterwards.
