# Phase 37.4 Plan 04: The quota seam Summary

`QuotaGate` is a module-level `charge_quota()` called on one visible line in each of `create_chat`
and `send_message`, and the admission-callback thread is gone from three modules — with 429-not-503
now holding structurally rather than by a wrapper, because the charge never enters the retry loop.

## The four line numbers the charge sits between

`src/nativespeaker/api/services/chats.py`, at HEAD:

| Method | Last validation raise | Charge | Provider call |
|---|---|---|---|
| `create_chat` | `:82` unsupported language, `:86` chats limit | **`:93`** | `:94` `await self.ask_llm(...)` |
| `send_message` | `:108` chat not found, `:111` messages limit | **`:117`** | `:118` `await self.ask_llm(...)` |

In each method the charge line is greater than every validation raise in that method and less than
the provider call. No validation moved, no method was added, and there is no second charge site:
`rg -c "charge_quota" src/nativespeaker/api/services/chats.py` reports exactly **3** — one import and
two call sites.

## The security-sensitive substitution, and how it was checked

This plan deletes the wrapper that kept a quota 429 from reading as a provider 503, and replaces it
with a structural argument. A green suite is not evidence that a structural argument holds, so the
new file was negative-controlled twice, out of tree, against the real `ChatService`:

| Probe | Change | Result |
|---|---|---|
| Charge hoisted above every validation in `create_chat` | 1 line moved | **5 failed, 9 passed** — three "not charged" cases plus both session-ordering cases named it |
| Charge moved after `await self.ask_llm(...)` | 1 line moved | **3 failed, 11 passed** — `test_the_llm_service_records_zero_calls` and both session-ordering cases named it |

Both probes were reverted with `git checkout -- src/nativespeaker/api/services/chats.py`. The four
zero-charge assertions are additionally guarded by two positive controls
(`test_the_admitted_path_is_charged_exactly_once` and its follow-up twin), so the zeros cannot be a
stand-in that never fires.

## Reading the diff for guards whose meaning changed

The prior wave's warning — that two live auth bugs this phase were mechanical edits which left the
suite fully green — was applied to this diff. Two guards disappeared here; both were checked against
the real wiring rather than against the test result:

1. **`get_quota_gate`'s `if identity.user is None: raise AuthenticationError`.** Its own comment
   called it unreachable. Confirmed: `chats.py`, `examples.py` and `root.py` each declare
   `Depends(get_linked_identity)` at router level *and* on every endpoint, and
   `TestEveryRouteIsAuthenticated` (a live structural check, negative-controlled in plan 37.4-03)
   passes. Deleting it widens nothing.
2. **`get_chat_service`'s `identity: Identity = Depends(get_identity)`.** This mattered: if any route
   reached authentication only through `get_chat_service`, removing the parameter would silently
   deauthenticate it. Every route that declares `get_chat_service` — all eight — also declares
   `get_linked_identity` at two levels. Verified by reading all three routers, not by the suite.

A third semantic shift worth recording: **`ask_llm` is no longer a charging path.** The charge used
to ride inside it as the admission callback, so any caller of `ask_llm` was billed; now only
`create_chat` and `send_message` charge. `ask_llm` has exactly those two call sites, so nothing is
served free today — but it is a public method whose billing property changed, and a future third
caller would not be charged.

## The accepted regression, restated as sanctioned behaviour

**Queue-full (429) and circuit-open (503) are now billable.** The charge precedes both, where the old
callback fired only after a slot and the semaphore were held. D-07 sanctions this explicitly; it is
not a defect and must not be "fixed".

It is asserted as expected behaviour in `tests/unit/test_quota_seam.py::TestTheAcceptedRegression`:
an open breaker answers `CircuitOpenError` *after* the charge has opened, committed and closed its
session, and `usage.monthly_used == 1`. A second case asserts the charge is not refunded when the
provider call fails, which is the module docstring's claim.

**Where it is not asserted, and why.** `tests/e2e/test_quota.py::test_an_open_circuit_is_not_charged`
was the stale expectation of the old ordering. It could not simply be inverted: `_db_transaction`
binds one connection and gives every session `join_transaction_mode="create_savepoint"`, so
`charge_quota`'s commit is a released savepoint nested inside `get_db`'s, and `get_db`'s rollback on
the handler's exception discards it. The e2e counter therefore reads 0 — an artifact of the harness,
not of production, where `async_sessionmaker(bind=db_engine)` gives the charge its own connection and
its own top-level transaction. The e2e case was rewritten as
`TestAnOpenCircuitStillAnswers503`, keeping the 503 assertion and stating in its docstring why the
counter is deliberately not read and where the credit *is* asserted. No assertion was weakened to
make the suite pass; the claim was moved to the only level that can carry it.

## Deviations from plan

### 1. [Rule 3 — blocking] The task boundaries could not be commit-atomic as written

Each task's `<verify>` runs the suite, and the plan's file lists cross that boundary in two places:

- **Task 1** deletes `QuotaGate`, but `services/chats.py` imports it and `tests/unit/conftest.py`
  constructs a `ChatService` with it, so `python -c "import nativespeaker.api.app.main"` — a Task 1
  acceptance criterion — fails unless both move in the same commit. `tests/unit/test_quota_resolver.py`
  likewise passes `route=` at eight sites, so Task 1's own `<verify>` fails without it. All three were
  absorbed into commit 1.
- **Task 2** deletes the `on_admitted` parameter, and `tests/unit/test_resilience_retry.py` (a Task 3
  file) passes it at roughly twenty sites. It was pruned in commit 2.

Same shape as plan 37.4-03's deviation 1. Every commit is green on its own.

### 2. [Rule 1 — bug in my own draft] A helper method was added, which A-03 forbids

The first draft of `services/chats.py` wrapped the charge in `ChatService._charge(...)`. A-03's
stated property is that option A2 adds **zero** methods, and the plan says "Do not add a method."
Caught by re-reading the acceptance criterion (`charge_quota` must appear exactly 3 times), not by a
test — the suite was green with the helper. Both call sites now call `charge_quota` inline.

### 3. The resilience suite lost its only assertion on `ainvoke`'s return value

`TestOnAdmittedFiresAtMostOnce` was deleted whole, as instructed. Two of its six cases
(`test_fires_once_when_the_first_attempt_succeeds` and `test_no_callback_is_a_supported_call`) were
the only places asserting that a successful `ainvoke` returns the operation's value. Rather than let
that lapse silently, `test_a_successful_call_returns_the_operations_value` was added to
`TestFailureAccounting`, carrying every non-callback assertion from the first of them. Net unit count:
853 → 864.

### 4. Two `admit.calls == 0` assertions removed with a reversed subject

`TestGateAndBreakerErrorsAreNeverWrapped` asserted "refused before admission, so nothing is charged"
for queue-full and circuit-open. That property is exactly what D-07's accepted regression reverses,
so the assertions were removed rather than carried; the surviving `operation.calls == 0` and breaker
assertions in both cases are untouched.

## D-15 — stranded symbols

**One question outstanding.**

**`AuthenticationError` (`src/nativespeaker/api/errors.py:269`) now has no production raise site.**
At the plan base, `get_quota_gate` held the only one in `src`. It is still referenced by
`tests/unit/test_exception_handlers.py` as the 401 mapping fixture, and it is a member of D-08's
tree that `assert_tree_total()` walks at startup. **Not deleted:** `errors.py` is plan 37.4-02's
artifact, this plan claims exclusive ownership only of `quota.py`, and a generic 401 with no current
raiser is plausibly intentional. Flagged for the phase owner rather than removed.

Everything else the plan names as deleted was deleted, and nothing else was found stranded:
`QuotaGate`, `get_quota_gate`, `_AdmissionRejected`, the `on_admitted` closure and every
`on_admitted` parameter, `admit_once`, and the `route` parameter on `consume_quota`. The `ROUTE`
constant in `tests/unit/test_quota_resolver.py` was orphaned by the signature change and removed in
the same commit. Three stale prose references to deleted machinery were repaired: two `_StubSession`
docstrings naming a `require_quota` that has not existed for some time (in
`tests/unit/test_quota_resolver.py` and `tests/e2e/test_quota.py`), and
`tests/e2e/test_quota.py`'s "the quota dependency must declare chat_id as well as body", which
described a route dependency this plan deletes.
