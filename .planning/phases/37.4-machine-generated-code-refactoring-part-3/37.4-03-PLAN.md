<objective>
Collapse the identity union into one class and one accessor pair (D-01, D-02), retire `RequestContext`
field by field (D-03), and finish D-13's module folding by merging `auth/context.py` and
`auth/resolve_identity.py` into `auth/identity.py`.

Purpose: this is the phase's most security-sensitive change, because it **removes a type-level
guarantee**. Today `LinkedIdentity` and `PreAuthIdentity` make "read an unlinked identity as linked"
unrepresentable. After this plan the only thing standing between a handler and that mistake is the
router-level `Depends(get_linked_identity)` declaration and the wiring test that enforces it. That
substitution is deliberate (D-02 says so in as many words) and the replacement control must land in
the same commit as the removal, never after it.

Output: `auth/identity.py` holding `Identity` and `resolve_identity`; `app/dependencies.py` with
`get_identity` / `get_linked_identity`; four routers and the challenge store reading nullable fields;
the two identity test files rebuilt on one class.

becomes `get_identity()`, `evaluated_at` is generated at the start of each endpoint that needs it,
and `route` is deleted and not re-derived. The fourth, `attempt_id`, becomes a **local** in
`routers/auth.py` and dies in plan `37.4-05` together with the `claim_attempt_id` column and the
lifecycle CHECK conjunct that requires it. Removing it here would leave the store writing NULL into a

scope reduction: nothing about `attempt_id` survives the phase.

**Discretion exercised (CONTEXT.md delegates the `Identity` class's shape and field names, and whether
`get_linked_identity` returns the same class or a narrowed view):**

1. **`Identity` is a frozen slotted dataclass with four fields** — `issuer: str`, `subject: str`,
   `user: User | None = None`, `identity: ExternalIdentity | None = None` — copying the decorator and
   field register of the class it replaces. Both object fields default to `None` so an unlinked
   identity constructs with two arguments.
2. **It carries the `ExternalIdentity` row, not just the `User`.** This is not a style choice: the
   challenge binding keys on `bound_external_identity_id`, so the row's id must be reachable from the
   identity the store is handed. CONTEXT.md D-01 states this and it is load-bearing.
3. **`get_linked_identity` returns the same class, narrowed by a runtime check** — not a second type.
   A second type is exactly what D-01 deletes. The narrowing is a raise, and the type checker gets no
   help; that is the accepted cost, and the router-level declaration is the compensating control.
4. **The trailing per-field explanatory comments die with D-12.** The class carries a three-line
   docstring and no field comments. The two comments inside `resolve_identity` — the one explaining
   the outer join and the one explaining why the state tests are positive — both clear D-12's bar and
   are kept.

**37.3-REVIEW dispositions, fix-in-place:** WR-02 (`verify_binding` is a bare statement, turning a
fail-closed call site into a fail-open one) sits in `crud/challenges.py` lines this plan rewrites — fix
it in place by making the call site's result load-bearing, and say so in the SUMMARY. WR-01, WR-06,
WR-07 and WR-08 sit in `routers/auth.py` / `create_user.py` lines that plan `37.4-06` rewrites; leave
