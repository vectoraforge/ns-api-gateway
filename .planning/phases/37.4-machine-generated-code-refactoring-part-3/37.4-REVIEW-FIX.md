#### WR-01: `missing_token` reported for callers that did present an `Authorization` header

**Files modified:** `src/nativespeaker/api/app/dependencies.py`, `tests/unit/test_auth_security.py`,
`tests/unit/test_identity_accessors.py`
**Commit:** `0efa869`
**Applied fix:** `get_identity` now reads the raw `authorization` field when `HTTPBearer` answers

`missing_token` only when none was. This is the classification
`specs/auth-refactor-phases/01-foundation.md:47-48` states normatively (non-Bearer scheme →
`malformed`; empty token after the scheme → `malformed`; `:44` zero field values → `missing_token`).

`missing_token`, so the wrong `WWW-Authenticate` half is corrected by the same change with no edit

defect itself. It is now `test_an_unusable_authorization_field_names_the_error` and asserts
`Bearer error="invalid_token"` for the same four shapes. Three cases were added to the bounded-reason
parametrize in `test_identity_accessors.py` (wrong scheme, empty credential, unparsable field).

**Decision-record note:** A-04 (`37.4-CONTEXT.md`) directed that `missing_token`, `malformed` and

#### WR-22: a present-but-unusable DeviceCheck key 500s every anonymous-grant claim
