**Discretion exercised here, recorded so later plans do not re-litigate it** (CONTEXT.md
"Claude's Discretion" delegates the mechanism for D-08's startup check and the status/code
declaration shape):

1. **Status and code are two class attributes on one base**, `status: int = 500` and
   `code: ErrorCode = "internal_error"`, per RESEARCH.md §B. This *loses* a property `ErrorClass`
   had — a frozen pair could never name a status and a code in disagreement, and two attributes can.
   The replacement control is mandatory and is in Task 1: the startup walk asserts
   `("status" in vars(cls)) == ("code" in vars(cls))` for every class. Without it, D-08 would remove
   a fail-closed control silently.
2. **The `ErrorCode` Literal stays.** It is what makes a code typo a construction-time error rather
   than a runtime 500, and `test_error_contract.py` asserts the OpenAPI body's `code` is an enum.
3. **The totality check is the `__subclasses__()` walk already written and already
   negative-controlled in `tests/unit/test_rejection_vocabulary.py`, promoted into `errors.py`** —
   not a new walk, and not an explicit list (an explicit list is `REGISTRY` renamed). The lazy-import
   hazard does not apply: A-01 puts every class in one module, and `app/main.py` imports that module
   at load time, before the `FastAPI()` object exists.
4. **`STATUS_TO_CLASS` is replaced by a class-attribute marker**, `answers_framework_status: bool`,
   with the walk building the status map at check time and asserting exactly one class per status.
   RESEARCH.md assumption A4 flags the risk that the developer reads any class attribute as
   "a registry"; the distinguishing property is that nothing is *stored* — the map exists only inside
   the check.
5. **`log_level` defaults to `logging.WARNING` on the base**, with `None` where silence is deliberate
   (`TransientLLMError`, `PermanentLLMError`) and `logging.ERROR` where a traceback is owed. This
   preserves both existing behaviours with the fewest declarations. Today service errors log only when
   `log_level is not None` while every rejection logs unconditionally at WARNING; the merge must not
   silently make the LLM classes chatty or the rejections quiet.
6. **"One handler" cannot be literal.** `StarletteHTTPException` and `RequestValidationError` are
   framework types outside the tree, so the achievable reduction is five registrations to four. The
   two framework adapters construct the tree's own exception and delegate, so exactly **one function**
   builds a response body. Stated here so nobody later tries to force it to one registration.
