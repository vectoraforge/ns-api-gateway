Collapse the create-user conflict path (D-06, A-07) and replace the hand-rolled bearer extractor with
the framework's (D-10, A-04, A-05).

Purpose: two more instances of the same pattern — machinery whose justification fails re-examination.

Output: one insert function with no savepoint and one already-linked answer for any conflict; a
`Depends()`-declared `HTTPBearer(auto_error=False)`; `BoundedReason` living with the verifier that
still produces five of its members; and four test files pruned or deleted with exactly one sanctioned
status move.

**What D-06 gives up, restated so it is not rediscovered as a bug.** The unmapped-constraint 500
tripwire dies. A constraint rename or a new constraint will read as a benign 409 rather than
surfacing. This was 37.3 D-03's explicitly preserved fail-loudly property and 37.3-REVIEW WR-12's
subject; it is knowingly given up. And the provider-account distinction collapses onto the
already-linked answer — flagged against `02-create-user.md`'s completion step 11, whose
provider-account conflict earns `operation_not_allowed`. Only the **race** path loses the distinction; the pre-check keeps it.

**What D-10 gives up, restated.** Duplicate `Authorization` field instances stop being a distinct
rejection, because the framework reads the header through a mapping that returns the first value and
hides the rest — the resolution `SHARED-INVARIANTS.md:18` forbids by name. Comma-joined and
line-folded values stop being distinctly rejected and degrade to a signature failure. And per A-09 the
framework's scheme/param split strips the parameter, so a value with padding around the token is now
accepted where the extractor rejected it as malformed — a *loosening* of the same invariant, from a
different cause, recorded as its own flagged conflict by plan `37.4-07`.

**A-05 corrects D-10's premise.** The installed FastAPI's bearer base already answers 401 with a
`WWW-Authenticate: Bearer` header, not the 403 D-10 anticipated. D-10's bullet requiring a re-map is
**withdrawn as factually wrong**. Do not write one. Use `auto_error=False` so our own code raises the
rejection and the log event survives.

**Line numbers:** every `file:line` in RESEARCH.md and PATTERNS.md predates plans `37.4-01` through
`37.4-05`. Re-verify line numbers by reading; the facts are sound.

   its own exception and our `invalid_external_jwt` log event never fires. With it off, a missing or
   malformed credential yields `None` and our own code raises `InvalidExternalJwt`, keeping the event,
   the code and the header behaviour exactly as they are today.
2. **`BoundedReason` moves to `jwt_verifier.py`**, the module that produces five of its members and the
   only module that will still reference it after this plan. It is not moved to `errors.py`: the
   verifier owns the vocabulary, and `errors.py` merely types a field on one class.
3. **`ProviderAccountAlreadyLinked` is deleted, not kept unraised (A-07).** D-06 removes its only raise
   site, so under D-04's rule — a distinction is fine as long as an exception carries it — the class
   now carries nothing. Its code survives on the class that still raises it, so no code drops out of
   the vocabulary and the totality walk stays satisfied.
