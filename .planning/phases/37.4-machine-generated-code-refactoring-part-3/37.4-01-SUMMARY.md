## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] `POST /auth/create-user` raised `TypeError` on every claimed challenge**

- **Found during:** Task 1, while resolving a `monkeypatch` target that named a non-existent attribute.
- **Issue:** `d466a4b` renamed the account-creation helper `create_account` → `create_user`. In `routers/auth.py` that name **already belonged to the route handler** at line 68. The handler's `def` executes after the line-15 import, so the module attribute `create_user` bound to the route, and `_complete()` at line 128 called the **route handler** with keyword arguments it does not accept (`context=`, `challenge=`, `provider=`, …). Every request that got past the challenge claim would raise `TypeError`. Confirmed empirically, not by reading:
  ```
  routers.auth.create_user -> nativespeaker.api.routers.auth  (the route)
  helper create_user       -> nativespeaker.api.auth.create_user
  SHADOWED: True
  ```
- **Fix:** Imported the helper as `create_account` and updated the one call site.
- **Files modified:** `src/nativespeaker/api/routers/auth.py`
- **Verification:** `routers.auth.create_account is helper.create_user` → `True`; the 26 previously erroring `test_create_user_precedence.py` cases now pass.
- **Committed in:** `9e9e273`

**Note on the plan's "changes no behaviour" prohibition.** This fix does change behaviour — from crashing to working. The prohibition assumed `d466a4b` left only *stale references*; it left a *live collision* as well. The plan's own gate (`pytest -q` exits 0) cannot be met without fixing it. Flagging it here because it is the most consequential finding of this plan and deserves a reviewer's eye.

### Which markers were skipped, and why — none

`pytest -q -m ""` ran all 1102 tests with **nothing skipped**. Both credential-gated layers really executed:

- **`schema`** connected to a real local PostgreSQL and applied the migrations to a scratch database. `tests/schema/conftest.py:21-27` carries explicit `DB_*` defaults (`localhost:5432`, `postgres`/`postgres`) so the suite runs with `DB_*` unset.
- **`e2e`** ran in-process over `ASGITransport` with `FakeFirebaseAdapter`, and reached a real provider for `test_llm_schema.py`.

**Worth knowing for every worktree-run wave:** the worktree has no `.env`, but `pytest-dotenv` resolves it by walking *up* the directory tree and loads the **parent checkout's** file:

```
$ .venv/bin/python -c "from dotenv import find_dotenv; print(find_dotenv())"
/home/init/native-speaker/ns-api-gateway/.env
```

So credentials reach worktree runs from outside the worktree. That is why the `OPENAI_API_KEY` skip guard at `tests/e2e/test_llm_schema.py:35-40` did not fire. Downstream executors should not assume a worktree is credential-isolated.
