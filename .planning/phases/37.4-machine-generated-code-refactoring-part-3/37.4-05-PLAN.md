**Schema push gate: `[BLOCKING]` and satisfied by task 05-T3.** This phase edits
`migrations/20260818_01_initial-release.sql` in place twice. The established v2.0 pattern is an
in-place edit of the single initial migration with the disposable dev/test database re-applied, never
an incremental migration. Note RESEARCH.md Pitfall 8: the schema suite creates and applies its own
scratch database per session, so it picks up a migration edit with no manual step; the **e2e** suite
runs against the developer's dev database and does not. A green schema suite therefore does not imply
the dev database matches the file. Without 05-T3, unit tests and typechecks would pass against a stale
database and produce a false-positive verification state.

**Discretion exercised:**

1. **The lifecycle CHECK is rewritten, not trimmed.** Dropping the column leaves the first arm
   `(claimed_at IS NULL AND consumed_at IS NULL)` and the second arm `(claimed_at IS NOT NULL)`,
   which together are a tautology. The rewritten constraint expresses the surviving rule — consumed
   implies claimed — and a schema test proves it still rejects a violating row. The in-repo precedent
   for rewriting the whole CHECK rather than removing a conjunct is commit `cf6b44f`, which performed
   this exact operation on this exact table.
2. **A-08's timing loss is accepted, not mitigated.** The keyring's comparison went through a
   constant-time digest compare; the plaintext replacement is a plain inequality. The compared value
   is a Firebase uid that an attacker holding the token already knows, and the same value is stored
   permanently in plaintext one table over. No constant-time comparison is reintroduced — doing so
   would be exactly the disproportionate machinery this phase removes.
3. **A-06 reading (a).** `tests/schema/test_inventory.py` is genuinely untouched: it asserts no column
   of this table and no CHECK-constraint name, and neither edit changes an index, a constraint name,
   an enum or a table name. `test_constraints.py` gets mechanical edits only.
   `test_create_atomicity.py` and `test_create_race.py` are ordinary collateral — they construct
   application types — and get A-02's prune treatment.
