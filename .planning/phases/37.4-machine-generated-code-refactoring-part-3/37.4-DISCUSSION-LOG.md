# Phase 37.4: Discussion Log

**Date:** 2026-08-29
**Human reference only** — not consumed by the researcher, planner, or executor.

## Opening state

Phase 37.4's roadmap goal was the placeholder `[Urgent work - to be planned]`
(`ROADMAP.md:397`), Requirements `TBD`. Three candidate domains were scouted and
presented — closing out 37.3's 20 unaddressed review findings, de-complicating the
13,612-line test suite against 3,309 lines of source, or collapsing the two error
trees. The developer dismissed the question and supplied three directives directly,
which became the phase.

## Directives as given

1. Delete `LinkedIdentity`/`PreAuthIdentity` and `get_linked_identity()`; normal routes
   use `get_current_user`.
2. Delete `RequestContext` — `identity` becomes an accessor call, `resolved_at` becomes
   a `now()` at endpoint start, `attempt_id` leaves entirely ("nothing anywhere un-claims
   a challenge"), `route` is redundant with the request logging middleware.
3. Remove functions like `_reject_existing_identity()` that exist only to distinguish
   error kinds — **later withdrawn, see below.**

## Reversal

The developer reversed directive 3 mid-discussion: `_reject_existing_identity` and its
like stay, and distinguishing between errors is correct so long as an exception carries
the distinction. Recorded as D-04. Replaced with a larger set of code-shape rules and
the error-architecture unification (D-08).

## Questions asked

**Quota charge timing** — Options: bill early at the endpoint / endpoint owns the call but
bills after the service's own validation / keep the resilience callback.
→ **Endpoint calls it, keep late billing.** Queue-full and circuit-open become billable;
the service's own rejections still precede the charge.

**Route template in logs** — Keep the matched template in the handler / drop it for the
middleware's raw path.
→ **Drop it.** Label cardinality becomes unbounded; correlate on `request_id`.

**AccountUnavailable's two causes** — Two classes under a shared base declaring one 403 /
two classes with two client answers.
→ **Two classes, shared base.** The `cause` string dies; indistinguishability holds.

**Merged log format** — Class name as event / message as event with a type field / fixed
event name with a type field.
→ **Class name as event.** The service-layer message becomes a field.

**Identity class contents** — user + identity row + claims / user + claims with the binding
moved to `user_id`.
→ **user + identity row + claims.** The binding column keys on the external_identities row,
so the row is required; no schema change there.

**Rejecting unlinked callers** — Asked as a three-option question; the developer answered in
free text: create `get_linked_identity` on top of `get_identity`, `get_identity` on the two
auth routes and `get_linked_identity` on the rest.

**`claim_attempt_id`** — Column dropped too / column stays unused.
→ **Column goes**, edited out of the initial migration. Contradicts `02-create-user.md:65`.

**The IntegrityError arm** — Savepoint and split only / also the constraint mapping / union
types only.
→ **Constraint mapping too.** Consequences named in the option and accepted: the
provider-account 403 becomes a 409, and the unmapped-constraint 500 tripwire dies.

**Where the docstring rule lives** — AGENTS.md / PROJECT.md / both.
→ **AGENTS.md.** Written to `ns-api-gateway/AGENTS.md` rather than the parent repo's, which
is shared with `ns-ios` and would not travel with this submodule's commits.

**Module folding** — Answered partly by the codebase: the developer had already landed the
renames in `d466a4b` and asked for a rescan. `resolve_identity()` folds into the Identity
class's module (D-13).

**`extract_bearer`** — The developer asked whether a third-party library covers it.
Answered: FastAPI ships `HTTPBearer`, but it resolves duplicate Authorization headers by
taking the first — the resolution `SHARED-INVARIANTS.md:18` forbids by name — answers 403
rather than 401, and has no bounded-reason vocabulary.
→ **Swap it in anyway**, with the divergence flagged. Verbatim: *"I would rather sacrifice a
requirement than bloat my code."*

**Other disproportionate-cost candidates** — Requested by the developer in the same answer.
Found and presented: the HMAC keyring (432 lines protecting a subject for 300 seconds that
`core.external_identities.subject` stores permanently in plaintext), of which
`idp_account_hash` and the key versioning were already dead on their own terms; and
`tests/unit/test_challenge_ids.py` at 490 lines for a two-line function.
→ **Delete the keyring entirely.** Prune the tests this phase touches; leave `tests/schema/`
alone. **No standing deletion rule** — named instances only, unlike 37.3's D-13.
