# Phase 37.4 Plan 03: The identity collapse Summary

One `Identity` class and one accessor pair replace the `LinkedIdentity`/`PreAuthIdentity` union and
the `RequestContext` builder, with the router-level `Depends(get_linked_identity)` declaration —
negative-controlled twice — standing in for the deleted type guarantee.

## What changed

**Task 1 (`d20a8a6`) — one class, the folded resolver, nullability in the store.**
`auth/identity.py` holds `Identity` and `resolve_identity`; `auth/context.py` and
`auth/resolve_identity.py` are gone. `IdentityKind`, `LinkedIdentity` and `PreAuthIdentity` are
deleted. The challenge store branches on `identity.identity is not None` in both `issue` and
`verify_binding`. `auth/adapters.py` is untouched, as required.

**Task 2 (`0771fcd`) — the accessor pair, `RequestContext` retired field by field.**
`get_request_context` became `get_identity` returning `Identity`; `get_linked_identity` declares
`Depends(get_identity)` and raises `PreAuthIdentityNotAllowed` when `user is None`. `evaluated_at`
is generated at the top of each endpoint that needs it, `route` is deleted and not re-derived in
`routers/auth.py`, and `identity` comes from the accessor. `get_chat_service` stays defined below
both accessors.

**Task 3 (`39131a8`) — the two identity suites rebuilt on the one class.**

## The security-sensitive substitution, and how it was checked

This plan removes a type-level guarantee. A green suite is not evidence that the replacement holds,
so both replacement controls were negative-controlled out of tree, against the real wiring:

| Control | Probe | Result |
|---|---|---|
| Router-level `Depends(get_linked_identity)` | A handler reading `identity.user.id` served with, then without, the declaration | **403 `preauth_identity_not_allowed`** with it; **500** without it. Never a success, and the outcome changes — the declaration is load-bearing |
| `TestEveryRouteIsAuthenticated` | An undeclared `/leaked` route injected into the real app object | Both `test_every_route_but_the_two_exemptions_requires_a_linked_identity` and `test_the_public_allowlist_is_exactly_the_readiness_probe` **failed**, naming `/leaked` |

`git diff tests/unit/test_app_wiring.py` removes no assertion and weakens none; the change inside
`TestEveryRouteIsAuthenticated` is the accessor name only, and `PREAUTH_CALLABLE_PATHS` still names
exactly two routes. The one-verify-one-query case lost its `route` assertion (D-03 killed the
subject) and gained a stronger one in its place: `who is admitted`, object identity across both
declaration levels, which proves the dependency cache more directly than the route template did.

The narrowing is now asserted in both directions at the accessor level, per D-02: an unlinked caller
on a `get_linked_identity` route is refused, and the same caller on a `get_identity` route is
admitted.

## 37.3-REVIEW WR-02 — what changed at `verify_binding`'s call site

WR-02 was that `challenge_store.verify_binding(challenge, identity)` sat as a bare statement, which
reads as fail-open to anyone skimming it: deleting the line would have left a working function that
verified nothing.

`verify_binding` now returns the `AuthChallenge` it verified (both the bound arm and the pre-auth
arm return `row`), and the call site in `routers/auth.py::_complete` binds the name every following
line reads:

```python
located = await challenge_store.locate(session, challenge_id)
if located is None:
    raise ChallengeNotFound()

# Every line below reads `challenge`, which only the binding check produces: deleting it is a NameError.
challenge = challenge_store.verify_binding(located, identity)
```

Deleting the verification is now a `NameError`, not a silent fail-open. Three unit cases and two e2e
cases that asserted `verify_binding(...) is None` were updated to `is row` — strengthened, since they
now pin the load-bearing return rather than the absence of one.

## Deviations from plan

### 1. [Rule 3 — blocking] Task boundaries could not be commit-atomic as written

Task 1 deletes `auth/context.py`, which held `RequestContext`; Task 2 retires `RequestContext`.
Task 1's `<verify>` runs the full suite, so the class had to exist somewhere in between.
`RequestContext` was carried in `auth/identity.py` for the duration of Task 1 and deleted in Task 2.
Task 1 also absorbed the forced import/annotation fallout across ten production files and eighteen
test files, since deleting a module breaks every importer in the same commit.

### 2. [Rule 1 — bug] The mechanical rename turned both narrows into always-true no-ops

Substituting `LinkedIdentity` → `Identity` rewrote `if not isinstance(identity, LinkedIdentity)` in
`get_linked_identity` and in `get_quota_gate` into `if not isinstance(identity, Identity)` — always
false, so **both guards would have admitted an unlinked caller silently, and the suite stayed
green**. Caught by reading the diff, not by a test. Both became `if identity.user is None`. This is
the same failure shape the prior wave flagged in plan 02's `except AuthRejected:` narrowing.

### 3. [Rule 3 — blocking] `get_quota_gate` still passes a `route`, carried for one plan

`QuotaGate.__init__` requires `route: str`, and plan 37.4-04 claims exclusive ownership of every
edit to `quota.py`. Blanking the label would have made the quota logs lie for one plan, so
`get_quota_gate` reads `request.scope["route"].path` with a one-line comment naming plan 37.4-04 as
its owner. `evaluated_at` is likewise generated there with `datetime.now(UTC)`, which is where plan
37.4-04 says it belongs. **This is a re-derivation of the route D-03 deletes**, scoped to the one
function plan 37.4-04 deletes wholesale. Flagged rather than hidden.

### 4. [Rule 3 — blocking] Nine test files outside Task 3's list needed the same substitution

`tests/e2e/test_challenge_store.py`, `tests/unit/test_create_user_precedence.py`,
`test_conflict_classification.py`, `test_create_user_rollback.py`, `test_exception_handlers.py`,
`test_rejection_vocabulary.py`, `test_auth_package_shape.py`, and — despite D-14's "leave
`tests/schema/` alone" — `tests/schema/test_create_atomicity.py` and `test_create_race.py`. The
schema files were changed only by type substitution and by following `create_user`'s new signature;
no constraint assertion was touched, so they remain the check on the migration.

### 5. Recorded auth-package shape updated twice

`tests/unit/test_auth_package_shape.py::CURRENT` went `(9, 14, 34)` → `(8, 12, 34)` after Task 1 →
`(8, 11, 34)` after Task 2. That file exists to make package growth a deliberate visible edit; this
phase shrank it, and the number was written down as its docstring requires.
