### `errors.py` - the merged tree (model) - D-08 / A-01

**Analog A - the base's fail-closed defaults.** `errors.py:212-219`, verbatim:

```python
# One `error_class` per subclass, so a status and a code can never be named in disagreement.
class ServiceError(Exception):
    """Base exception for service layer errors."""
    error_class: ErrorClass = INTERNAL_ERROR
    log_level: int | None = None

    def extra_headers(self) -> dict[str, str] | None:
        return None
```

`auth/exceptions.py:23-42` is the same idiom with `log_fields()` added. The merged base is these two
unioned, with `error_class` split into `status` / `code` per RESEARCH.md §B, and `log_level`
defaulting to `logging.WARNING` per RESEARCH.md Pattern 3.

**Analog B - declare-once-on-a-base.** This is D-05's exact template. `auth/exceptions.py:180-215`,
trimmed to the shape (the full docstring is 13 lines and violates D-12; keep the rule, not the prose):

```python
class ChallengeRejected(AuthRejected):
    """The five challenge rejections' one shape, and never raised itself -- only its leaves are."""
    error_class = CHALLENGE_REQUIRED


class ChallengeNotFound(ChallengeRejected):
    """No row carries the handle presented, compared byte for byte and never trimmed."""


class ChallengeExpired(ChallengeRejected):
    """The claim found the row still unclaimed but past its expiry -- the one expiry evaluation."""
```

Five leaves, zero re-declarations. `HistoricalIdentity` and `BlockedUser` under an
`AccountUnavailable` base copy this literally. The `cause` field and the `log_fields` override at
`auth/exceptions.py:115-120` are deleted, not moved.

**The counter-example in the same file.** `errors.py:232-247`: `AnalysisError` declares
`INTERNAL_ERROR`, then `TransientLLMError` and `PermanentLLMError` *re-declare* `SERVICE_UNAVAILABLE`
and `log_level = None`. That re-declaration is correct there (the leaves answer differently) and is
the failure mode for a shared-answer base. Keep both idioms and keep them distinguishable.

**Explicit-500 is a declaration, not a default.** `auth/exceptions.py:79-87` (`IdentityUnresolvable`)
declares `INTERNAL_ERROR` on purpose so the totality walk can tell it from a leaf that forgot. That
class must keep an explicit `status = 500; code = "internal_error"` after the merge.

**Message-never-in-body.** Every diagnostic `__init__` in `errors.py:344-370`
(`MissingUsageRowError`, `MultipleEffectiveGrantsError`, `UnknownTierError`) stores its ids on `self`
and passes a formatted string to `super().__init__`. The response is built from `code` alone
(`errors.py:56-60`). That split survives the merge unchanged.

**The two sites, verbatim at HEAD** (`:383`, `:387`, `:390-395`, `:405-414`):

```sql
    -- A keyed hash of the verified subject, with no key version: a challenge outstanding across a rotation fails.
    preauth_subject_hash BYTEA,
    ...
    claim_attempt_id UUID,
    ...
    -- Lifecycle: issued, then claimed once claimed_at and claim_attempt_id are set, then consumed.
    CHECK (
        (claimed_at IS NULL AND claim_attempt_id IS NULL AND consumed_at IS NULL)
        OR
        (claimed_at IS NOT NULL AND claim_attempt_id IS NOT NULL)
    ),
    ...
    -- Exactly one of the bound identity or the preauth pair, with the hash clearable only once consumed.
    CHECK (
        (bound_external_identity_id IS NOT NULL
            AND preauth_issuer IS NULL
            AND preauth_subject_hash IS NULL)
        OR
        (bound_external_identity_id IS NULL
            AND preauth_issuer IS NOT NULL
            AND (preauth_subject_hash IS NOT NULL OR consumed_at IS NOT NULL))
    )
```

Dropping `claim_attempt_id` leaves the lifecycle CHECK's first arm
`(claimed_at IS NULL AND consumed_at IS NULL)` and its second arm `(claimed_at IS NOT NULL)` - a
tautology in the second arm. RESEARCH.md Pitfall 7 is exactly this; `cf6b44f` is the precedent for
rewriting the whole CHECK rather than removing a conjunct and leaving it vacuous.

## Shared Patterns

### D-12 applied per-file, never as a trailing sweep
`AGENTS.md` (this repo) is the rule. The prose it supersedes is concentrated in the files this phase
rewrites: `auth/exceptions.py:1-6` (6-line module docstring), `:24-29`, `:33-41`, `:53-59`,
`:80-85`, `:106-111`, `:127-135`, `:181-193`; `auth/context.py:22,31,41-43`;
`app/error_handlers.py:28-33`; `quota.py:1` (a 118-character docstring line). Each is cut inside the
task that already rewrites its file. RESEARCH.md's anti-patterns list forbids a trailing "apply D-12
everywhere" plan.

### The challenge handle is never logged
`crud/challenges.py:1`: *"this module holds no logger, so none is logged."* The five challenge
classes carry no `__init__` and no field for exactly this reason (`auth/exceptions.py:190-192`). The
merged handler splats `**exc.log_fields()` - so the rule is enforced by those classes staying
field-free, not by the handler. Preserve both halves.

### `log_fields()` returns scalars only
`auth/exceptions.py:33-41` states the constraint and the failure it prevents (an expired ORM
attribute read inside the handler, after `get_db`'s rollback - RESEARCH.md Pitfall 1). Every merged
class keeps plain `str`/`UUID`/`None` values. `test_exception_handlers.py:252-294` is the guard.

### Wave 0: do not copy a broken import forward
Cited excerpts include A-00's breakage. Named here so no plan replicates it:
`app/dependencies.py:9`, `app/lifespan.py:9` (`from nativespeaker.api.database.challenges import
ChallengeStore`), `quota.py:10`, `services/chats.py:7`, `tests/unit/conftest.py:21` (`from
nativespeaker.api.database import ...`). The module is `nativespeaker.api.crud` and the class is
`ChallengesDB`.
