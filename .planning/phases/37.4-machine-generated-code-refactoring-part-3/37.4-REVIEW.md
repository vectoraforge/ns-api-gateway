### CR-60: A DeviceCheck write failure after the grant has committed is re-raised, so a durable, irreversible claim answers the client with an error

**File:** `src/nativespeaker/api/services/auth.py:218` and `src/nativespeaker/api/services/auth.py:274`, via `src/nativespeaker/api/services/auth.py:150-157`

**Issue:**
Both claim paths commit the grant and only then tell Apple:

```python
await self.session.commit()                                   # :214 / :269 -- the grant is durable
# Fail-open by design: a failure below costs the device bit, never the grant already durable.
await write_bits_with_retry(self.devicecheck, device_token, bit0=True, bit1=state.bit1)   # :218
```

The comment states a property the code does not have. `write_bits_with_retry`
(`auth/devicecheck.py:174`) does not return on failure — `_write_exhausted`
(`auth/devicecheck.py:154-157`) raises `Unavailable(stage="devicecheck_write")` when the three-attempt
budget is spent, and `_reject_or_retry` raises `ProofRejected(stage="devicecheck_write")` on an
explicit Apple rejection. Both are `AppError` subclasses, so `_complete`'s handler catches them:

```python
try:
    settled = await post_claim(identity)
except AppError:
    await self.session.rollback()
    await self._consume_quietly(...)
    raise                    # :157 -- the 503/403 becomes the client's answer
```

The rollback discards nothing (the grant committed at `:214`), the challenge is consumed, and the
client receives `503 verification_temporarily_unavailable` (or `403 proof_rejected`) for a claim
that fully succeeded. This is the only place in the codebase where the server *knows* a
state-changing mutation committed and still reports failure.

It compounds: the client's retry needs a fresh challenge (the old one is consumed), and the retry
then takes the repeat arm at `:180` / `:231`, which returns before ever reaching `write_bits_with_retry`.
So a transient DeviceCheck outage permanently leaves the device slot unspent *and* leaves the
caller having been told the claim failed. Only a `POST /auth/sync` reveals the truth.

The failure needs no attacker and no race — one Apple 5xx or one dropped connection triple is enough.

**Fix:** the mutation is durable, so the post-commit vendor write must not decide the wire answer.
Swallow it and log it, in both methods:

```python
# services/auth.py -- _claim_anonymous_grant, replacing :216-218
await self.session.commit()
# Fail-open by design, and it must not become the answer: the grant is durable, so a vendor
# failure here costs the device bit only. Logged, never raised.
try:
    await write_bits_with_retry(self.devicecheck, device_token, bit0=True, bit1=state.bit1)
except AppError as failure:
    # A closed-set label only: the class name, never the token and never Apple's body.
    logger.error("devicecheck_bit_write_failed", failure=type(failure).__name__)
```

and the same shape around `:274` for `_claim_registered_grant`. If a caller must instead learn that
the bit is unspent, that is a new response field, not a status code that contradicts the committed
state.

### CR-80: The container image the chart `require`s cannot be built at all

**File:** `pyproject.toml:4` (anchor); `Dockerfile:1,8,10,14,17,27,31`
**Issue:**
`k8s/templates/deployment.yaml:23` now hard-fails the render unless `image.repository` and
`image.tag` are set. Nothing in this repository can produce that image. `Dockerfile` has four
independent breaks, and each one alone stops the build or the boot:

1. `Dockerfile:1,10` pin `python:3.12-slim`, while `pyproject.toml:4` declares
   `requires-python = ">=3.14"`. `uv sync --frozen` resolves against `uv.lock`, whose wheels are
   `cp314` (e.g. `asyncpg-0.31.0-cp314-cp314-manylinux…`). The sync fails on the interpreter
   constraint before it ever reaches a wheel.
2. `Dockerfile:8` passes `--no-group test`. The only group declared is `dev`
   (`pyproject.toml:28-39`); uv rejects an undefined group name.
3. `Dockerfile:14` copies `/nativespeaker/app/.venv`. The builder stage's `WORKDIR` is `/app`
   (`:5`), so uv creates `/app/.venv`. The source path does not exist and `COPY` fails.
4. `Dockerfile:17,31` copy `src/nativespeaker/api` to `/app/app` and start `app.main:app`. The
   application imports itself absolutely (`from nativespeaker.api.app.lifespan import lifespan`,
   `main.py:7`), and `version("ns-api-gateway")` at `main.py:24` needs the distribution installed.
   Neither resolves under that layout, so the process would crash on import even if the build
   succeeded.

The `HEALTHCHECK` at `:27` is dead on top of that: it imports `requests`, which is in neither
`dependencies` nor `dev`, and it probes `/`, which `routers/root.py:20` now puts behind
`get_linked_identity`.

**Fix:** Bring the image in line with the project it packages:

```dockerfile
FROM python:3.14-slim AS builder
COPY --from=ghcr.io/astral-sh/uv:latest /uv /bin/uv
WORKDIR /app
COPY pyproject.toml uv.lock ./
COPY src ./src
RUN uv sync --frozen --no-dev --no-editable

FROM python:3.14-slim
WORKDIR /app
COPY --from=builder /app/.venv /app/.venv
ENV PATH="/app/.venv/bin:$PATH"
COPY config ./config/
RUN useradd -m -u 1000 appuser && chown -R appuser:appuser /app
USER appuser
EXPOSE 8000
CMD ["uvicorn", "nativespeaker.api.app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

Drop the `HEALTHCHECK` entirely — Kubernetes probes it via `/health/ready`
(`k8s/values.yaml:30`), and a Docker `HEALTHCHECK` is not read by the kubelet.

### CR-81: The chart cannot deliver the DeviceCheck key file, so both free-grant claims are permanently 503 in any cluster installed from it

**File:** `k8s/templates/deployment.yaml:17-48`; `k8s/values.yaml:47`
**Issue:**
`.env.example:81-83` states that `DEVICECHECK_PRIVATE_KEY_PATH` must point at a `.p8` PEM file on
disk, and `config.py:81` types it as a path. `deployment.yaml` declares no `volumes:` and no
`volumeMounts:` anywhere, and the only injection surface is `{{- if .Values.env }}` at `:45-48`,
whose default is `env: []` (`values.yaml:47`). An environment variable cannot carry a file. So in
every deployment produced by this chart the DeviceCheck adapter is unconfigured and
`POST /auth/claim-anonymous-grant` and `POST /auth/claim-registered-grant` fail closed as `503
verification_temporarily_unavailable` — forever, not transiently. Those are the only two routes
that mint a free grant, so no anonymous or newly registered account can ever obtain credits from a
cluster installed with this chart.

The same `env: []` default is a second, separate failure. `DatabaseConfig` (`config.py:31-35`)
and `JWTConfig.project_id` (`config.py:62`) have no defaults, so a `helm install` that sets only
the three `required` values renders a Deployment whose pod crash-loops on a pydantic
`ValidationError`. The chart already proves it knows how to prevent exactly this class of mistake:
`image.repository`, `image.tag` (`deployment.yaml:23`) and `jwt.issuer`
(`security-policy.yaml:29`) are all wrapped in `required`. The six settings the process genuinely
cannot boot without are not.

**Fix:** Add the mount and guard the mandatory settings:

```yaml
# values.yaml
credentials:
  secretName: ""          # a Secret holding AuthKey_XXXXXXXXXX.p8
env: []
```

```yaml
# deployment.yaml, in the container spec
        env:
        - name: DEVICECHECK_PRIVATE_KEY_PATH
          value: /etc/ns/devicecheck/key.p8
        {{- with .Values.env }}
        {{- toYaml . | nindent 8 }}
        {{- end }}
        volumeMounts:
        - name: devicecheck
          mountPath: /etc/ns/devicecheck
          readOnly: true
      volumes:
      - name: devicecheck
        secret:
          secretName: {{ required "credentials.secretName must name a Secret holding the DeviceCheck .p8" .Values.credentials.secretName }}
          defaultMode: 0400
```

and supply `DB_*` / `JWT_PROJECT_ID` through `envFrom: [{secretRef: {name: ...}}]` with the secret
name likewise `required`, so a forgotten `--set` fails at render rather than at the third
CrashLoopBackOff.

### WR-01: `missing_token` is reported for callers that did present an `Authorization` header

**File:** `src/nativespeaker/api/app/dependencies.py:70-73` (and `src/nativespeaker/api/errors.py:361-371`)

**Issue:** `_bearer` is `HTTPBearer(auto_error=False)`. FastAPI 0.135.1's
`HTTPBearer.__call__` returns `None` for *four* distinct inputs: no header at all, a non-Bearer
scheme, a Bearer header with empty credentials, and an unparsable value. `get_identity` maps all
four onto `BoundedReason.missing_token`.

`dependencies.py:71-72` claims the label separates "clients that send nothing from clients that
send garbage", and `errors.py:363-366` states the rule explicitly: *"a duplicated or garbage
Authorization field did present one, so it earns `invalid_token` like a failed signature."*
Neither holds. Driven through the real stack:

```
no header      -> 401 WWW='Bearer'                        bounded_reason='missing_token'
Basic ...      -> 401 WWW='Bearer'                        bounded_reason='missing_token'   <-- wrong
"Bearer"       -> 401 WWW='Bearer'                        bounded_reason='missing_token'   <-- wrong
"zzzzz"        -> 401 WWW='Bearer'                        bounded_reason='missing_token'   <-- wrong
Bearer <junk>  -> 401 WWW='Bearer error="invalid_token"'  bounded_reason='bad_signature'
dup header     -> 401 WWW='Bearer error="invalid_token"'  bounded_reason='duplicate_authorization'
```

Two consequences. (1) The spike alert cannot separate the two populations it is labelled by — a
credential-stuffing run against a non-Bearer scheme lands in the same bucket as unauthenticated
health noise. (2) Those responses carry the bare RFC 6750 §3.1 challenge, which is reserved for
requests that carried no credential; a malformed one should carry `error="invalid_token"` (or
`invalid_request`), which is what the class already knows how to emit.

This is not covered by D-10 (which accepted losing the distinction along with `BoundedReason`
itself): the tree since re-added `BoundedReason` *and* `duplicate_authorization`, and both
comments now assert the distinction as live behaviour.

**Fix:** read the raw field once in `get_identity` and classify before delegating:

```python
raw = request.headers.get("authorization")
if credential is None:
    # Something was sent but HTTPBearer could not use it: that is garbage, not absence.
    raise InvalidExternalJwt(bounded_reason=BoundedReason.malformed if raw
                             else BoundedReason.missing_token)
```

### WR-02: the bounded reason handed to `InvalidExternalJwt` may be `None`

**File:** `src/nativespeaker/api/app/dependencies.py:76-79`

**Issue:** `TokenVerifier.verify` is typed `tuple[VerifiedClaims | None, BoundedReason | None]`,
so `reason` is `BoundedReason | None` at the point it is passed to
`InvalidExternalJwt(bounded_reason=reason)`. The class docstring says *"Never `None`: spec 11
closes the reason set at eight named values, and a null label is not one of them"*, but nothing
enforces it — not the type (the parameter is annotated `BoundedReason`, and `ty` does not reject
the call), not an assertion. If a verifier double or a future arm ever returns `(None, None)`,
`log_fields()` emits `bounded_reason="None"` — a label outside the closed set the alert is keyed
on — and `extra_headers()` silently degrades to `invalid_token`. The `_FixedKeyVerifier` in
`tests/unit/conftest.py:92-108` has the same signature, so a test double is a live route to it.

**Fix:**

```python
if claims is None:
    # The set is closed; an unlabelled refusal is a forgery for logging purposes, never a null.
    raise InvalidExternalJwt(bounded_reason=reason or BoundedReason.bad_signature)
```

### WR-03: `get_chat_service` reads the clock outside the per-request evaluation-time dependency

**File:** `src/nativespeaker/api/app/dependencies.py:111-122` (vs `:142-144`)

**Issue:** Every other service factory takes `evaluated_at: datetime = Depends(get_evaluated_at)`,
whose whole purpose (`:143`) is that FastAPI caches it so one instant serves the request.
`get_chat_service` instead calls `datetime.now(UTC)` inline at `:122`. `SHARED-INVARIANTS.md`
("Grants and evaluation time") requires every time-dependent value to derive from ONE captured
evaluation time per request.

Today no route mixes the two — `/`, `/chats/*` and `/examples` take `get_chat_service` and
nothing else clock-bearing — so the invariant is not currently broken. It is a landmine: adding
`Depends(get_evaluated_at)` (or any `get_*_service`) to a chats route silently produces two
instants for one request, and the quota charge `ChatService` performs is exactly the kind of
time-dependent write that then straddles a month boundary. `test_sync_clock_capture.py` asserts
the pattern for the sync path only, so nothing fails.

**Fix:**

```python
def get_chat_service(request: Request,
                     db: AsyncSession = Depends(get_db),
                     config: AppConfig = Depends(get_config),
                     quota_service: QuotaService = Depends(get_quota_service),
                     evaluated_at: datetime = Depends(get_evaluated_at)) -> ChatService:
    return ChatService(..., evaluated_at=evaluated_at)
```

### WR-04: the config loader assumes `yaml.safe_load` returned a mapping

**File:** `src/nativespeaker/api/config.py:163-166`

**Issue:** `AppConfig(**yaml_data, ...)` runs with no check on what `safe_load` produced. An
empty `config/config.yaml`, a file that is all comments, or one whose top level is a list or a
scalar makes `yaml_data` `None`/non-mapping and boot dies with a bare interpreter error that
names neither the file nor the problem. Reproduced:

```
EMPTY YAML: TypeError nativespeaker.api.config.AppConfig() argument after ** must be a mapping, not NoneType
```

The same applies to `examples=yaml.safe_load(examples_path.read_text())`, which reaches pydantic
as `None` and produces an `examples` type error that never mentions `examples.yaml`. A
zero-length config file is a routine ConfigMap/volume-mount failure mode in Kubernetes, and this
turns it into a crashloop whose log line names nothing an operator can act on.

**Fix:**

```python
def _mapping(path: Path) -> dict:
    """One YAML document as a mapping, or a failure naming the file that is not one."""
    loaded = yaml.safe_load(path.read_text())
    if not isinstance(loaded, dict):
        raise ValueError(f"{path} does not contain a YAML mapping")
    return loaded
```

### WR-05: `default_factory` on nested models with required fields mislocates the boot error

**File:** `src/nativespeaker/api/config.py:138-139`

**Issue:** `db: DatabaseConfig = Field(default_factory=DatabaseConfig)` and
`jwt: JWTConfig = Field(default_factory=JWTConfig)` both name models whose fields are required.
When the block is wholly absent — no `db:` in YAML and no `DB_*` in the environment — pydantic
calls the factory, `DatabaseConfig()` raises on its own, and the error surfaces with the leaf
names and no path. Reproduced:

```
NO DB: ValidationError  5 validation errors for EnvironmentConfig
host   Field required
port   Field required
user   Field required
password  Field required
...
```

Nothing in that message says "database". `DatabaseConfig` and `JWTConfig` are also plain
`BaseModel`s, so the `hide_input_in_errors=True` that `BaseConfig:26` sets does not apply to an
error the factory raises directly (it happens to be harmless here because the inputs are absent,
but the comment at `:24` asserts a property that this path does not have).

**Fix:** declare the two blocks required, so the absence is reported as `db.host` rather than
`host`:

```python
    db: DatabaseConfig
    jwt: JWTConfig
```

Reserve `default_factory` for the nested models whose fields are all optional
(`DeviceCheckConfig`, `AppStoreConfig`, `GooglePlayConfig`, `ModelConfig`, `ResilienceConfig`).

### WR-62: The final `commit()` in both store services sits outside every failure classifier, so a deferred-constraint violation is an unhandled 500

**File:** `src/nativespeaker/api/services/restore.py:154` and `src/nativespeaker/api/services/subscriptions.py:168`

**Issue:** Both services classify integrity failures only at `flush()` time — every writer in
`crud/subscriptions.py` wraps its flush and asks `is_unique_violation`, and `_settle` turns
`lost_race` into the documented `InternalError`. Neither service wraps its own `commit()`.

Two foreign keys on `core.access_grants` are `DEFERRABLE INITIALLY DEFERRED`
(`migrations/20260818_01_initial-release.sql:242-247`), which means they are evaluated at COMMIT and
nowhere else. Any violation of the composite `(subscription_id, user_id)` key or the
product-entitled key therefore escapes every classifier in these two files and lands in
`unhandled_exception` (`app/error_handlers.py:78`) with `exc_info=exc` — a full traceback for a
condition the same files elsewhere treat as an ordinary lost race with a one-line warning.
`45-04-SUMMARY.md:218` records that this deferred FK has already fired as a 23503 in this codebase.

The wire answer happens to be the same 500 `internal_error`, so this is a diagnosability and
consistency defect rather than a wrong answer — but it means the log for the real-world failure mode
looks nothing like the log for the modelled one.

**Fix:** wrap the terminal commit in both services and route it through the same `_settle` vocabulary:

```python
try:
    await self.session.commit()
except IntegrityError:
    # The deferred grant keys are evaluated here and nowhere else; a violation is the same
    # lost race the flushes classify, and the store/client retry finds the winner's rows.
    await self._settle(WriteOutcome.lost_race, proof)
```

### IN-91: The Identity Toolkit key travels in the URL query string, so an HTTP error prints it

**File:** `tests/e2e/conftest.py:76-83`, `113-118`, `162-174`
**Issue:** `f"…/accounts:signInWithPassword?key={api_key}"` followed by `resp.raise_for_status()`.
`httpx.HTTPStatusError` renders the full request URL in its message, so a 400 from Identity Toolkit
writes `JWT_API_KEY` into the pytest traceback and into CI logs. `config.py:66` deliberately types
the value `SecretStr` so it cannot leak through a model dump; this path leaks it anyway. Firebase
Web API keys are semi-public by design, so the impact is small — but the value is one the project
already treats as a secret, and `.env.example:14` calls it one.
**Fix:** Pass it as a parameter rather than splicing it into the URL, and it stays out of the
rendered URL only if httpx is given a header instead:
`httpx.post(url, headers={"X-Goog-Api-Key": api_key}, json=...)`, which Identity Toolkit accepts.
Failing that, wrap the three calls in a helper that catches `HTTPStatusError` and re-raises with the
key redacted.
