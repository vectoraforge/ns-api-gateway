### Gaps Summary

That gap: the must-have stated verbatim in `37.4-02-PLAN.md`'s frontmatter ("`Retry-After`,
`WWW-Authenticate` and the `Allow` header on a 405 all still reach the client (D-08)") was false —

Closed by `a981e4b` and `53c7f4a`. `extra_headers()` now lives on `InvalidExternalJwt` (bare `Bearer`

verification, per RFC 6750 §3.1) and on `UserNotFound`. `AuthenticationError` is deleted.

wrong status, since an authenticated-but-unlinked caller is `get_linked_identity`'s 403. The header
had therefore never reached a client in any version of this code. Plan 04's deletion of
`get_quota_gate` removed a broken thing and, in doing so, removed the last cover story for an
already-missing header. The must-have it violated was already false when the phase began.

The replacement is verified against six genuine unauthenticated requests in
`test_auth_security.py::TestEveryRealUnauthorizedCarriesTheChallenge`, not a raised class, and
negative-controlled: stubbing `extra_headers()` to `{}` fails all six by name. This matters because
the *original* test asserted the header by raising the dead class at a synthetic route — which is
precisely why a fully green suite hid the defect. That makes seven instances in this phase of the
same pattern: a green suite concealing a real fault, caught only by reading or by negative control.

Everything else the phase's four fronts required — the identity collapse, the error-tree
unification (aside from the header gap), the quota-function demotion, and the deletion of the HMAC
keyring / hand-rolled bearer extractor / `claim_attempt_id` — is verified present, wired, and
tested. The three flagged conflicts (D-11, D-03 under CREATE-02; D-06 under CREATE-04) are recorded
correctly and consistently across `REQUIREMENTS.md`'s header, per-requirement blocks, traceability
row, and standing tables. `FOUND-02`'s deletion is complete and its cross-references resolved. The
5-vs-3 conflict count in `37.4-07-PLAN.md`'s must-haves is a documented, developer-directed scope
