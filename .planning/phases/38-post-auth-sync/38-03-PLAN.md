Add a test class proving ROADMAP success criterion 3, following `test_create_user.py`'s before/after
helper shape but stronger than a row count.

Write a helper that snapshots the caller's entitlement state: every column of the caller's
`core.access_grants` rows, every column of the matching `core.user_monthly_usage` rows, and the
caller's `core.users` row, plus the total row counts of all three tables. Order the snapshot
deterministically by id so two snapshots are comparable.

Take the snapshot, issue the sync request, take it again, and assert the two snapshots are equal.
Run this over three seeded states so the read-only guarantee is proven where it is most likely to
break, not only where it is easy:

1. A current-period grant with a matching usage row (the happy path).
2. A grant whose usage row names an earlier period — the branch quota resolves by writing. This is
   the case that would silently persist a rollover if the service assigned instead of computing, and
   it is the reason this criterion is tested rather than assumed.
3. No grant at all.

Additionally assert that a second identical request immediately after the first returns the same body
as the first, which is what a caller reconciling after a lost response actually does.

Add three short test classes.

**The stored provider column.** Seed a caller whose `core.external_identities.provider` is not the
default the happy-path fixture uses, and assert the `identity_provider` field on the wire equals that
seeded value. This is what proves the field is read from the stored column rather than defaulted,
rederived from a token claim, or inferred — the rule `SHARED-INVARIANTS.md` § "Identity and
ownership" states and the value Phase 39's `/users/me` must agree with.

**The barrier's rejections, which this endpoint owes but does not implement.** Assert that a request
with no `Authorization` header returns 401 with body exactly `{"code": "auth_required"}`, and that a
verified but unlinked caller returns 403 with the body the existing barrier returns for
`preauth_identity_not_allowed` — read the error class to get the exact code string rather than
guessing it. Both must come from the existing dependencies with nothing endpoint-specific added;
the point of the test is that the route inherits them.

**One fail-closed case end to end.** Seed a grant with no usage row using `seed_grant`'s
`with_usage=False` parameter — the parameter's own comment in the fixture names this as the case it
exists for — and assert 500 with body exactly `{"code": "internal_error"}` and nothing more. This is
D-07's divergence observed from outside: the brief would have reported a zero here.
