Append a dated Phase 40 entry to the header block of amendments in `.planning/REQUIREMENTS.md`, and a
matching note under UPGRADE-01 and UPGRADE-02, covering four things.

**The client declaration is gone.** The brief has the client naming its target provider at prepare and
the server re-checking it byte-for-byte at completion. Neither exists: the server derives the provider
solely from the Firebase Admin read, which continues Phase 37 D-12 and answers the question Phase 37
D-13 flagged forward when it dropped the operation variant column. Say what dissolves with it — the
required field, the normalisation, the persisted variant, the re-check, and the third bounded cause
the brief's not-linked rejection carried, which cannot occur when there is no declaration to mismatch.

**The operation enum is smaller than the schema shipped with.** Three values existed only for the auth
event audit that Phase 37.1 deleted, leaving the challenge table as the type's only consumer. The type
now carries exactly the four challenge-bearing operations and the constraint that restated that
membership is dropped. Record the accepted cost in the developer's own terms: for one phase each, a
client can obtain a handle for an operation whose endpoint does not exist yet, which expires unspent
in 300 seconds — chosen over a maintained list of issuable operations because the concern being
optimised for is fewer copies of one fact, not tidiness.

**The Firebase exposure is accepted and flagged.** Every completion makes one Admin read, including an
idempotent repeat that changes nothing, and the brief forbids skipping it because the read is the only
thing that detects a diverged binding. With the rate-limit engine deleted from the product and the
gateway limit deferred, a looping client can call it without bound. Record the mitigating facts: the
caller must already hold a valid token for an existing linked account, so this is one subject looping
on itself rather than a fan-out; the client contract says to call only when the client's own Firebase
state and the backend disagree; and the exposure closes when the gateway contract lands. Mirror how
Phase 37 D-01 recorded unlimited account creation.

**What was already dead before this phase started.** State plainly that the brief's three backend
rate-limit entries and its gateway entry, and its audit row and audit-hardening paragraph, were
removed from the product by earlier decisions — the rate-limit engine by Phase 35 D-05, the audit
subsystem by Phase 37.1 D-01, and the invariant requiring it by Phase 38 D-03 — so a later reader does
not treat the brief as unmet by this phase.
