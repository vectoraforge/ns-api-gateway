Wire one entry point through every layer, for exactly one path: a linked caller whose stored identity

**`crud/identities.py` — two new methods.**

`lock_identity_and_user` takes the issuer and subject and returns the identity row and its user,
locked. It is a **new** statement with an **inner** join, not a reuse of `resolve`: PostgreSQL refuses
a row lock on the nullable side of an outer join, and by the time this runs the route's dependency has
already established that both rows exist and are active, so the outer join's purpose is already
served. Take the lock with SQLAlchemy's `.with_for_update()`, never as raw SQL text — the raw form
trips a ratchet in the unit suite that scans the combined source of this module and the service. Use
`col(...)` in every `where`, as every other statement in this module does. State the lock's ordering
in the module docstring the way `crud/grants.py` states its own.

`flip_provider` takes the captured instant, the locked identity row, its user, and the provider,
provider_uid and email the read reported, and issues both halves of the flip inside the caller's
transaction. It sets the identity row's provider, its provider_uid and its updated_at; it sets the
user's registration timestamp and updated_at; and it copies the email **only** when the stored value
is still absent, per D-13 — a stored address is never overwritten and a divergent live address is not
a rejection here. It never touches the display name, the identity state, the historical timestamp or
the free-grant timestamp. It never commits: transaction boundaries live in the service.

Wrap only the `flush()` in the `try` — an ORM attribute assignment sends nothing to the database and
does not belong inside one (D-17). The `except IntegrityError` arm raises
`ProviderAccountAlreadyLinked`, carrying the identity row id and the stored and live provider names,
`from` the caught error. Name no constraint, parse no message, and open no savepoint: copy
`insert_account`'s two-line arm exactly.

**`services/auth.py` — the sequence shared, not copied (D-16).**

Extract the body of `complete` into `_complete`, taking the operation to check for and the write to
perform as parameters. Everything between locate and spend stays byte-identical in behaviour: the
pre-claim rejections in the same order and still consuming nothing, the claim, the deliberate commit
before the provider call, the retry-wrapped lookup, the rollback-then-spend arm, and the spend on
success. `complete` becomes a one-line call with the create-user operation and the create-user write;
`complete_upgrade` is its twin with the upgrade operation and the upgrade write. Do not extract a base
class and do not create a second service — D-16 declined both.

`_complete` returns what the write seam returns, not what the read reported. This matters: on the
idempotent repeat that plan 40-05 adds, the value the transaction settled on is the stored provider,
and a seam that returned the read's provider before the transaction had its say would launder a
divergence into a success.

The upgrade write seam locks and revalidates the identity and user rows at the top of the transaction
(D-15), then, for this task's one path — stored anonymous, live registered — calls the flip and
returns the provider written. Every other combination is out of scope here and must raise rather than
fall through. A not-yet-built marker is not acceptable on a shipped route, so raise the 403 the phase
already owns and let plan 40-05 give each combination its own class. Say in the summary exactly which
combinations currently reach that placeholder raise, so 40-05 has a list rather than a search.

Discharge D-17 in the shared arm while you are in it: the rollback path currently nests a `try`
inside an `except`. Move the swallow into one small named function whose whole job is not raising,
the way `_consume_and_commit` is already a named boundary in this file. That is the minimum change
that makes the rule true for the new path; it is not the deferred rewrite of create-user's logic, and
no status code, log event or consumption disposition may move with it.
