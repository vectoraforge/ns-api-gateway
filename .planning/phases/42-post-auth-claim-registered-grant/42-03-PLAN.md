<objective>
Execute every outcome the registered claim can produce, at the two depths that can reach them: a
stub-session unit matrix for precedence and consumption, and end-to-end cases through the real router
for the outcomes a client actually sees.

Purpose: plan 42-02 built the destination decision and both writes; this plan turns each of its
branches into a named, executed case. The consumption rule is the one most easily broken by a later
edit — every outcome from the claim onward must spend the handle exactly once, including the
refusals — and it is invisible without a matrix that counts.

Output: two test modules covering ten outcomes, with the precedence order and the consumption count
asserted per outcome rather than inferred from the happy path.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → `POST /auth/claim-registered-grant` | every refusal body crosses back here, and a difference between two of them is an account-state oracle |
| application → Apple DeviceCheck | the failure arms cross here; an ambiguous answer must never become permission |
| test double → the code under test | a stub that is more permissive than production can hide a live defect, which is how the Phase 41 loser arm shipped |
