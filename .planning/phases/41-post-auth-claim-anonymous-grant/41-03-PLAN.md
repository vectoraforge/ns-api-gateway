**`services/auth.py` — the branches.** Replace each placeholder raise the tracer's summary names with
its own leaf. The preflight order stays exactly as the tracer set it, database before Apple:

- an effective grant with `source == anonymous_device_grant` is held → return without writing; the

**`tests/e2e/test_claim_anonymous_grant.py` — the matrix.** Add classes covering, each as its own
case, each through the real router, and each asserting the challenge row's consumption state
afterwards:

1. **The repeat (D-09).** An account already holding an active anonymous device grant claims again
   with a fresh handle: 200, a body equal to the fresh claim's body, no new rows of any of the three

   proves the preflight ran before Apple rather than after.

   so a more helpful field fails the case. No Apple call.
3. **An active grant of another source.** Seed a `manual` active grant: 403, same body, no Apple call.
4. **A registered caller (D-08).** Seed the identity with a registered provider: 403, same body, no
   Apple call, and nothing claimed or written.
5. **The device slot is already spent.** Script the fake to answer bit0 true: 403 with the
   device-exhausted code, no write call to Apple, and no grant row.
6. **Apple refuses the token.** Script the fake to raise the proof rejection: 403 with that code, and
   no grant row.
7. **Apple is unavailable.** Script the fake to raise the exhausted-budget rejection: 503 with the
   temporarily-unavailable code, and no grant row.

For 1 through 4 assert the refusal body by equality against one module-level constant, the way the
upgrade file does — three of them are the same class of refusal and a body that differed between them
would be an account-state oracle for any token holder.

For every one of the seven, read the challenge row back and assert its consumption: 5, 6 and 7 happen
after the claim and must consume; 1, 2 and 3 also happen after the claim and must consume; 4 is

in the summary rather than adjusting the case to match, because the disposition is a decision and not
an implementation detail.

Use two obviously synthetic token strings and never a value that looks like a real device token.
