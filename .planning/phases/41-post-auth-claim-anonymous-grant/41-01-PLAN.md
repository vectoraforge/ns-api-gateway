<assumption_delta_decision>
**Signal:** the pluralization detector fired on ROADMAP criterion 3, *"A second claim on an account
that already holds a free grant does not allocate a second one"*.

**Judged on its merits.** The trigger phrase is a repeat-invocation case, not a second variant of a
modelled noun, so on the literal signal the answer would be `no-change`. But there is a real delta
next to it, and it is the one worth recording: **the lifetime free-grant slot is not per source, it is
per account across the *set* of free sources.** `ix_access_grants_one_free_grant_per_user_source` is
partial on `source IN ('anonymous_device_grant', 'registered_account_grant')` and carries no status
predicate, so the rule this phase implements is already plural in the database while
`anonymous_device_grant` is the only member Python names. Phase 42 adds the second member.

**Noun now primary:** the free-grant source *set*, not the anonymous device grant.

**Decision: `promote`.** `tables/grants.py` gains one named constant, `FREE_GRANT_SOURCES`, holding
both members, and the eligibility read in `crud/grants.py` filters on it rather than on a literal
pair. Rationale: without it this phase writes a second copy of a membership the index already carries,
and Phase 42 would write a third. One name, three readers.

**Companion (planned, cheap):** plan 41-04 asserts that `FREE_GRANT_SOURCES` equals the membership in
the live index predicate, so a future phase that narrows the constant back to the singular goes red
against the database rather than silently reopening a spent slot.
</assumption_delta_decision>

**`auth/devicecheck.py` — the new seam (Claude's Discretion, `AGENTS.md` § Package layout).** Mirror
`auth/firebase.py`'s structure exactly: module constants, an internal retryable marker that never
escapes, an exhausted-budget callback that converts to the client's owed rejection, and free
`*_with_retry` functions holding the `AsyncRetrying`.

Constants: `DEVICECHECK_HOST = "https://api.devicecheck.apple.com"`, `QUERY_PATH =
"/v1/query_two_bits"`, `UPDATE_PATH = "/v1/update_two_bits"`, `DEVICECHECK_ATTEMPTS = 3`. The host is a
constant and not a config field — the development host must not be reachable through anything a
client can influence, and D-01 defers the bypass that would need one.

`BitState` is a frozen slotted dataclass with `bit0: bool` and `bit1: bool`. `DeviceCheckAdapter` is a
`Protocol` declared in this module beside its implementation, per FOUND-08's forward-flag treatment,
with two methods: `read_bits(device_token: str) -> BitState` and `write_bits(device_token: str, *,
bit0: bool, bit1: bool) -> None`. It does not go in `auth/adapters.py`: that module is guarded by an
import allowlist that does not include `httpx`, and putting it there fails
`tests/unit/test_adapter_interfaces.py`.

`AppleDeviceCheck` takes the three credential values and an `httpx.AsyncClient`. Both methods mint a
fresh ES256 bearer through one private `_service_jwt` helper and send `Authorization: Bearer <jwt>`.
The claim set is `iss` (the team id) and `iat` (whole seconds), with `kid` (the key id) in the header
and `algorithm="ES256"` — built with `jwt.encode`, never by hand: a JOSE ECDSA signature is raw r‖s
and not the DER a signer emits, and converting it by hand is the classic silent failure. Keep the
claim set in that one helper so Open Question 1's unresolved `sub`/`exp` question is a one-line change
when a real 401 from Apple settles it. If any of the three credential values is absent, raise
`Unavailable(stage="devicecheck_read")` before signing anything — fail closed, and the same shape the
Firebase seam already takes with no credential.

Both request bodies carry `device_token`, a fresh `uuid4()` string as `transaction_id`, and
`timestamp` as **milliseconds** since the epoch. Never use the challenge handle as the transaction id:
the handle is a secret capability that travels only in the prepare response and the completion body.
The update body additionally carries `bit0: True` and `bit1` set to the value the query returned —
Apple writes both bits in one call, so a fabricated bit1 destroys the state Phase 42 depends on, with
no way to detect it afterwards.

Parse the query response in this exact order, with nothing falling through to a default:
1. status 400 → `ProofRejected(stage="devicecheck_read", cause="rejected")` — definitive, spends no
   further attempt.
2. any other non-2xx → the retryable marker carrying the status number only.
3. the stripped body equals one of the two documented never-set strings, `Failed to find bit state` or
   `Bit State Not Found` → `BitState(bit0=False, bit1=False)`. This is the eligible first-ever claim,
   not an error, and it arrives as HTTP 200 with a plain-text body — calling the JSON decoder before
   this check breaks every genuine first claim.
4. the body decodes to a mapping carrying both bit keys → that state.
5. anything else → the retryable marker carrying a bounded reason.

Parse the update response the same way: 200 is the confirmation, 400 is
`ProofRejected(stage="devicecheck_write", cause="rejected")`, everything else is retryable. Only
Apple's explicit confirmation permits activation.

`read_bits_with_retry` and `write_bits_with_retry` each build an `AsyncRetrying` with
`stop=stop_after_attempt(DEVICECHECK_ATTEMPTS)`, `retry=retry_if_exception_type` on the retryable
marker only, and `retry_error_callback` set to a module-level callback that raises
`Unavailable(stage="devicecheck_read")` or `Unavailable(stage="devicecheck_write")` from the last
exception. `Unavailable` already answers 503 `verification_temporarily_unavailable`, so no third class
is needed. `ProofRejected` and `DeviceGrantExhausted` are not retryable and propagate after one
attempt.

This module holds no logger, exactly as `crud/challenges.py` states for handles: a module that sees a
raw token must have nothing that could write one. Every string that reaches an exception is one of
ours from a closed set — a stage name, a bounded cause, or a status number. Certificate verification
on the client stays at the library default and is never turned off, here or in a test.

**`errors.py` — the two new codes and the refusal family (D-11, D-08).** Append after the upgrade
arms. `ProofRejected` and `DeviceGrantExhausted` both subclass `ProviderLookupError`, each declaring
