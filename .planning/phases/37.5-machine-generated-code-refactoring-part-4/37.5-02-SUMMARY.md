## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The token-collision monkeypatch pointed at a module that no longer holds `uuid4`**
- **Found during:** the start of task 2, by running `pytest -m schema` rather than only collecting it
- **Issue:** `tests/schema/test_create_atomicity.py:272` does `monkeypatch.setattr(creation, "uuid4", lambda: minted)`, where `creation` was `nativespeaker.api.auth.create_user`. Task 1 moved the insert — and with it `uuid4` — into `crud/identities.py`, so the attribute was gone and four cases raised `AttributeError`. **Collection was green throughout**; only running the suite showed it. This is A-10's trap one level deeper than the plan anticipated: the plan's collection gate catches a broken import, but not a broken `setattr` target.
- **Fix:** import `nativespeaker.api.crud.identities as identities_crud` and patch there.
- **Verification:** `pytest -m schema -q` went from `110 passed, 4 errors` to `114 passed`.
- **Committed in:** `ef730bd` (its own commit, so task 1's tree is correct in isolation)

**2. [Rule 2 - AGENTS.md] `_reject_existing_identity`'s user read routed through the store**
- **Found during:** task 2 design
- **Issue:** The plan says `_reject_existing_identity` "moves, it does not dissolve" and survives "as written". As written it contains `select(User).where(...)` — a raw database query. Landing that in `services/auth.py` would put database access in `services/`, which `AGENTS.md` § Package layout forbids ("`crud/` — database access"), inside the very plan whose objective is to restore that layering. AGENTS.md is a hard constraint and takes precedence over the plan text.
- **Fix:** added `IdentitiesDB.user_by_id(user_id)`; `_reject_existing_identity` survives as a named rule on `AuthService` and calls it. The function still moves and still does not dissolve — only its one read is delegated.
- **Impact on assertions:** none. The store shares the service's session, so `test_the_historical_arm_reads_only_the_identity_row`'s `len(session.statements) == 1` and every other statement-count assertion hold unchanged.
- **Committed in:** `88e5f4d`

**3. [Rule 3 - Blocking] No `.venv` and no `.env` inside the worktree**
- **Found during:** environment setup, same as plan 37.5-01 hit
- **Issue:** both are gitignored, so the worktree has neither; the repo `.venv`'s editable `.pth` resolves `nativespeaker` to the **main** checkout.
- **Fix:** symlinked the repo `.venv` in, copied `.env` in, and ran every command with `PYTHONPATH=src` so the worktree's `src/` precedes the `.pth` entry. Verified: `nativespeaker.api.errors.__file__` resolves inside the worktree. Both removed before the final commit.
- **Committed in:** n/a — no tracked file involved

### Deliberate departures from the plan text

**4. Task 2 landed as two commits (RED, then GREEN), not one.** The plan's action block says "One commit", but the task is `type="auto" tdd="true"` and carries a `<behavior>` block — which is the executor's TDD contract, and RED/GREEN are its commits. RED (`75ff9fc`) re-points five modules at `AuthService` and is observably red: all five fail to collect with `ModuleNotFoundError`. GREEN (`88e5f4d`) is a single atomic commit containing the whole move, so the plan's real requirement — do not split the *move* — is met.

**5. `schemas/__init__.py` was left empty, and that is the decision.** The plan lists it in `files_modified` and PATTERNS asks the facade question to be settled once. Settled: no facade. Every `schemas.*` symbol is already imported by full path (`from nativespeaker.api.schemas.api import ...`), and adding one would make `tables/__init__.py` → `schemas.api` → `schemas/__init__` → `schemas.auth` → `tables.identities` re-enter a partially-initialised `tables` package. The `crud`/`services`/`tables` facades stay as they are; `schemas` keeps its established no-facade convention.

**6. `IdentitiesDB` method names dropped the `_identity` suffix.** `resolve_identity` → `resolve` (named by the plan), and by the same reasoning `resolve_existing_identity` → `resolve_existing` and `_insert_account` → `insert_account`. On a class already called `IdentitiesDB` the suffixes stutter.

**7. `_CREATION_SOURCE` now spans two modules.** `test_conflict_classification.py`'s structural guards (no second race arbiter, no message-text discrimination, no savepoint) read one file's source. The creation path is now two files, so the guard reads `services/auth.py` and `crud/identities.py` concatenated. Pointing it at either one alone would have silently halved its reach — that is the weakening D-13 forbids, and it would not have failed any test.
