Deleting a trailing comment necessarily rewrites its line, so a pure-deletion grep cannot distinguish it from a weakening. **The AST proof is the stronger statement and it is clean**: all 16 changed `.py` files parse to an identical tree with docstrings stripped, so the assertion is byte-for-byte the same expression. The gate was reported rather than gamed; restoring the comment to make the grep read 0 would have kept a restatement the sweep exists to remove.

**Flag 3 — `test_quota.py::TestAnOpenCircuitStillAnswers503` lost a harness caution's pointer.** The docstring was three lines and cleared the gate, but two of them said what the class does *not* assert and named the file that does. The replacement keeps the caution and drops the pointer:

> was: *"The wire answer an open circuit gives. The counter is not readable here -- `_db_transaction` nests every session as a savepoint that `get_db`'s rollback discards -- so the credit is asserted in `tests/unit/test_quota_seam.py::TestNoRequestThatNeverReachedTheProviderIsBilled`."*
>
> now: *"The wire answer an open circuit gives; the credit is not readable through the rollback harness."*

**What is lost is the mechanism (`savepoint` / `get_db`'s rollback) and the pointer.** The hazard it guards against is a maintainer "strengthening" this class with a counter assertion that then fails for a harness reason. If the developer judges that pointer worth the D-12 breach, it belongs back.
