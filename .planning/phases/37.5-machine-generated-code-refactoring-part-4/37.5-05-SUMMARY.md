## The four negative controls

**Three credits for one request.** Restored, the same case reports `1`. The case therefore discriminates.

### Control 2 — the classifier really is kept away from the quota rejection. **Observed.**

With the same break in place, the two exhausted-allowance controls both failed, and a direct probe

This is A-01's second and third failure modes made visible in one run: **the user's own 429 came back as

### Control 4 — the double is not lying. **Executed; did NOT reproduce as specified. Read this one.**

The plan predicts that moving `"provider_called"` back onto entry to the passthrough makes
`TestNoSessionIsHeldAcrossTheProviderCall`'s ordering case fail. **It does not.** Observed:

```
pytest -k "closed_before_the_provider_is_entered"  →  1 passed
```

**Why the prediction was wrong.** `37.5-RESEARCH.md` Pitfall 2 reasons that "under Option B the marker
would fire before admission". It fires before *the provider*, but not before *the charge*: `ChatService`
enters admission, charges, and only then calls `ask_llm` → `llm_service.ainvoke`. An entry marker on
`ainvoke` therefore still lands after `session_closed`, and the ordering assertion is simply insensitive
to where inside the LLM service the marker sits. The marker would have to move onto `admission()` entry
for that case to notice.

**The lie is still caught, by two other cases.** With the marker on entry the counter increments once per
*request* instead of once per *attempt*, and:

```
FAILED test_two_transient_failures_then_success_spends_one_unit
FAILED test_the_charge_is_not_refunded_when_the_provider_call_fails
E   assert 1 == 3
```

So the double cannot lie undetected — but the case that catches it is the retry pair, not the ordering
case. **Consequence for later plans: `TestNoSessionIsHeldAcrossTheProviderCall` alone is not a control on
the double's honesty under this seam.** Nothing was changed to make the plan's prediction come true; the
ordering class was left exactly as it is, and the finding is written down instead.

## The three costed behaviour deltas

These are real changes, all acceptable at the configured values. Recorded so a later reader does not
rediscover them as bugs.

| # | Delta | Cost at configured values |
|---|---|---|
| 1 | The gate slot is held across the whole retry sequence rather than released between attempts | Worst case 3 × 30s timeout + 0.5s + 1.0s backoff ≈ **91.5s**, of which **90s** was already slot-held. The extra occupancy is the **1.5s** of backoff — **1.6%**, over 30 total slots. Not material. |
| 2 | The breaker is consulted once per request rather than once per attempt | A request whose own first attempt trips the breaker over threshold no longer sees `CircuitOpenError` on its retry; it spends its remaining attempts. **Cross-request behaviour — the thing the breaker exists for — is unchanged.** |
| 3 | The charge's database round trip now runs while an LLM concurrency permit is held | Does not create the pool hazard, but moves it inside the permit. `db.pool_size` defaults to **5** with `max_overflow=0`, and a chat POST already holds two connections, so three concurrent posts exhaust the pool **today**. A DB-pool stall would now also consume an LLM permit. Out of scope (T-37.5-05-06, transferred); remains plan `37.5-10`'s finding for the developer. |

## What moved, and what deliberately did not

**`ResiliencePolicy` split into the two things it already was.** `admission()` consults the breaker and
enters `gate.hold()`, yielding an `Admitted`; both admission rejections are raised there, before the
caller's body runs, which is structurally why they never reach the classifier. `ainvoke` keeps the
timeout, the classification and both breaker recordings, and now requires the token.

**`LLMExecutionGate.run` was deleted, not kept.** `hold()` is `run()` with `return await operation()`
replaced by `yield`, and `run` had exactly one caller (`resilience.py:137`) which no longer exists.
Keeping both would be two spellings of one body. `_inflight_slot` is untouched — still the acquire/release
critical section, still the sole raise site of the queue-full rejection, `try/finally` put-back and
`QueueFull` swallow intact. `timed_op` dissolved when `gate.run` left, exactly as the plan predicted.

**The six keeps are all present**, verified mechanically:

```
25:def _is_transient_error   40:class CircuitBreaker   74:class LLMExecutionGate
84:    async def _inflight_slot   110:def _should_retry   115:async def _sleep_if_positive
```

**`attempt()`'s passthrough arm was kept verbatim, although it is now unreachable.** Nothing inside
`attempt()` can raise `QueueFullError` or `CircuitOpenError` any more — the breaker and the gate both
left. `37.5-RESEARCH.md` §1.4's sample code drops the arm; `37.5-PATTERNS.md` pins `resilience.py:138-145`
as "must NOT change" and the plan's action says the classification stays unchanged. **The explicit
must-not-change won**, and the non-negotiable it protects is satisfied either way:
`grep -c 'charge\|QuotaExceededError' src/nativespeaker/api/resilience.py` returns **0**. Flagged here
because a genuinely dead `except` arm is a fair D-12 target for plans 06–09 if they disagree.

**No callback was reinstated.** `grep -rn 'on_admitted' src tests` returns zero lines. The charge is a
plain statement between two plain statements, in a method a reader can see:

```python
        async with self.llm_service.admission() as admitted:
            await self.quota_service.charge(user_id=user_id, evaluated_at=self.evaluated_at)
            ai_message = await self.ask_llm(chat, human_message, admitted)
```

**The double was rewired before it could lie.** `RecordingLLM`'s counter and `"provider_called"` marker
moved from `ainvoke` entry into `_answer`, the actual operation, and the double gained an `admission()`
passthrough. It also gained a `transient_failures` count, which is what makes the exactly-once case
express a real retry rather than a single call.
