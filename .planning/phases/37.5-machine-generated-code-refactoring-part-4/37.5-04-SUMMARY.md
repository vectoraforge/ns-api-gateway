### The one deliberate departure from PATTERNS' and RESEARCH's written form

Both documents give the fix as `env={**os.environ, "PYTHONPATH": str(_TESTS_ROOT)}` — a **replacement**. Shipped instead:

```python
_TESTS_ROOT = Path(__file__).resolve().parent.parent

# `subprocess.run` inherits `os.environ` but not pytest's own `sys.path` insertions.
_SUBPROCESS_PATH = os.pathsep.join(
    entry for entry in (str(_TESTS_ROOT), os.environ.get("PYTHONPATH")) if entry)
```

A bare replacement drops every inherited entry, so the child resolves `nativespeaker` from whatever the editable install points at rather than from the tree the parent is testing. In this worktree that is the **main checkout** — the child would have imported the worktree's `unit.error_tree` against the main checkout's unmodified `errors.py`, and every control observation in this plan would have been measuring the wrong tree while looking green. Verified after the fix, printing `__file__` for both modules from inside the child:

```
.../worktrees/agent-a51421e92de6dbd61/src/nativespeaker/api/errors.py
.../worktrees/agent-a51421e92de6dbd61/tests/unit/error_tree.py
```

Both inside the worktree. In a normal checkout `PYTHONPATH` is unset and the expression reduces to exactly what PATTERNS wrote, so this is strictly a superset of the specified behaviour.
