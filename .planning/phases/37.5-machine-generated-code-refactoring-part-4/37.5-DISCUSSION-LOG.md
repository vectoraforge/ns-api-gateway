## Resilience

The developer recalled wanting to replace hand-rolled rate-limit code with a library already in the
project. Claude verified and corrected the premise:

- The retry loop **was already replaced** with tenacity — commit `2afa7fd`.
- `limits` was **never** in this project; Phase 35 D-05 deleted the engine before it was added.
- What remains hand-rolled is a circuit breaker and a queue gate, not rate limiting.
- **No installed package replaces them** — all 110 packages in `.venv` enumerated; only `tenacity`
  (in use) and `anyio` (no breaker) are relevant.

The developer then asked for the full consequences of deletion, and what "tenacity bounds a failing
call" actually means. Claude corrected its own earlier phrasing: tenacity bounds one request
(~91.5s at the configured values) and nothing across requests; the breaker is the cross-request
control and the two are not substitutes.

| Option | Description | Selected |
|--------|-------------|----------|
| Keep it | Breaker stays; the reasoning goes into AGENTS.md so it isn't re-opened | ✓ |
| Delete it anyway | Accept 91.5s failures, the 503→429 flip, 22 test references removed | |
| Use a library instead | New dependency (purgatory-circuitbreaker / aiobreaker) replacing 32 lines | |

**User's choice:** Keep it (Claude's recommendation)
**Notes:** The first re-ask was dismissed with "In plain English"; the analysis was reissued in
plain language and the decision taken from that. Seventh consecutive phase of deleting machinery —
first time re-examination came back "keep it", on measured numbers. Recorded as D-11.

## Billing

Raised by Claude, not the developer: `charge_quota()` currently runs before the queue and breaker,
so a queue-full 429 and a circuit-open 503 both bill the user. Accepted knowingly by 37.4 D-07 and
placed there by A-03; it is `37.4-REVIEW.md` WR-01, still open. Quota is being rebuilt anyway.

| Option | Description | Selected |
|--------|-------------|----------|
| Fix it | Charge only after the request is admitted, never for a request that didn't reach the provider | ✓ |
| Leave it | Stays as 37.4 accepted it; keeps the phase strictly to the five directives | |

**User's choice:** Fix it (Claude's recommendation)
**Notes:** The seam is the hardest single piece of the phase — the charge must land between
admission and the provider call without reinstating the callback chain 37.4 deleted. Recorded as
D-07 with the invariants that must survive.
