## Deviations from Plan

### Deliberate departures from the plan text

**1. The roadmap entry was not the placeholder the plan describes.** The plan's `read_first` says the Phase 37.5 entry's goal *"was still a placeholder and its requirement line still read as unset when the discussion opened"*, and its acceptance gate greps for `to be planned` / `TBD`. Neither string was in the entry: it already carried a real goal and a real requirement line, written when the phase was inserted. **The gate passed on arrival**, which would have made a no-op look like success.

The work done instead is what the plan's *action* asks for and its gate could not detect: the goal now records **what landed** rather than what was intended — the deleted modules named, the docstring bar's measured 29 → 0, `AuthService` / `QuotaService` / `admission()` named, the suite figure — and the requirement line now carries D-15's verdict, the six-vs-seven count position, FOUND-04's amendment, the three corrected notes and a pointer at the records section. `9/10 plans executed` → `10/10 plans complete — phase verification pending`, and plan 10's checkbox is ticked. Reported rather than silently satisfied, because a gate that passes before the work starts is worth a later reader knowing about.

**2. The two records went into a new `§ Phase 37.5 records` section rather than inside the top blockquote.** The plan says both records live *"under the Phase 37.5 amendment"*. A 21-row table and four multi-paragraph findings inside a `>`-quoted paragraph would be unreadable, and the top of `REQUIREMENTS.md` is where a reader meets the four prior amendments as a compact series. The dated amendment stays a blockquote in the established register and points at the section; the section sits immediately before `## Future Requirements`. Every acceptance grep is file-wide and passes either way.

**3. Three prior notes were corrected, which the plan did not ask for.** Reading the summaries against the file turned up three statements that are now false, and leaving a false note in place is the failure mode this whole plan exists to prevent:
- **FOUND-03** claimed `TestEveryRouteIsAuthenticated` is *"(negative-controlled against an injected undeclared route)"*. It is not, and no such control exists anywhere in the repository — plan `37.5-08` read the class. Corrected with a dated ⚠️ note that states it as **open**.
- **FOUND-01** named `auth/identity.py` as kept and re-hosted. That file no longer exists. Corrected as a pointer, with A-06's ruling on why the four rejections stayed with the query.
- **FOUND-04** said *"The startup totality check survived the loss of the thing it walked"* — true until D-09 moved it into `tests/`. Amended.

All three are **appended** dated corrections in the 37.1–37.4 style. No prior amendment line was rewritten or deleted.

**4. `errors.py` is 397 lines, not the 399 plan 04 measured.** Plan 06's `src/` sweep took two more. The amendment states the measured 397 against 37.4 A-01's projection of ~250.

## The three items handed over as open, recorded as open

These were the ones most at risk of being written up as accomplishments. Each is recorded in `REQUIREMENTS.md` § Phase 37.5 records **and** in `STATE.md`'s pending-todo or blocker sections, with the cost of closing it:

1. **`tables/__init__.py` still re-exports the `schemas/` names** — eleven of them. `37.5-PATTERNS.md` lists this as this phase's layering work; no plan claimed it and none did it. It is layering, not prose, so no sweep would have reached it.
2. **`tests/unit/test_app_wiring.py`'s every-route class has no negative control against an injected undeclared route**, and three vacuous cases stand in `test_quota_resolver.py`. Reported by plan 08, outside plan 09's scope, not fixed. Also the subject of the FOUND-03 correction above.
3. **`tests/schema/conftest.py:56` still calls the database "a crud"** — `"refusing to interpolate {name!r} as a crud identifier"`. Left by plan 09 because it is a string literal, not prose: changing it would have changed the AST under that plan's no-logic-change proof. One-line fix for a later phase.

## The coverage loss that was NOT restored, recorded as a loss

Plan 07 cut two security cases that no survivor covered — `test_rejects_token_signed_with_different_key` and `test_the_module_logs_nothing` — and the developer **restored both** in commit `658895e`. Verified present and passing at `tests/unit/test_jwt_security.py:109` and `tests/unit/test_challenge_ids.py:332`.

Plan 06 separately cut **`test_foundation_calls_no_adapter_method_anywhere_in_src`**, and it was **not** restored. `grep -rn` over `tests/` returns nothing for it. It was the only enforcement in the repository that `get_user_provider_data` is named nowhere in `src/` except `auth/adapters.py` and `auth/firebase.py` — an **architectural** guarantee where its eight deleted siblings carried language guarantees. `grep -rl get_user_provider_data src/` returns exactly those two files today, so the property holds; **nothing now fails if a third file starts calling the adapter.** Restoring cases 9–12 as a small class costs about 25 lines. Recorded as a real, still-open coverage loss in both `REQUIREMENTS.md` and `STATE.md`'s blockers, not glossed.

## The A-16 count position, stated rather than reconciled away

`SHARED-INVARIANTS.md` § Rate limits mandates the `limits` library and this project has none — re-verified this phase (`git log -S'limits' -- pyproject.toml` empty; no `limits` among the 110 distributions in `.venv`). That divergence is **already on record**, at `REQUIREMENTS.md:48` and under FOUND-06, as a Phase 35 D-05 **override** rather than as one of the counted flagged conflicts.

**The count therefore reads six and the known-divergence set is seven, and the amendment says so in both places** — in the new amendment and in a clause added to the count paragraph itself. It was not reconciled by re-filing the `limits` item as a seventh conflict, because that would rewrite Phase 35's own decision about its own scope. A reader auditing divergences is told to read the count **and** the override.

It is also recorded as the reason the developer's opening expectation in this phase's discussion was correct: the specification really does mandate a library this project deleted before it was ever added. They were reading the spec, not misremembering — which is precisely why the resilience question kept coming back, and why D-11's record now says so.
