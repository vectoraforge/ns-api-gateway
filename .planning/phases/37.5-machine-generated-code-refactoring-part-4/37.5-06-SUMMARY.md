## Findings

**1. A comment in `tables/identities.py` was factually wrong, not merely stale.** It claimed `core.auth_challenges` stores a keyed hash of the external subject. `migrations/20260818_01_initial-release.sql:381,383` declares `preauth_issuer TEXT` and `preauth_subject TEXT`, and `tables/auth.py` documents both as plaintext on purpose ("The verified subject in plaintext, cleared by consumption"). The claim was deleted rather than corrected: `external_identities.issuer`/`subject` need no comment, and the challenge table already documents its own columns. **No behaviour is affected — the storage was always plaintext — but anyone who read that line believed the subject was hashed in one of the two tables holding it.** Worth a look from whoever decides whether plaintext there is intended.

**2. `auth/adapters.py`'s module docstring no longer carries the three `SHARED-INVARIANTS.md` rules.** The plan directs deleting `TestSharedAdapterRules` on the grounds that the rules are `SHARED-INVARIANTS.md`'s and asserting a docstring quotes them tests prose. Once the test was gone, the rules in the docstring described what implementations elsewhere must do, which is what `AGENTS.md` forbids a docstring from carrying. They were dropped. They remain in `/home/init/native-speaker/specs/auth-refactor-phases/SHARED-INVARIANTS.md`, which is their home, and `auth/firebase.py` — the one implementation — still carries its own prohibitions in its module docstring.

**3. `firebase.py`'s module docstring is pinned by a test, like `adapters.py`'s was.** `test_firebase_adapter.py::TestTheClassifierRecordsItsProhibitions` asserts five phrases in it. The 8-line docstring was compressed to exactly 3 lines with all five phrases intact and unbroken by a line wrap, so the test passes untouched. **No test was weakened to let the sweep land.** Whether a docstring should carry prohibitions at all is the same question raised by finding 2; it is left open here because answering it means deleting five assertions, which belongs to the `tests/` sweep plans, not to this one.

**4. `tables/__init__.py` still re-exports four `schemas/` names** (`AnalyzeInput`, `AnalyzeResponse`, `FollowUpInput`, `FollowUpResponse`, `Issue`, `RejectResponse`, and the four `schemas/api.py` models). `37.5-PATTERNS.md`'s Package facade entry lists `tables/__init__.py (−4 schema names)` as work for this phase. It is a layering matter, not a prose matter, so this sweep left it. Not done by any wave so far.
