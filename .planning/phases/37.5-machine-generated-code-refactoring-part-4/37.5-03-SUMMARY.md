## What moved, and what deliberately did not

**`services/quota.py::QuotaService`** takes the session factory in its constructor and exposes exactly one public method. `grep -c 'async def'` returns **1** — the two halves really are one method and not two where one calls the other.

The short session survives as the property it was: `charge` opens it from the factory *inside itself*, commits on success and rolls back on any exception. It is not the request-scoped session and was not replaced by one. `SHARED-INVARIANTS.md` § Locks depends on this, and `test_quota_seam.py`'s `TestNoSessionIsHeldAcrossTheProviderCall` still observes the exact event order `["session_opened", "session_committed", "session_closed", "provider_called"]` — with the *real* charge running, not a stub.

**Every fail-closed branch moved unchanged**, with its log event and its closed-set `branch` label: `no_effective_grant`, `multiple_effective_grants`, `missing_usage_row`, `unknown_tier`, `allowance_exhausted`. No label is an id and none is a raw path. The rollover still runs before the allowance comparison and inside the same transaction as the charge; `updated_at` is still stamped from the request's captured instant and never from a clock read; the grant rows are still locked before the usage row on every path.

**`crud/grants.py` was not opened for writing.** `git diff --stat 0b2f862 -- src/nativespeaker/api/crud/grants.py` is empty — the file is byte-identical to its pre-phase state and `GrantsDB` keeps its name. The plan's precondition said that if this plan found itself editing that file, the plan was wrong; it did not.

**`ChatService` lost `session_factory` entirely.** Rather than keeping the factory on the chat service and handing it to the charge, the service now holds the `QuotaService` and calls `self.quota_service.charge(...)`. There is one owner of the short session instead of two holders of the factory. The two call sites stay at the same two visible points, in the same order relative to the four validation rejections — this plan moved the call's *owner*, not its position. Plan `37.5-05` owns the position.

**`get_quota_service` sits beside its two siblings** in `app/dependencies.py`, declared above `get_chat_service` because `Depends()` defaults are evaluated at definition time.

## Deviations from Plan

### Deliberate departures from the plan text

**1. Tasks 1 and 2 landed as one RED/GREEN pair, not as two sequential task commits.**

Task 1's acceptance criteria include "`.venv/bin/python -m pytest -q` passes" and "`grep -rn 'api\.quota\b' src tests` returns zero lines". Both range over `tests/`, and both are unsatisfiable while task 2 is outstanding: `test_quota_resolver.py` imports `consume_quota` at module scope, so deleting `quota.py` makes that file fail to *collect*, and `conftest.py`/`test_quota_seam.py` monkeypatch `chats_service.charge_quota`, an attribute that ceases to exist. The two tasks are one atomic change at the "suite is green" level.

The only thing that could have separated them is a re-export shim, and a shim is precisely what plan 02's Control 2 exists to forbid and what PROJECT.md's global deletions rule out ("no compatibility shims, no deprecated aliases").

So the work was split on the boundary that *is* atomic. Task 1 is `tdd="true"` with a `<behavior>` block, which is the executor's TDD contract, and RED must precede GREEN:

- **RED (`ac26f50`)** re-points the three test files at `QuotaService.charge`. Observably red: `ImportError: cannot import name 'QuotaService' from 'nativespeaker.api.services'`, raised at conftest import so the whole unit tree fails to collect.
- **GREEN (`25c808b`)** is the entire source move in one commit, so the plan's real requirement — do not split the *move* — is met.

Both tasks' acceptance criteria are evaluated against the final tree and all of them hold.

**2. `test_app_wiring.py` was read and left unchanged.** The plan says to update it "if it enumerates DI accessors". It does not — it enumerates *route* dependencies (`get_identity`, `get_linked_identity`) to assert every route is authenticated, and `get_quota_service` is not a route dependency. Editing it would have added a number with nothing behind it. It is listed in `files_modified` and is the one file there with a zero-line diff.

**3. The module docstring moved verbatim, including its second sentence.** `37.5-PATTERNS.md` flags "A failed provider call is not refunded" as a D-12 sweep target. D-12's sweep is plans 06-09's work, not this plan's; the docstring is 2 lines and already under the three-line bar; and `test_quota_seam.py:357` cites that sentence by name. Cutting it here would have created a stale citation inside a test class this plan is explicitly forbidden to touch.
