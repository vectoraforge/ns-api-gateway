    Append three sections to `AGENTS.md`, below the existing "Comments and docstrings" section, in the

    section states, and no sentence explains history.

    **Section "Package layout" (D-01).** One home per file, decided by what the file is and not by
    which feature it serves: `services/` business logic, orchestration, rules and transaction
    boundaries; `crud/` database access; `schemas/` Pydantic request and response bodies and domain
    value types; `tables/` SQLModel tables and the enums mirroring database types; `routers/` HTTP
    handlers, `Depends()` only; `auth/` external-SDK seams only (per D-02: `adapters.py`,
    `firebase.py`, `jwt_verifier.py`).

    Then four one-line exceptions, each stated as a rule and not as a story — write them or a future
    agent makes the move the binding specification forbids:
    1. `errors.py` owns the client-visible error response shape, the statuses, the copy and the
       handlers. Nothing about errors moves to `schemas/`. Ground: `SHARED-INVARIANTS.md`
       § Errors — one shared registry (per A-07 / P-08).
    2. `BoundedReason` stays in `auth/jwt_verifier.py`. Moving it to `schemas/` creates an import
       cycle, because `errors.py` imports it.
    3. `commit()` and `rollback()` are transaction boundaries and therefore business logic; they live
       in `services/`, not in `crud/`.
    4. A fail-closed read may raise its own rejection, so the rejection stays with the query in
       `crud/` (per A-06).

    **Section "Function shape" (D-08).** Delete a function that is only a step; keep one that states a
    rule or marks a boundary, where a boundary is a lock, a transaction, or a callable a library
    requires. The check: inline it, then read the call site — if the call site now needs a comment to
    explain what the code does, the name was carrying meaning and the function stays. Add one line for
    the case Pitfall 5 names: a recursive function is never a step, because it cannot be inlined.

    **Section "Resilience" (D-11).** State that `CircuitBreaker` and `LLMExecutionGate` in
    `resilience.py` are deliberate and are not awaiting replacement, and give only the arguments that
    survived A-02's correction: the retry loop is already `tenacity`; `tenacity` bounds one request
    (three attempts at a 30s timeout plus backoff, about 91.5s) and bounds nothing across requests, so
    without the breaker every request during a provider outage pays that from scratch; nothing
    installed replaces a circuit breaker, so finishing the idea means a new dependency; and without
    the breaker a client is told to retry in 2 seconds when the provider is down.

    Do NOT write the status-flip claim. Per A-02 both admission rejections are 503
    `service_unavailable` today — `QueueFullError` subclasses `ServiceUnavailable` and declares no
    status of its own — and a note carrying a wrong fact will not survive its first re-examination,
    which is this note's only job. Add one line recording that `limits` is mandated by
    `SHARED-INVARIANTS.md` § Rate limits and was overridden by Phase 35 D-05, so the reader who
    arrives from the specification finds the answer here rather than re-opening the question.
  </action>
