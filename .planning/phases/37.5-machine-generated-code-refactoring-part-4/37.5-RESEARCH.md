### P-01 — `QueueFullError` answers **503**, not 429. D-07 and D-11 both say 429.

`37.5-CONTEXT.md` D-07 reads *"a queue-full 429 and a circuit-open 503 both bill"*, and D-11 reads
*"the client-visible answer flips from 503 with `Retry-After: 60` to 429 with `Retry-After: 2`"*.

Both are wrong. `errors.py:342` declares:

```
class QueueFullError(ServiceUnavailable):
    """The LLM queue is full."""
```

`ServiceUnavailable` (`errors.py:209-214`) declares `status = 503`, `code = "service_unavailable"`.
`QueueFullError` declares neither of its own, so it inherits both. [VERIFIED: src/nativespeaker/api/errors.py:209-214, 342-350]

**Consequence for D-07:** nothing — the billing defect is real either way, and the fix is unchanged.

**Consequence for D-11:** its second cost argument is void. Deleting the breaker would *not* flip the
status or the code; both arms are 503 `service_unavailable`. The only thing that changes is the
`Retry-After` value (60 → 2), because `QueueFullError.extra_headers()` (`:349`) and
`CircuitOpenError.extra_headers()` (`:360`) both emit `Retry-After` from their own constructor
argument. D-11's *"it reads as 'you are rate-limited' when the truth is the provider is down"* is not
a property of this code. The decision (keep the breaker) still stands on the surviving argument — wrong
retry advice, and no cross-request bound — but D-11 explicitly says the *reasoning* is what stops the
question being re-opened a fourth time, so the reasoning must be corrected in the record.

### P-02 — the 429-not-503 property does not live at `resilience.py:73-79`.

`:73-79` is `class LLMExecutionGate:` and the first six lines of its `__init__`. [VERIFIED: src/nativespeaker/api/resilience.py:73-79]

The property D-07 means — *a quota rejection must never read to a client as a provider outage* — is
defended in two places, neither of which is `:73-79`:

1. **Structurally**, by `charge_quota` being called at `services/chats.py:93` and `:117`, which is
   entirely outside `ResiliencePolicy.ainvoke`. The test that pins it says so verbatim:
   `tests/unit/test_quota_seam.py:242-252 test_the_429_never_degrades_into_a_503` —
   *"Structural: the charge is raised outside the resilience policy, so the classifier never sees it."*
2. **By the passthrough list** at `resilience.py:138-139`:
   ```
   except (QueueFullError, CircuitOpenError):
       raise
   except Exception as e:
       await self._circuit_breaker.record_failure()
       if _is_transient_error(e):
           raise TransientLLMError(str(e)) from e
   ```

   `QuotaExceededError` is **not** in that list. Anything raised inside `attempt()` that is not
   `QueueFullError` or `CircuitOpenError` becomes a 503 *and* records a breaker failure.
   [VERIFIED: src/nativespeaker/api/resilience.py:138-145]

**This is the single most important fact in the phase.** Any D-07 seam that places the charge inside
`attempt()` silently converts every exhausted-allowance 429 into a 503 `service_unavailable`, and lets
one user's exhausted allowance count five times toward opening the circuit breaker for every other
caller. Two existing tests would catch it —
`test_quota_seam.py:242 test_the_429_never_degrades_into_a_503` and
`:264 test_the_circuit_breaker_records_no_failure` — but only because they exist; the planner must not
rely on that and must keep both, adapted, as the seam's negative controls.

### P-03 — tenacity retries `attempt()` up to three times, so a charge inside `attempt()` charges three times.

`ResiliencePolicy.ainvoke` builds `AsyncRetrying(stop=stop_after_attempt(self._retry_max_attempts), …)`
and calls `await retrying(attempt)` (`resilience.py:149-160`). `retry_max_attempts` defaults to `3`
(`config.py:38`). The retry predicate is `_should_retry` = `isinstance(exc, TransientLLMError)`
(`resilience.py:103-105`). [VERIFIED: src/nativespeaker/api/resilience.py:103-105, 149-160; src/nativespeaker/api/config.py:38]

So on a transient provider failure the body of `attempt()` runs three times. The gate slot is
**acquired and released once per attempt** — `self._gate.run(timed_op)` is inside `attempt()`
(`:137`), not outside it. Any charge placed after `gate.run` admits and before `operation()` runs is
therefore executed once per attempt: **a transient 503 costs the user three credits, not one.**

The context file does not address this. It is the highest-risk detail in D-07 and it is what
eliminates the otherwise-attractive "charge at the narrowest point" seam (§3.3, Option C).

### 1.2 Option A — probe-then-charge (smallest diff). **Rejected.**

```python
# resilience.py

    """Raise if the breaker is open or no slot is free. Advisory only: nothing is reserved."""
    await self._circuit_breaker.before_call()
    if self._gate.is_saturated():
```

| C1 double-charge | C2 429-not-503 | C3 no callback | C4 no lock across call |
|---|---|---|---|
| ✅ once — outside the retry loop | ✅ raised outside `ainvoke` | ✅ | ✅ |

**Why it is rejected anyway:** it is a TOCTOU. Between `check_admission()` returning and
`gate.run()` actually acquiring a slot inside `attempt()`, another coroutine can take the last slot,
and the user is charged for a queue-full. The window is small but the property D-07 asks for is
*"never charged for a request that did not reach the provider"*, and this seam delivers *"almost
never"*. It also consults the breaker twice per request and reserves nothing, so the slot count and
the charge count can diverge under load. This project's culture — see the `_undeclared` fail-closed
comments, the `MultipleEffectiveGrantsError` tripwire, `resolve_identity`'s outer join — is to make
invariants structural, not probabilistic. List it in the plan and reject it on the record.

### 1.3 Option C — charge inside `attempt()`, guarded. **Rejected.**

The literal reading of *"after the gate and breaker admit but before the provider call"* puts the
charge inside `attempt()`, immediately before `timed_op()`. To survive C1 and C2 it needs three
patches: a `nonlocal charged` one-shot flag, `QuotaExceededError` added to the passthrough tuple at
`:138`, and some way for `resilience.py` to reach `charge_quota`.

| C1 | C2 | C3 | C4 |
|---|---|---|---|
| ⚠️ only via a `nonlocal` flag — hidden state | ⚠️ only by widening the passthrough tuple | ❌ needs a callback, or an import | ✅ |

**Why it is rejected:** the only two ways to get `charge_quota` into `attempt()` are (a) pass it in —
the `on_admitted` callback D-07 forbids and P-04 shows the review proposed; or (b) `import charge_quota`
inside `resilience.py`, which inverts D-01's own layering (infrastructure importing a service) and
would make `resilience.py` a quota-aware module. Both are worse than the problem. The `nonlocal`
one-shot flag is also precisely the "hidden control flow" register that 37.1–37.4 have spent four
phases deleting.

### 1.4 Option B — an explicit `admission()` context manager. **RECOMMENDED.**

Split `ResiliencePolicy` into the two things it already is: *admission* (breaker + slot) and
*execution* (timeout + retry + classification). Admission becomes an `@asynccontextmanager` the
service enters explicitly, so the charge is a plain statement between two other plain statements.

```python
# resilience.py

class LLMExecutionGate:
    @asynccontextmanager
    async def hold(self):
        """Hold an in-flight slot and a concurrency permit, or raise `QueueFullError`."""
        async with self._inflight_slot():
            async with self._semaphore:
                yield


@dataclass(frozen=True, slots=True)
class Admitted:
    """Proof that the breaker was closed and a slot is held. Only `ResiliencePolicy.admission` mints one."""


class ResiliencePolicy:

    @asynccontextmanager
    async def admission(self):
        """Admit one request: breaker consulted, slot held. Raises before the caller's body runs."""
        await self._circuit_breaker.before_call()
        async with self._gate.hold():
            yield Admitted()

    async def ainvoke(self, operation: Callable[[], Awaitable], admitted: Admitted) -> Any:
        """Run `operation` under the timeout and the retry policy. The caller already holds admission."""

        async def attempt() -> Any:
            try:
                result = await asyncio.wait_for(operation(), timeout=self._timeout_seconds)
            except Exception as e:
                await self._circuit_breaker.record_failure()
                if _is_transient_error(e):
                    raise TransientLLMError(str(e)) from e
                raise PermanentLLMError(str(e)) from e
            await self._circuit_breaker.record_success()
            return result

        retrying = AsyncRetrying(...)          # unchanged
        return await retrying(attempt)
```

|---|---|---|---|

**Why the `Admitted` token and not a bare split.** A bare split leaves an unenforced contract: nothing
stops a future caller invoking `llm_service.ainvoke(...)` without holding admission, which bypasses the
gate and the breaker entirely — an unbounded fan-out to the provider, failing *open*. Making `admitted`
a required positional parameter on both `ainvoke` signatures turns the contract into a `TypeError` at
the call site and a `ty` diagnostic in CI. `ty` is already in the venv. The token carries no data; it
exists to be un-forgeable in the ordinary case. This is the same move `_family`/`class_answering_status`
make elsewhere: the structure is the guarantee.

If the developer finds the token too clever, the fallback is a `ContextVar[bool]` set by `admission()`
and asserted at the top of `ainvoke`. It is equivalent, cheaper to thread, and weaker (a runtime raise,
not a type error). **Do not ship the bare split with no enforcement.**

### 1.5 Behaviour deltas Option B introduces, costed

Three things genuinely change. All three are acceptable at the configured values; the plan should
record them so a later reader does not rediscover them as bugs.

1. **The slot is now held across the whole retry sequence, not per attempt.** Today `gate.run` is inside
   `attempt()` (`:137`), so a slot is released between attempts. Under Option B it is held for the
   full sequence. Cost at configured values: the worst-case sequence is 3 × 30s timeout + 0.5s + 1.0s
   backoff ≈ **91.5s**, of which **90s** was already slot-held. The extra occupancy is the 1.5s of
   backoff — **1.6%**. With 30 total slots this is not material. (This is the same arithmetic D-11 ran
   for a different question, and it lands on the other side of it.)
2. **The breaker is consulted once per request instead of once per attempt.** A request whose first
   attempt trips the breaker over threshold no longer sees `CircuitOpenError` on its own retry; it
   spends its remaining attempts. Cross-request behaviour — the thing the breaker exists for — is
   unchanged. `test_resilience_retry.py:174 test_circuit_open_propagates_unwrapped_and_is_not_retried`
   must move to exercising `admission()` rather than `ainvoke()`.
3. **The charge's DB round trip now happens while an LLM concurrency permit is held.** This is a real
   coupling, and it interacts with a **pre-existing** capacity hazard the planner should see:
   `app/lifespan.py:38` builds the engine with `pool_size=config.db.pool_size` (default **5**) and
   `max_overflow=0`. A `POST /chats` already holds `get_db`'s connection *and* opens a second one for
   `charge_quota`'s short session — **2 connections per in-flight chat request**. At 3 concurrent chat
   POSTs the pool is exhausted and the third blocks. That is true **today**; Option B does not create
   it, but it moves the blocking inside the LLM semaphore, so a DB-pool stall would now also consume
   an LLM permit. [VERIFIED: src/nativespeaker/api/app/lifespan.py:38-40; src/nativespeaker/api/config.py:25; src/nativespeaker/api/app/dependencies.py:50, 80-81] See **OQ-1**.

**Recommended: a new `tests/unit/error_tree.py`** — an importable helper, not a `test_*.py` file and

they are no longer private to `errors.py`), plus a thin `assert_tree_total()` that raises `RuntimeError`

**The design constraint the context file misses:** `subprocess.run([sys.executable, "-c", …])` inherits
`os.environ` but not pytest's `sys.path` insertions. `pyproject.toml:54` sets `pythonpath = ["."]` for
pytest only. The eight subprocess snippets across two files must be given an explicit environment:

```python
_TESTS_ROOT = Path(__file__).resolve().parent.parent      # .../tests

def _fresh_interpreter(snippet: str) -> subprocess.CompletedProcess:
    """Run a check in its own process, so a synthetic subclass cannot outlive it."""
    return subprocess.run([sys.executable, "-c", snippet], capture_output=True, text=True,
                          env={**os.environ, "PYTHONPATH": str(_TESTS_ROOT)})
```

**Negative control for the rehost itself:** `test_error_registry.py:160
test_the_same_checks_report_nothing_when_no_synthetic_class_exists` already asserts
`returncode == 0 and stderr == ""` on a clean run. It is the only thing standing between "the checker
found no defect" and "the snippet died on an `ImportError` and the case read the non-zero exit as a
pass". **It must be executed first in the rehost and must fail before the `PYTHONPATH` fix is applied.**
If it passes both before and after, the fix was not needed and the rehost is wrong somewhere else.

## Common Pitfalls

### Pitfall 1: charging inside `attempt()`
**What goes wrong:** three credits per transient failure, and every exhausted allowance answers 503
`service_unavailable` while counting toward opening the breaker for all callers.
**Why it happens:** the phrase "after the gate and breaker admit but before the provider call"
describes a point that is literally inside `attempt()`.
**How to avoid:** §1.4. **Warning signs:** `charge_quota` appears anywhere in `resilience.py`, or
`QuotaExceededError` appears in the `except (…)` tuple at `resilience.py:138`.

### Pitfall 2: a test double whose event marker moves
**What goes wrong:** `RecordingLLM.ainvoke` marks `"provider_called"` on entry (`test_quota_seam.py:76-77`).
Under Option B that fires before admission, so `TestNoSessionIsHeldAcrossTheProviderCall`'s ordering
assertion passes while proving nothing.
**How to avoid:** move the marker into `_answer`. **Warning signs:** the suite stays green while the
seam changes — the exact pattern `37.4-VERIFICATION.md` recorded seven times.

### Pitfall 3: leaving the tree unimportable between commits
**What goes wrong:** `d466a4b` did this for days (37.4 A-00).
**How to avoid:** §3.4 — never split a module move across two commits; end every wave with
`python -c "import nativespeaker.api.app.main"` and a green `pytest`.
**Warning signs:** a commit that adds `crud/identities.py` without deleting `auth/identity.py`.

### Pitfall 4: forgetting `tests/schema/`'s two import lines
**What goes wrong:** `tests/schema/test_create_atomicity.py:12-14` and `test_create_race.py:13-14`
import `Identity` and `create_user`. They are deselected by default (`-m 'not schema'`), so the suite
stays **green** while the schema suite cannot collect.
**How to avoid:** run `pytest -m schema --collect-only` as an explicit verification step in the wave
that moves those symbols. **Warning signs:** none in the default run — that is the point.

### Pitfall 5: `_family` looks single-caller after D-09
**What goes wrong:** it becomes a one-call-site private function and a subsequent D-08 reading inlines
