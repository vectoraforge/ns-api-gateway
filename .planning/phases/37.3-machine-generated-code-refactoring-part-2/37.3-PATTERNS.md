## Pattern Assignments

### `src/nativespeaker/api/auth/exceptions.py` (new — model, request-response)

**Analog:** `src/nativespeaker/api/errors.py` — the `ServiceError` hierarchy. This is not a loose
analogy: D-01 is literally "do what `ServiceError` does, with a different base and its own handler."

**Base-class pattern to copy** (`errors.py:229-236`) — note the comment above the class; the planner
should carry an equivalent one-liner, in the same register:

```python
# One `error_class` per subclass, so a status and a code can never be named in disagreement.
class ServiceError(Exception):
    """Base exception for service layer errors."""
    error_class: ErrorClass = INTERNAL_ERROR
    log_level: int | None = None

    def extra_headers(self) -> dict[str, str] | None:
        return None
```

`AuthRejected` copies the `error_class: ErrorClass = INTERNAL_ERROR` class-attribute idiom exactly
(the fail-closed default is the security control named in RESEARCH's threat table). It does **not**
subclass `ServiceError`. `log_fields()` is the `extra_headers()` of this family: a base returning `{}`,
subclasses overriding — same shape, same position in the class body.

**Subclass with scalars captured in `__init__`** (`errors.py:394-397`, the tightest example):

```python
class UnknownTierError(ServiceError):
    """A grant whose `tier_id` has no `core.access_tiers` row -- maps to 500."""
    # A foreign key makes this unreachable; the silent readings are a wrong 429 or a free service.
    error_class = INTERNAL_ERROR
    log_level = logging.ERROR

    def __init__(self, tier_id: str, grant_id: UUID):
        self.tier_id = tier_id
        self.grant_id = grant_id
        super().__init__(f"Grant {grant_id} references tier {tier_id!r}, which has no row")
```

Every stored attribute here is a scalar (`str`, `UUID`). **That is already the house rule** — the
whole 170-line hierarchy stores nothing but `str`, `int`, `UUID`, `list[str]`. RESEARCH's Pitfall 1
("carry only plain scalars, never ORM instances") is therefore not a new discipline to introduce; it
is the existing convention, and the planner should state it as *conformance*, not as a new rule.

**Subclass with no `__init__` at all** (`errors.py:312-313`) — the shape most of the 13 new classes take:

```python
class QuotaExceededError(ServiceError):
    error_class = QUOTA_EXCEEDED
```

**Two-level hierarchy where the middle class carries the metadata** (`errors.py:249-264`) — this is
the precedent for D-14's `ChallengeRejected` base with five silent subclasses:

```python
class AnalysisError(ServiceError):
    """Raised when phrase analysis fails"""
    error_class = INTERNAL_ERROR
    log_level = logging.ERROR


class TransientLLMError(AnalysisError):
    """All retries failed on a transient LLM error; `__cause__` holds the last one."""
    error_class = SERVICE_UNAVAILABLE
    log_level = None
```

Note the existing pair *does* re-declare `error_class` on the child. D-14 requires the opposite —
the five challenge subclasses must **not** re-declare it, so the anti-oracle property is structural.
That is a deliberate divergence from the analog and deserves a comment at the base class.

**Error-class constants to import** — all already registered, none change (`errors.py:65-178`):
`AUTH_REQUIRED` (401), `PREAUTH_IDENTITY_NOT_ALLOWED` (403), `ACCOUNT_UNAVAILABLE` (403),
`CHALLENGE_REQUIRED` (409), `IDENTITY_ALREADY_LINKED` (409), `OPERATION_NOT_ALLOWED` (403),
`VERIFICATION_TEMPORARILY_UNAVAILABLE` (503), `INTERNAL_ERROR` (500).

### `src/nativespeaker/api/app/errors.py` (middleware — request-response)

**Analog:** `service_error_handler` in the same file, `:22-29`.

**Handler pattern** — the `assert isinstance` narrowing, the `Exception`-typed parameter (Starlette's
signature), and `return error_response(...)` as the single exit are all mandatory conventions here:

```python
async def service_error_handler(_: Request, exc: Exception) -> JSONResponse:
    assert isinstance(exc, ServiceError)
    if exc.log_level is not None:
        # structlog's filtering logger indexes the five standard levels and raises on any other.
        level = exc.log_level if exc.log_level in _LOGGABLE else logging.ERROR
        logger.log(level, str(exc), error_type=type(exc).__name__,
                   exc_info=(exc.log_level >= logging.ERROR))
    return error_response(exc.error_class, headers=exc.extra_headers())
```

The new handler differs in exactly two ways: it takes `request: Request` rather than `_: Request`
(it needs `request.scope["route"].path`), and it logs unconditionally at WARNING with a derived
event name. Everything else — module-level `logger = structlog.get_logger()` at `:17`, the
`JSONResponse` return type, `error_response` as the only body builder — is copied verbatim.

**Handler that reads a table and logs a miss** (`:37-46`) — the closest precedent for a handler that
does real work before responding, and the model for the `route`-lookup style:

```python
async def http_exception_handler(_: Request, exc: Exception) -> JSONResponse:
    """Answer a framework-raised HTTPException with the one class that status declares."""
    # STATUS_TO_CLASS is closed, so a miss is a registry hole and is logged rather than defaulted.
    assert isinstance(exc, StarletteHTTPException)
    error_class = STATUS_TO_CLASS.get(exc.status_code)
    if error_class is None:
        logger.error("error_registry_unmapped_status", unmapped_status=exc.status_code)
        return error_response(INTERNAL_ERROR)
```

**Registration pattern** (`:54-58`) — one flat function, one line per handler, `Exception` last:

```python
def register_exception_handlers(app: FastAPI) -> None:
    app.add_exception_handler(ServiceError, service_error_handler)
    app.add_exception_handler(RequestValidationError, validation_error_handler)
    app.add_exception_handler(StarletteHTTPException, http_exception_handler)
    app.add_exception_handler(Exception, generic_error_handler)
```

`camel_to_snake` lives in this module per RESEARCH (module-private, beside `_LOGGABLE` at `:19`).

**Structured-log field convention to preserve** — the two existing rejection log sites both pass
`route=` as a keyword and never pass the handle (`routers/auth.py:58-60`, `dependencies.py:87`):

```python
logger.warning("auth_rejected", result=str(result), bounded_reason=reason, route=route)
```

The new handler reproduces `route=` and `bounded_reason=`; `result=` is what D-02 replaces with the
event name itself.

**Analog:** itself. `_reject` at `:81-88` is the pattern being *inlined*, and its two properties must
be preserved at the new raise sites in `get_request_context`:

```python
def _reject(error_class: ErrorClass, result: AuthEventResult,
            bounded_reason: BoundedReason | None, route: str) -> NoReturn:
    """Record the rejection, then raise it; `NoReturn` lets each call site stand as a bare statement."""
    # The structured security log is the only record a rejection leaves.
    # `route` is the path template, never the caller's raw path.
    reason = None if bounded_reason is None else str(bounded_reason)
```

path. Dropped: the logging (moves to the handler, D-06) and the `NoReturn` helper itself. Call sites


**`BoundedReason`** (`auth/wire.py:8-18`) is a `StrEnum` and is a plain scalar — safe to carry on an

### `src/nativespeaker/api/auth/firebase.py` (service — external I/O, request-response)

**Analog:** itself. Two ordering constraints in `_read` (`:80-107`) must survive; they are explained
in the existing comments and the comments should survive with them:

```python
    @staticmethod
    def _read(app: firebase_admin.App, subject: str) -> ProviderDataResult:
        """The synchronous body, run off the event loop. Everything that can raise happens here."""
        try:
            record = auth.get_user(subject, app=app)
            # A lazy property that raises on an empty rawId, so it is materialized inside this try.
            entries = tuple(ProviderDataEntry(provider_id=entry.provider_id, uid=entry.uid)
                            for entry in record.provider_data)
            email = record.email  # read here so every field comes off this one getUser response
            email_verified = record.email_verified
        except auth.UserNotFoundError:
            # Definitive, spends no retry budget, and listed before the FirebaseError it subclasses.
            logger.info("firebase_get_user_not_found")
            return ProviderDataResult(ProviderDataOutcome.user_not_found)
        except ValueError as error:
            # A malformed or indeterminate response, which is retryable rather than definitive.
            logger.warning("firebase_provider_data_malformed", detail=str(error))
            return ProviderDataResult(ProviderDataOutcome.retryable_failure)
        except google.auth.exceptions.GoogleAuthError as error:
            # Not a FirebaseError and raised before the request is sent; unhandled it means 500, not 503.
            logger.warning("firebase_credential_unavailable", detail=str(error))
            return ProviderDataResult(ProviderDataOutcome.retryable_failure)
        except exceptions.FirebaseError as error:
            # Outage or integration-auth failure; the provider's text is for the log, never a body.
            logger.warning("firebase_get_user_failed", code=error.code, detail=str(error))
            return ProviderDataResult(ProviderDataOutcome.retryable_failure)
```

Each `return` becomes a `raise` of the matching class; the `except` **order**, the four log event
names, and `detail=str(error)` / `code=error.code` field names all stay. Provider text goes to the
log and never to a body — that comment at `:103` is a security note, keep it.

### `src/nativespeaker/api/routers/auth.py` (controller — request-response)

**Analog:** itself. The three collapsing helpers, quoted so the planner can see what the try/except
must reproduce.

**The precedence block — D-16 says this order *is* the spec** (`:96-123`):

```python
    """Create the account. The order of the rejections below is the rejection precedence."""
    # No rejection before the claim consumes anything, so a wrong presenter cannot burn a live challenge.
    challenge = await challenge_store.locate(session, challenge_id)
    if challenge is None:
        # A definitive no-row. A lookup outage raises out of `locate` instead of answering "no such challenge".
        return await _challenge_rejected(session, result=AuthEventResult.challenge_not_found)
    ...
    if not await challenge_store.claim(session, ...):
        # `claimed_at` distinguishes the two losses; the claim's WHERE is the only expiry evaluation anywhere.
        await session.refresh(challenge)
        lost = (AuthEventResult.challenge_expired if challenge.claimed_at is None
                else AuthEventResult.challenge_consumed)
        return await _challenge_rejected(session, result=lost)

    # Deliberate commit: an uncommitted claim across the provider call would let a second attempt win the challenge.
```

```python
                               stage: str, challenge_store, cause: str | None = None) -> Response:
    """Reject after the provider read, consuming the challenge so the handle cannot be re-presented."""

    logger.warning("create_user_lookup_rejected", stage=stage, result=str(result), **bounded)

                                             challenge_id=challenge.challenge_id,
                                             claim_attempt_id=context.attempt_id,
                                             now=context.evaluated_at)

    return error_response(error_class)
```

### Class-attribute error metadata

**Source:** `src/nativespeaker/api/errors.py:229-233`
**Apply to:** `auth/exceptions.py` (every class), `auth/adapters.py` (`ProviderLookupError` hierarchy)

```python
# One `error_class` per subclass, so a status and a code can never be named in disagreement.
class ServiceError(Exception):
    """Base exception for service layer errors."""
    error_class: ErrorClass = INTERNAL_ERROR
    log_level: int | None = None
```

The `INTERNAL_ERROR` default is the fail-closed control: a subclass that forgets to set one answers
500, never 200 and never a weaker class.

### Scalars-only on exceptions
