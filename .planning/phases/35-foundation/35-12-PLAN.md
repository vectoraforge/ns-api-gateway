<objective>
Close the single failed must-have in `35-VERIFICATION.md`: 35-02-PLAN.md's D10 claim that token
verification "performs no per-request network call". Four of its five conjuncts hold and are
tested. The fifth is false whenever a request carries an unrecognized `kid`, because
`JWTVerifier.verify()` calls the synchronous, blocking `PyJWKClient.get_signing_key_from_jwt`
directly from `async def AuthBarrierMiddleware.__call__` with no thread offload, no configured
fetch timeout, and no memory of a `kid` it has already failed to match.

Purpose: an unauthenticated caller can stall the whole process today. The independent review
measured a contiguous 1.206s event-loop stall from three requests at a 0.4s simulated round trip,
during which `/health/ready` — served by the same loop — is also blocked. Envoy rate-limits how
many such requests arrive; it cannot un-block an event loop, and one request is enough.

Output: the offload, the bounded timeout, the bounded negative-`kid` cache, and a replacement for
the vacuous test that let this ship.
</objective>

Give `JWTVerifier` a bounded memory of key ids it has already failed to match, so a repeated
unrecognized `kid` stops buying an outbound round trip per request.

Add two keyword-only constructor parameters — `unknown_kid_ttl_seconds: float = 60.0` and
`unknown_kid_cache_size: int = 256` — and one private `OrderedDict[str, float]` mapping a key id to
its expiry deadline taken from `time.monotonic()`. A TTL of `0` disables the cache outright; Task 2's
control case depends on that being an honest disable, not a special case.

In `verify()`, before calling `get_signing_key_from_jwt`, read the unverified `kid` through
`jwt.get_unverified_header`, wrapped so that a malformed compact form raising `PyJWTError` falls
through to the existing path rather than escaping — `verify()` never raises, for the same D-01
reason the barrier never raises. Treat an absent or empty `kid` as no cache key at all: no lookup,
no entry, straight through to the client, which already answers a keyless token with
`PyJWKClientError`.

When the `kid` is present and its recorded deadline has not passed, return
`(None, BoundedReason.bad_signature)` immediately without touching the client. That is exactly the
reason the fetched path yields for an unmatched key id, so the two are indistinguishable to
telemetry, to the audit `details.failure`, and — through the shared `AUTH_REQUIRED` class — to the
client. Do not mint a new `BoundedReason` member: the enum is part of the audit row contract and
widening it is another phase's decision.

Record a `kid` as unknown only when the client raises `PyJWKClientError` **and not**
`PyJWKClientConnectionError`. The connection variant is a subclass and means the endpoint was
unreachable, not that the key id is bogus; recording it would let a brief upstream outage reject
legitimate tokens for the whole TTL after the endpoint recovers. This distinction is the whole
difference between a cache and an outage amplifier, and it is what the prohibition in this plan's
`must_haves` names.

Keep the dict bounded on every insert: drop entries whose deadline has passed, then evict from the
oldest end until the length is within `unknown_kid_cache_size`. Store nothing but the key id and its
deadline — no signing key, no claim set, no admission decision. A positive cache here would keep a
rotated key working past its own lifetime, which is the second prohibition.

Then write the tests, in `tests/unit/test_jwt_security.py`, as a new class
`TestTheJwksTransportIsNotHitPerRequest` with its own `counted_transport` fixture built on Task 1's
JWKS document and `urlopen` stub — a **real** `PyJWKClient` behind a counted transport, never a
substituted client class. Cover every case in this task's behavior list by name, including
`test_with_the_negative_cache_disabled_each_repeat_costs_a_fetch` and
`test_distinct_unknown_kids_still_cost_one_fetch_each`. Those two are what make the bounded
assertion evidence rather than decoration: the first shows the harness counting real fetches, the
second states the accepted residual in a place a later phase will find it.

Write these tests first and watch them fail against the un-cached verifier before implementing the
cache; the repeated-`kid` case must report five fetches where it will later report one.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated client → barrier step 3 | An attacker chooses the token's `kid` header, and it is read **unverified** to select a signing key. This is the only attacker-controlled value that reaches an outbound network decision before any identity work happens. |
| verifier → Google JWKS endpoint | Outbound HTTPS whose latency and availability this service does not control, invoked on the request path. |
| verifier → in-process negative-`kid` cache | Cache keys are attacker-influenced strings; the cache decides whether a request skips the fetch path. |

## STRIDE Threat Register (ASVS L1, blocking on `high`)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-35-12-01 | Denial of Service | `auth/barrier.py` step 3 | high | mitigate | Await the verifier through `starlette.concurrency.run_in_threadpool` so a blocking JWKS fetch cannot stall the loop that also serves `/health/ready`. Pinned by a measured heartbeat case plus a permanent starvation control, and observed failing before the fix. |
| T-35-12-02 | Denial of Service | `PyJWKClient` fetch bound | high | mitigate | Pass an explicit `timeout=` of 3.0s, replacing PyJWT 2.12.1's 30s default, so a hung endpoint frees the worker in seconds. Pinned by asserting the `timeout` value observed at the transport is not `None` and is at most 5. |
| T-35-12-03 | Denial of Service | outbound JWKS amplification from attacker-chosen distinct `kid`s | medium | accept | Repeated `kid`s cost zero fetches; distinct ones remain one bounded, off-loop fetch each. Envoy rate-limits by IP, user and URL (AGENTS.md), which bounds arrival rate — the argument that rate limiting cannot help applied to a blocked event loop, and T-35-12-01 removes that. A global refresh cooldown would also delay legitimate key rotation. Accepted, and pinned by `test_distinct_unknown_kids_still_cost_one_fetch_each` so the residual is discoverable rather than assumed away. |
| T-35-12-04 | Denial of Service | negative-`kid` cache poisoned by an upstream outage | high | mitigate | `PyJWKClientConnectionError` never records a `kid`, and every entry carries a bounded TTL, so a brief JWKS outage cannot become a longer self-inflicted authentication outage. Pinned by a recover-after-failure case. |
| T-35-12-05 | Spoofing | negative cache misused as a positive cache | high | mitigate | The cache stores only key id and expiry — no signing key, claim set, or admission decision. | T-35-12-06 | Information disclosure | cache-hit and fetch-path rejections distinguishable by a client | medium | mitigate | Both yield `BoundedReason.bad_signature` and the shared `AUTH_REQUIRED` class; no new bounded reason is minted, so neither the body, the status, the copy, nor the audit `details.failure` differs. |
