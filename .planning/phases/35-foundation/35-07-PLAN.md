  <action>
Create `src/nativespeaker/api/auth/budgets.py` implementing §7.1's gating helper as plain
in-process counters. `BudgetGate` holds a `dict[str, int]` of remaining counts built from the
limits mapping passed to `__init__`, and is constructed per request — it meters provider calls
issued while serving one request, not traffic.

`check_all(names)` walks `names` in the given order and returns the first exhausted name, or
`None`. The caller passes names broadest to narrowest — the global `ADAPTER_FIREBASE_LOOKUP`
first, then endpoint-layer entries — and that ordering is load-bearing: §7.1 says when more than
one is exhausted, the global provider-call budget is the primary reported result. `exhausted(names)`
returns the full list so every exhausted limiter can be recorded in metrics alongside the primary.

`check_all` must be non-destructive. It reads counters and mutates nothing. `charge_all(names)`
is the only mutator: it re-checks that every name has capacity, raises `BudgetExhausted` if any
does not, and only then decrements all of them together. That all-or-nothing shape is the point —
§7.1 says no counter is incremented unless every applicable budget has capacity, and once
charged they stay charged however the call resolves, because budgets meter calls actually issued.
Callers charge immediately before the outbound call and again before each permitted retry.

Ship exactly one budget name: `ADAPTER_FIREBASE_LOOKUP = "adapter_firebase_lookup"` with
`FIREBASE_LOOKUP_ATTEMPTS = 3` — the initial call plus up to two additional attempts, for
retryable causes only. Every endpoint-layer name belongs to a later phase; do not invent any
here. A `user_not_found` outcome is definitive and non-retryable, spends no retry budget, and is
the caller's concern in phase 37 — this module only meters.

Document at the top of the module, and hold to it, that this is per-request provider-call
metering and not traffic limiting. Do not add an IP key, a user key, a route key, or a request
key. Do not add a shared, persistent, or cross-request counter store. Do not add `limits`,
`redis`, or `valkey` — Envoy Gateway is the sole request-rate enforcement point per D-05, which

recorded in `35-CONTEXT.md` as the required conflict flag rather than resolved silently.

`rate_limited` (429) still lives in the error registry regardless, per D-07: it is the class

every unspecialized rate-limit rejection carries. Exhaustion of a *budget* is not a rate-limit
rejection — it maps to internal `firebase_lookup_unavailable` and client
`verification_temporarily_unavailable`.

Write `tests/unit/test_budgets.py` covering every behaviour listed above, including a case that
