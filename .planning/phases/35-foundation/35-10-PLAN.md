<objective>
Ship the challenge store and the protocol the four challenge-bearing operations depend on: one
opaque capability handle, a 300-second TTL, and two atomic conditional updates with the claim as
the single serialization point.

Purpose: phases 37, 40, 41, and 42 implement `create_user`, `upgrade_anonymous_to_registered`,
`claim_anonymous_grant`, and `claim_registered_grant` against this store and build nothing of
their own. The claim update is the entire mutual-exclusion mechanism for all four — there is no
lock, no lease, and no cleanup job anywhere in the design, and adding one would be building
something SHARED-INVARIANTS forbids in every phase.

Output: the `core.auth_challenges` model, the store, the shared mode-signal check, and a
concurrency test that proves exactly one claimant wins.

`new_challenge_id()` is
`base64.urlsafe_b64encode(secrets.token_bytes(CHALLENGE_ID_BYTES)).rstrip(b"=").decode()` — 16
CSPRNG bytes, base64url, unpadded, 22 characters. Do not substitute a UUID, a counter, or a token
format; §6.1 pins this.

`issue(session, *, operation, operation_variant, identity, now)` inserts one row with
`expires_at = now + timedelta(seconds=CHALLENGE_TTL_SECONDS)` computed from the server's own
clock, and returns exactly `(challenge_id, expires_at)`. Nothing else about the challenge is ever
disclosed. The TTL is universal — no per-operation override in either direction, no grace period,
no sliding renewal on retry, and `expires_at` is never client-supplied, extended, or renewed.
Bind per §6.4: a linked identity sets `bound_external_identity_id`; a pre-auth identity sets
`preauth_issuer` in plaintext (it is a deployment-known provider string shared by every user of
that provider — do not hash it) and `preauth_subject_hash` through the shared
`keyring.actor_subject_hash`, the same derivation family and the same key the audit writer uses,
under the current active key with no version stored on the row.

`locate(session, challenge_id)` looks the row up by byte-for-byte equality on the stored value.
No trimming, no decoding and re-encoding, no case-folding, no defaulting. A definitive no-row is
`challenge_not_found`; a database outage during lookup is **not** `challenge_not_found` and must
propagate as the ordinary infrastructure failure. Never log the raw identifier a caller supplied.

`claim(session, *, challenge_id, claim_attempt_id, now)` is one conditional `UPDATE` whose
`WHERE` carries `challenge_id == handle`, `claimed_at IS NULL`, and `expires_at > now`, setting
`claimed_at` and `claim_attempt_id`, with `.returning(col(AuthChallenge.id))`. Return
`len(result.all()) == 1`. That single update is the serialization point for the whole protocol —
exactly one completion attempt can ever win it — and it is **the only place expiry is ever
evaluated**. No earlier step checks `expires_at` and nothing downstream is time-gated. Use the
`returning` row count rather than `rowcount`, which is unreliable under the test harness's
savepoint mode. A no-match mutates nothing and rejects immediately, before any proof verification
or provider call: `challenge_expired` where the row is still issued but expired, and
`challenge_consumed` where it is already claimed or consumed. The caller distinguishes those two
by re-reading the located row, not by a second conditional update.

`consume(session, *, challenge_id, claim_attempt_id, now)` is one conditional `UPDATE` whose
`WHERE` carries `claimed_at IS NOT NULL`, `consumed_at IS NULL`, and
`claim_attempt_id == this attempt's id`, setting `consumed_at` and `preauth_subject_hash = None`
in the **same** statement. Two statements would trip the table CHECK, which admits a cleared hash
only once `consumed_at` is set. It runs inside the caller's consuming transaction, atomically with
the audit row and any mutation, and does not commit.

`verify_binding(row, identity)` implements §6.4's completion comparison and its rejection
ordering. A linked context matches only when the request's resolved `external_identity_id` equals
`bound_external_identity_id`. A pre-auth binding matches only when `preauth_issuer` equals the
request's backend-verified issuer **and** `preauth_subject_hash` equals the value recomputed from
the request's backend-verified subject — even if that subject has since become linked. Compare
with `hmac.compare_digest`, never `==`. A pre-auth-bound row whose hash has already been cleared
is **not compared at all**, because clearing is part of consumption rather than a change of
identity: it takes the already-used rejection and audits `challenge_consumed`. Unknown handle,
bound-context mismatch, and operation mismatch are all rejected **before** the claim and leave any
located challenge unconsumed, so a wrong-endpoint or wrong-identity presentation can never burn
the rightful user's in-flight challenge. The operation-**variant** comparison is the exception: it
runs on the already-claimed row and is a consuming rejection.

The challenge binds **no** proof material — no restore proof, no reassignment target, no source
identity, no integrity or attestation material, no IP, no device, no TLS binding, no DPoP, no
mTLS, no token hash. A claimed challenge is dead: any failure after the claim consumes it, and an
abandoned attempt leaves the row claimed forever. That is the design, not an omission. Build no
cleanup job, no recovery scan, no reissue path, and no distributed lock, lease, or multi-phase
commit — SHARED-INVARIANTS forbids all of them in every phase, and rows are retained indefinitely.

Treat the public handle as a secret capability: it is body-only transport and must never reach a
URL, an audit row, a log, a trace, analytics, or error text. Correlate with the non-secret
`core.auth_challenges.id`.

Construct `app.state.challenge_store = ChallengeStore(app.state.hmac_keyring)` in

the pure-logic behaviours: handle length, alphabet, absence of padding, non-repetition, and the
exact 300-second TTL arithmetic from a fixed `now`.
