Envoy Gateway policies:
  - SecurityPolicy: JWT validation only, no claim headers (targets app-routes and auth-routes),
    and optional, so a request with no Authorization header reaches the backend and gets the
    shared {"code": "auth_required"} body instead of Envoy's plain-text "Jwt is missing".
    A token that is present but invalid or expired is still refused at the gateway, with that
    plain-text body: Envoy Gateway exposes no setting that lets a failed token fall through.

    REQUIRES ENVOY GATEWAY >= v1.2, which is where `spec.jwt.optional` was added. On an older
    gateway a CRD structural schema prunes the unknown field without error: the policy installs
    green, `helm install` succeeds, both probes pass, and an unauthenticated request receives
    Envoy's plain-text "Jwt is missing" instead of {"code": "auth_required"}. That is the most
    common error response this product emits, and the only signal that it is wrong is a
    client-side parse failure in production. The chart cannot read the CRD schema, so nothing
    here can check it. Verify it after install:

        curl -s $GATEWAY_URL/ | jq -e .code

    Anything other than "auth_required" means the field was pruned and the gateway is too old.
  - HTTPRoutes: app-routes (authenticated: /chats, /users, /examples, every method),
    auth-routes (authenticated: /auth/* and /), webhook-routes (public), health-routes (public)

No rate-limit policy ships in this chart: the BackendTrafficPolicy that carried the only one was
removed, so nothing at the gateway answers 429 on these routes. The backend does, and only when a
caller's monthly allowance is spent (`quota_exceeded`). The response override went with it,
because it matches on the status code alone, so it rewrote that answer -- the month is spent, do
not retry -- into `rate_limited` -- retry in a moment. Shedding stays where it can still say which
answer it is giving: the backend's execution gate caps in-flight work and refuses with 503
`service_unavailable` and `Retry-After`.

If the cluster Gateway applies its own IP- or user-keyed limits ahead of this chart, its 429
carries Envoy's own plain-text body, not the shared `{"code": ...}` one the error contract
requires. Nothing in this chart supplies that body.

The monthly allowance is not a gateway concern: the backend charges it per access grant.

Application Default Credentials: set `serviceAccountName` to a KSA annotated for Workload
Identity, or `credentials.googleCredentialsSecretName` to a Secret holding an ADC JSON. Firebase
Admin and the Play Developer API both authenticate through ADC, so with neither set the pod
becomes Ready and every account-creation route, plus the `google_play` arm of
`POST /auth/restore-subscription`, answers 503. Both probes still pass, and the only signal is
one warning line at boot.
